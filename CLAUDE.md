# EasyScript

EasyScript is a programming language with English sentence syntax. The compiler is written in C11. It compiles `.es` source files to C, then builds the generated C with `cc -O2` and runs the result.

## Language syntax (target)

- Statements are lowercase conversational sentences. A **period or a newline** ends a statement.
- A **colon followed by an indented block** opens a block (loops, conditionals, functions). The block ends when indentation returns to the outer level.
- Keywords are **case-insensitive**.
- `the`, `a`, `an` are **filler words**: the lexer/parser ignores them everywhere outside string literals. So they can never be used as identifiers. The one place meaning depends on one is `is a letter|digit|space`, which needs the dropped `a` (`Token.filler`), so `x is letter` still compares with a variable `letter` (and an unknown `letter`/`digit`/`space` gets a note suggesting `is a letter`).
- The 2024 uppercase prototype syntax (`MAKE A VARIABLE x ASSIGN 10`, `PRINT # x`) and its pipeline have been **removed**. Only the sentence syntax exists. `old/*.code` are historical files that no longer compile.

### Lexical rules (implemented in `src/front/lexer.c`)

- **Names of several words** are a parser matter (see "Names"); the lexer only makes words.
- **Words:** an ASCII letter followed by letters, digits, or `_`. An apostrophe is part of a word only when a letter follows it (`isn't`, `rock'n'roll`). A word ending in `'s` (any case) is the word and then a `TOK_POSSESSIVE` (`rex's` is `rex`, `'s`), and so is `'s` straight after `)`. A trailing apostrophe (`guests'`) is an error. Words are lowercased. `the`/`a`/`an` are dropped, and the next token (including NEWLINE/EOF, but never INDENT/DEDENT) records the dropped word's span in `Token.filler`. A filler-only line passes nothing on to the next line. `tokens` shows it as `[after "the"]`. **There is no keyword table:** every word is a `WORD`, and the parser decides what it means, so `count` can be a variable.
- **Ordinals:** a whole number directly followed by `st`/`nd`/`rd`/`th` (any case, and no more word characters) is `TOK_ORDINAL` (text as written); a wrong ending ("2th") is an error suggesting the right one ("2nd"). Only `every 3rd item of L` uses it.
- **Numbers:** `digits` or `digits.digits`. A `.` is a decimal point only when a digit follows it, so `5.` is `5` and then a period, `.5` is a period and then `5`, and `1.2.3` is `1.2 . 3`. No sign; `-` is always its own token. Letters stuck to a number (`3times`) are an error suggesting `3 times`.
- **Strings:** double quotes only, on one line, with escapes `\n \t \" \\`. An unknown escape is an error and is kept as written. An unterminated string is an error, and its value runs to the end of the line.
- **Symbols:** `. , : ( ) + - * / % = == < > <= >= !=`, and `'s` (possessive). A lone `!` is an error suggesting `!=`.
- **Comments:** `#` to the end of the line (outside strings), and any line whose first word is `note:` (any case, colon directly after it). `notes:` and `note :` are not comments.
- **Layout:**
  - `NEWLINE` ends each line that produced at least one token.
  - Blank lines, comment lines and filler-only lines produce nothing and don't affect indentation.
  - Indentation is measured with a tab as exactly 4 columns (not "next tab stop"). It's compared Python-style: an increase emits one `INDENT`, and a decrease emits a `DEDENT` per closed level.
  - A dedent to a width that matches no open level is an error that lists the valid widths. The line then stays at the nearest enclosing level.
  - An indented first line just emits `INDENT`; the parser rejects it.
  - Parentheses do **not** join lines.
  - At EOF the last line gets its `NEWLINE`, then a `DEDENT` for each open block, then `EOF`.
- **Positions:**
  - Tokens carry `line` and `column`, both 1-based. Columns count characters (UTF-8 aware), and a tab counts as 1.
  - Each token's `Span` covers exactly its source bytes: `NEWLINE` covers `\n` or `\r\n`, `INDENT` covers the indentation, and `DEDENT`/`EOF` are zero-length.
- **Other characters:** anything else is an error, and lexing continues. Curly quotes and curly apostrophes get a "use straight quotes" note. Non-ASCII letters get a note to use quotes. Invalid UTF-8 is reported as a byte, and control characters as `U+XXXX`.

### Expression grammar (implemented in `src/front/parse_expr.c`, operators; `parse_value.c`, values)

- **Precedence, loosest to tightest:**
  0. `every NAME in L REST` (only at the start of a value: `parse_expression`, which parentheses also use; elsewhere it's an error)
  1. `or`
  2. `and`, which stops before `and call`
  3. `not`
  4. comparison (no chaining), including `contains` / `does not contain` / `doesn't contain`, `has` / `does not have` / `doesn't have` (maps), `starts with` / `ends with` (and `does not` / `doesn't` forms), `is empty` / `is not empty` / `isn't empty` (but `is empty list of ...` compares with an empty list), and `is a letter` / `is a digit` / `is a space` (`parser_parse_char_test`)
  5. `followed by` (its own level, below arithmetic, so `"Sum: " followed by 2 plus 3` is `"Sum: " followed by (2 plus 3)`)
  6. `plus` / `minus` / `+` / `-`
  7. `times` / `multiplied by` / `divided by` / `mod` / `*` / `/` / `%`
  8. unary `-`
  9. postfix `as a number` / `as text`, `added together` / `reversed`, `without the first item|character`, and the text postfixes (`parser_parse_text_postfix`: `in uppercase`, `in lowercase`, `without extra spaces`, `split by X`, `joined with X`, `with X replaced by Y`)
  10. primary (including the list forms in `parse_list.c`, the map forms in `parse_map.c`, the text prefixes in `parse_text.c`, `only L that ...`, and `a new NAME with ...`), followed by any number of `'s FIELD` (`parse_primary` in parse_value.c; `parser_parse_field`), so `'s` binds tightest

  Binary levels are left-associative.
- **`and` is a single `BINARY_AND` node.** The checker decides whether it means logical and (both sides yes/no) or text joining. `followed by` is `BINARY_JOIN`.
- **Operator phrases** live in `Phrase` tables, both words and symbols. The longest full match wins.
  - **Missing last word:** if the next tokens spell a phrase minus its last word, and that prefix is longer than any full match, it's a "Something is missing after … / Did you mean …" error. This covers `is greater 5`, `is at 5`, `multiplied 3`, `as numbr`.
  - **No negated or mixed forms:** `is not greater than` and `is above or equal to` are errors that suggest `is at most` / `is at least` (or `<=`/`>=` after a symbol).
  - **Equality:** `is not equal to` and `isn't equal to` are accepted, and `==` is a lexer token.
- **`times` needs a value after it:** it's multiplication only when the next token can start a value, so `repeat 3 times:` keeps its `times`.
- **Reserved words:** these can't start a value or be names: `and or not is isn't equals reaches plus minus times multiplied divided mod followed as using`. The value words `yes no true false nothing it` are literals. Every other word is a name. `length`, `contents` and `file` are only special when followed by `of` / `of file`; the list words are only special in their forms (see "Lists"), so `item`, `first`, `last`, `only`, `every`, `list`, `copy` can still be names.
- **Prefix forms bind tightly:** `length of X` and `contents of file X` take a single *primary*, so `length of x plus 1` means `(length of x) plus 1`. Postfix conversions wrap the whole form.
- **Calls:** a call is a name (one word, or the longest known name of several) followed by `of`, `with` or `using` (or `to`/`for`/`from`/`in`, for a function defined with that word), then arguments (`parser_parse_call_args`). Each argument is a *unary* expression.
  - **Separators:** arguments are separated by `and` (but not `and call`), and also by commas after `using` only, so `if f of x, say y` keeps its comma. The `and`s are taken greedily, and the checker reports a wrong count.
  - **Arithmetic after the arguments** (+ - * / % plus minus times multiplied divided mod followed by) is an ambiguity error that suggests both parenthesized forms, unless the last argument is parenthesized (`fib of (n minus 1) plus 1` adds; `is_parenthesized` looks at the source).
  - **Comparisons and `or` end the call.**
  - **No inputs:** a bare `NAME` is `EXPR_NAME`, and the checker and codegen treat it as a call when it's a function with no parameters (functions and variables share one namespace).
- **Positions:** every node has a `SourcePos`, holding its span and the line and column of its first token. A parenthesized group's span includes its parentheses. Binary, unary and convert nodes also keep `op_span`.
- **Errors and recovery:** at most one error per sentence (`Parser.sentence_failed`). After an error, the parser skips to the sentence end (`.`, NEWLINE, DEDENT, INDENT or EOF) and continues.
- **`.5`** (a period directly followed by a number) is rejected wherever a value or a sentence is expected ("Write 0.5 instead of .5.").

### Statement grammar (implemented in `src/front/parse_stmt.c`)

- **A program is a list of statements** (`parse_statements(p, block, in_block)`, used for the program and for every block; in a block it stops after the closing DEDENT). A simple statement ends at `.`, NEWLINE, or EOF, and several can share a line when separated by periods; a block statement (`p->ended_with_block`) ends with its DEDENT instead. An INDENT nothing opened is rejected ("nothing above it starts a block") and its whole block is parsed and discarded, so its DEDENT can't close an enclosing block. A sentence-initial `.` is an error. Expressions can't stand alone as statements. `p->ends_with_name` (set from the form; a one-line if's inner statement overrides it) chooses the leftover message.
- **Optional `please`:** a leading `please` is skipped. `please` on its own is an error.
- **Statement forms** (table `forms[]`, keyed by the first word; the AST normalizes synonyms but keeps `Stmt.verb` as written):

  | Form | AST |
  |---|---|
  | `let X be E`, `let X equal E` | `STMT_LET` |
  | `set X to E`, `change X to E` | `STMT_SET` |
  | `add E to X`, `subtract E from X` (amount first) | `STMT_CHANGE` with a `ChangeOp` |
  | `increase` / `decrease` / `multiply` / `divide X by E` (target first) | `STMT_CHANGE` with a `ChangeOp` |
  | `say` / `print` / `show` / `display E`, or plain `write E` | `STMT_SAY` |
  | `write E to file F` | `STMT_WRITE_FILE` |
  | `ask E and call the answer X` (or `and call it X`) | `STMT_ASK`. The lexer drops "the", so the phrase is `and call answer`, and the prompt expression stops before `and call`. Both `ask` and `read file` take both phrases (`expect_call_phrase`). |
  | `append E to file F` | `STMT_APPEND_FILE` |
  | `read file F and call it X` | `STMT_READ_FILE` |
  | `stop the program` | `STMT_STOP` (`stop` on its own, or `stop the loop`, is `STMT_BREAK`; see loops) |
  | `if …` | `STMT_IF` (parse_if.c) |
  | `count` / `go` / `for` / `do` / `repeat` / `while` / `as long as` / `keep doing this until` / `forever` | `STMT_LOOP` (parse_loop.c) |
  | `stop the loop`, `stop`, `break` / `skip this one`, `skip`, `continue`, `move on` | `STMT_BREAK` / `STMT_CONTINUE` (parse_loop.c) |
  | `to NAME …:` / `give back E`, `return [E]` / `call NAME …`, or a sentence starting with a pre-scanned function name | `STMT_FUNCTION` / `STMT_RETURN` / `STMT_CALL` (parse_func.c) |
  | `keep NAME as E` / `keep NAME at E` (`keep doing …` is the loop) | `STMT_CONSTANT` (parse_func.c) |
| `add E to the end of L`, `insert E at position P of L`, `remove item P from L` (or `the first item`/`the last item`), `set`/`change item P of L to E`, `sort L …` | `STMT_LIST` with a `ListChange` (parse_list.c; `add`/`set` hand over when `end of` / an item form follows) |
| `remove K from M` (a map; anything after `remove` but an item form) | `STMT_LIST` with `LIST_REMOVE_KEY` (`value` is K, `list` is M) |
| `set the value for K in M to E`, `add E to the value for K in M` (and the other change sentences) | `STMT_SET` / `STMT_CHANGE` whose `field` is the `EXPR_MAP_GET` (`parser_parse_target`) |

- **Statement words are contextual.** They're special only as the first word, so `let say be 2`, `add 1 to add` and `let file be …` are fine.
- **Names** (`parse_names.c`): a name is one or more WORDs. `Name {text, display, pos}`: `text` is matched (lowercased, one space between words), `display` is how it was written there. `parser_parse_name(p, name, next)` takes the words up to one of `next` (the words that follow the name in that form, e.g. `be`/`equal` after `let X`), the end of the sentence, or a non-word. The first word may be any word that's neither an operator word nor a value word; further words also can't be stop words (`be equal to from by of with in at then that giving`). A word that means something followed by more name words is "\"%s\" can't be part of a name, because it already means something in EasyScript." suggesting the other words (`price tax`; `pay rate` for `rate of pay`).
- **Known names (pre-scan):** `parser_find_names` (run before parsing) records every function name (any length; `intros` holds the `to`/`for`/`from`/`in` its definitions introduce inputs with) and every other name of several words made by `let X be`, `keep X as|at`, `as X:`, `call answer|it|each number X`, `for each X in|from`, `every X in`, and function inputs. `parser_match_name(p, ahead, functions_only)` gives the longest known name there. Values (`parse_name_or_call` in parse_value.c), positions, and statement starts use it; a known function name of several words starts a call sentence even if its first word is a statement word.
  - **Filler as name:** if the current token isn't a valid name, or *is* one of those `next` words, and it carries a `filler` span, the filler was meant as the name. That gives the "can't be used as a name… EasyScript ignores a/an/the" error. `let the total be 0` stays valid.
  - **Reserved words** give "already means something" with a note suggesting a name that says what it holds.
  - **A `next` word with no filler** (`let be 5`) is "Something is missing after "let"".
- **Missing connectors:** `expect_word`/`expect_phrase` report the missing or wrong connector with the form's example sentence. For a wrong phrase, they quote what was written, e.g. `found "and call it"`. If the connector appears straight after the verb (`add to x`, `write to file …`, `append to file …`), the error is "Something is missing after "add"", because `to` would otherwise parse as a name.
- **Unknown first word:** "I don't know a sentence that starts with …", plus one note:
  - the closest statement word (or `please`) by edit distance, if one is close enough
  - otherwise, if the second token is `is`/`=`/`equals`/`be`, a `let X be …` / `set X to …` hint
  - otherwise, the generic list of starting words

  A non-word start gives "A sentence can't start with …".
- **Leftovers:** forms ending in a name or keyword (`add`, `subtract`, `ask`, `read`, `stop`, `break`, `skip`, `continue`, `move`) report extra words as "I expected the sentence to end after …". Others use the expression leftover reporting. Statements with errors are left out of the returned `Block`.
- **Quoting in messages:** `parser_quoted` renders text spans as `the text "…"` to avoid nested quotes.

### Constants (implemented in `parse_func.c`, `consteval.c`, `check.c`, `codegen_c.c`)

- **Syntax:** `keep NAME (as | at) E`. `parse_keep_form` sends `keep` + `doing` to the loop and everything else to `parse_constant`. AST: `STMT_CONSTANT {name, value, folded}`, where `folded` (a `ConstValue`: number/text/yes-no) is filled in by the checker.
- **Evaluation** (`front/consteval.c`, `const_eval(arena, diag, records, expr, lookup, ctx, out)`): literals (not `nothing`), unary minus and `not`, arithmetic, `followed by`, `and`/`or` (with the runtime's short-circuit and join rules), comparisons (with the 1e-12 tolerance), `as text`/`as a number`, and `length of`. Calls, `it`, `contents of file` and `nothing` are errors with a "fixed before the program starts … use let instead of keep" note. **It mirrors the checker's kind rules and `runtime/es_runtime.h`'s values exactly**, including `const_number_text` (= `es_number_text`) and the error wording (a kind mistake in a constant is reported by consteval, not by inference). `tests/run/constant_matches_runtime.es` prints each of 30 constants next to the same runtime expression, so change both together.
- **Checker:**
  - **Collection:** `checker_collect_constants` runs after `collect_functions`, so constants can be used anywhere. Duplicates are errors, and so is a constant named like a function (reported at the constant).
  - **Values:** `checker_check_constant` rejects constants inside blocks or functions. Otherwise it evaluates the value via `lookup_constant`: only constants with a lower `index` are allowed, and a failed earlier constant adds no extra error. Self, later constants, functions, variables and unknown names get specific errors.
  - **Use:** names resolve to constants everywhere (`check_name_expr` ignores `floor`). `check_target` rejects changing a constant ("… is a constant, so it can't change", with a `let` suggestion). `checker_clashes` also rejects variables, inputs and loop numbers named like a constant. Unknown names can get "Did you mean "rate"? It's a constant, kept on line N.".
- **Fixed lists:** `keep NAME as a list of ...` (or `an empty list of ...`) makes `ConstValue {kind CONST_LIST, len, list_type, items}`: items must be fixed numbers, text or yes/no of one kind ("All the items of a list have to be the same kind: ..."), never lists ("A fixed list can't hold lists or maps, because those could change."). `length of` a fixed list folds; any other list form or operator on a list in a constant is "A constant can't work things out from a list." `checker_check_list_stmt` rejects add/insert/remove/set item/sort on a constant's name with the constant message, and `check_target` already rejects `add X to`/`set`. Codegen emits a static immortal list (`static EsText *es_ki_NAME[]` plus `static EsList es_k_NAME = {{ES_OBJ_LIST, ES_IMMORTAL}, ...}`); reading the name gives `es_list_copy(&es_k_NAME)` (so a variable, function or list that keeps it gets its own copy), except where it's only looked at: `cg_list_operand` passes `&es_k_NAME` to items, `contains`, `length of`, list operations, slices, `every`/`only` and `for each`.
- **Kind:** the kind of `folded` (an unworked-out constant is `TYPE_ERROR`).
- **Codegen:** each constant becomes `static const double es_k_NAME = …;` (NAN/HUGE_VAL for special numbers), `static const bool …`, or `static EsText *const es_k_NAME = &es_sN;` (a static immortal text object). `EXPR_NAME` resolves constants first (`es_k_`), and `main` adds a `(void)es_k_NAME;` per constant so unused ones don't warn.

### Functions (implemented in `src/front/parse_func.c`, `check.c`, `codegen_c.c`)

- **Definition:** `to NAME [with | of | using | to | for | from | in] P [(KIND)] [and | ,] Q [(KIND)] … [[,] giving back KIND]:` plus an indented block. NAME is every word before the intro word (or `(`, `,`, `giving back`, `:`; `for` always ends it: a method when a kind of record follows or a comma precedes it, otherwise the intro word), so `to make tea:` has no inputs and `to greet someone:` is the function "greet someone"; `Stmt.function.intro` keeps the intro word (headers in messages reuse it). A `(` straight after the name is "A kind in parentheses goes after an input, and inputs come after "with"." (suggesting `to greet with who (text):`). KIND (`parse_kind`) is `number` (after the dropped `a`), `text`, `yes or no` or `yes/no`, and `nothing` only after `giving back`; errors: "I don't know the kind of value …", "I expected ")" after the kind of value…", "Something is missing after "giving back"". The param loop stops at `giving back`; with no inputs, `to roll, giving back a number:` skips the comma. AST: `STMT_FUNCTION {name, params, declared (per input, TYPE_UNKNOWN if none), declared_result, param_types, result (filled by the checker), body}`; `easyscript ast` shows `define area (width: a number) giving back a number`. The name can't be a statement word (`parser_is_statement_word`, which includes `please`): "… starts sentences in EasyScript, so it can't be the name of a function". `to greet a:` (filler before the colon) and `to greet with:` are errors.
- **Return:** `give back E`, `return E`, or bare `return` give `STMT_RETURN` (`returned` is NULL for bare; the parser also makes `give back nothing` bare).
- **Call sentences:** `NAME [with | of | using | to | for | from | in] A and B` (`to`/`for`/`from`/`in` only for a function defined with that word: `parser_at_call_intro`, `KnownName.intros` bits from `parser_intro_bit`; another of them is "\"pause\" takes its inputs after ... not ..."), where NAME was found by the pre-scan (the longest known function name), or `call NAME …`. A sentence starting with the first word of a longer function name gets a note explaining the name and the `with` fix. Zero arguments is allowed (`greet.`), but `greet with` with nothing after it is an error. AST: `STMT_CALL {call: EXPR_CALL}`. Unknown first words also get the pre-scanned function names as suggestions.
- **Checker:**
  - **Function table:** all top-level functions are collected first; a duplicate is "You already defined …".
  - **Where they can go:** a definition inside an if, a loop or another function (`Checker.blocks` / `function`) is "Functions can only be defined at the top level…", and its body isn't checked.
  - **Displays:** `Symbol`, `Function` and `Constant` keep `display` (as first written); messages show it, and names nothing made show as written at the use (`Expr.display`). An unknown name that ends the current function's name gets a note on making it an input with `with`.
  - **Function bodies:** a body sees only its parameters and the names it makes. `Checker.floor` hides `made[0..floor)`, and the loop stack is cleared. An unknown name that exists outside gives "A function only sees its own inputs and the names it makes. … pass it in as an input." Duplicate parameters are errors.
  - **Calls:** an unknown function gets "Did you mean "area"? It's defined on line N." or a "Define it first" note; a variable called like a function gets "… is a variable, not a function". A wrong count is "needs N value(s), but this gives it M" (or "doesn't take any values"), with a note quoting `to area with width and height` and the definition line. A bare name that's a function with parameters counts as 0 arguments.
  - **`give back` outside a function** is an error. Kinds of inputs, results and give-backs: see "Types".
  - **Names:** making a variable, parameter or loop number with a function's name is an error (`checker_clashes`).
- **Codegen:**
  - **Signature and order:** each function becomes `static RESULT es_f_NAME(int es_call, TYPE es_vX_P…)` (`es_call` is the call's site) with C types from `param_types`/`result` (`void` for nothing), with prototypes before all function bodies and main.
  - **Each body:** `emit_function` uses a fresh `Codegen` (its own body, temps, vars, loops, depth). It declares typed temporaries, then every variable made in the function (`cg_declare_name` hoists into `vars`, skipping parameters; numbers `= 0`, yes/no `= false`, text `= &es_empty_text`), `(void)` casts for non-text variables and all inputs, then the frame push (`es_enter`, `es_enter_one` or `es_enter_many`; see "Sites and the call stack").
  - **Returns:** `es_tN = E;` (worked out first), drop text inputs and variables (`emit_drop_all`), `es_leave(); return es_tN;` (or `return;`). Falling off the end: a nothing function drops and calls `es_leave()`; a value function calls `es_no_result(def line, "NAME")` (runtime error "The function "NAME" ended without giving anything back." with a hint).
  - **Calls:** `es_f_NAME(line, A, B)`; when two or more arguments have effects (`cg_has_effects`), all go into typed temporaries first, left to right. A zero-parameter function used as a name is `es_f_NAME(line)`. A call sentence: `es_release(CALL);` for text, `(void)CALL;` for numbers/yes-no, `CALL;` for nothing.
- **Runtime:** the frame push (`es_enter`/`es_enter_one`/`es_enter_many`) fails at `ES_MAX_DEPTH` (10000) frames with "Functions are calling each other too deeply (more than 10000 calls inside each other)." and a hint. `es_leave()` pops. See "Sites and the call stack".

### Loops (implemented in `src/front/parse_loop.c`)

- **Forms** (all need `:` plus an indented block via `parser_parse_block`; no one-line loops): `count [down] from A to B [by S | in steps of S] [and call each number N | as N]`, `go from …` (same as `count from`), `for each N from A to B [by S | in steps of S]`, `for each N in L` (`LOOP_EACH`, `list`; see "Lists"), `do this N times` / `repeat N times`, `while C` / `as long as C` / `repeat while C`, `keep doing this until C` / `repeat until C`, `forever`. AST: `STMT_LOOP` with `LoopKind`, `from`/`to`/`step` (NULL = 1)/`down`/`var` (default `"number"` at the verb's position, `var_named`)/`times`/`condition`/`list`/`body`.
- **`as` in count headers:** while parsing A, B and S, `Parser.as_ends_value` makes `parse_postfix` stop at `as`, so `as N` names the loop variable (even `as number`). Parentheses reset the flag (`parse_group`), so `(limit as a number)` converts. B and S stop before `and call` (the `and` rule), `by` and `in` (plain words).
- **`count` followed by `is`/`=`/`equals`/`be`** is "A sentence that starts with "count" is a counting loop…" with a `let count be` hint.
- **`stop`** (`parse_loop_control`): `stop program` (filler "the" dropped) is `STMT_STOP`; `stop loop` or bare `stop` is `STMT_BREAK`; `break` too. `skip [this one]`, `continue`, and `move on` are `STMT_CONTINUE`. Whether they're inside a loop is checked by the checker.
- `parse_loop` sets `ended_with_block` last, like `parse_if`.

### if / otherwise (implemented in `src/front/parse_if.c`)

- **Forms:** `if C:` NEWLINE INDENT block DEDENT, then any number of `otherwise if C:` blocks and at most one final `otherwise:` block. `else` is a synonym (`else if`, `else:`). One-line forms `if C, S` and `if C then S` take exactly one simple statement (not `if`/`otherwise`) and never have an `otherwise`. AST: `STMT_IF` with `Vec(IfBranch) branches` (`condition` NULL for the final `otherwise`, `body`, `pos` spanning the header up to its colon) and `one_line`.
- **Lining up:** after the if's DEDENT, an `otherwise` at the start of the next statement continues it (the lexer guarantees it's in the same column). Anything else starting with `otherwise`/`else` goes to `parse_orphan_otherwise`, which explains, in order: after a one-line if ("can't have an otherwise"), inside an open if's block (`p->open_ifs`, "doesn't line up with its if… The if on line N starts in column C"), or no if at all. A second plain `otherwise` is "already has an otherwise, on line N".
- **Header errors** (missing condition, missing colon/comma/then, text after the colon, nothing indented, broken condition) report once, then `parser_skip_line_and_block` skips the line and parses-and-discards an indented block; the rest of the chain is still consumed so it causes no extra errors. `parse_if` sets `ended_with_block` last, because statements inside its blocks reset it.
- **`:` or `,` right after an operator** (`if x plus:`) is "Something is missing after "plus"" (in `expected_value`).

### Lists (implemented in `src/front/parse_list.c`, `parse_expr.c`, `check_list.c`, `src/back/codegen_list.c`, `runtime/es_list.h`)

- **Values:** `list of A, B and C` (`EXPR_LIST`; items are `parse_join` values; commas separate items until the first `and`, after which only `and` does, so a one-line if's comma survives; an unparenthesized `list of` inside is "A list inside a list needs parentheses."), `empty list of KINDS` (`EXPR_EMPTY_LIST`, `list_type`), `item P of|in L`, `first item of|in L`, `last item of|in L` (`EXPR_ITEM` with `ItemWhere`; the list is a primary), `number of items in L` (`EXPR_LENGTH`), `copy of L`, `biggest of L`, `smallest of L`, postfix `L added together`, `L reversed` (inner lists copied, via `es_list_copy`), `L sorted [biggest|smallest first]` / `L sorted by their length [longest|shortest first]` (`LIST_SORTED*`, `es_list_sorted`: `es_list_copy` then `es_sort`; mismatched order words are the sort sentence's errors), and `L is empty` / `is not empty` / `isn't empty` (`EXPR_LIST_OP` with `ListOp`), `L contains X` / `does not contain` / `doesn't contain` (`BINARY_CONTAINS` / `BINARY_NOT_CONTAINS`).
- **Slices** (`EXPR_SLICE` with `SliceKind`, all new lists; `every other item of L` is `SLICE_EVERY` with step 2 and start 1, positions 1, 3, 5, while `every second item` starts at 2; `parser_at_every_nth` keeps `every other item in L` from being read as the map `every NAME in L`): `items A to B of|in L` and `items A to end of|in L` (`at_range`: `items` + a position + `to`, or arithmetic to report), `first N items of|in L` / `last N items ...` (`at_first_last`), postfix `L without first item` / `without last item` (`without_phrases` in parse_expr.c), postfix `L without item P` / `T without character P` (`SLICE_WITHOUT_AT`, `parser_parse_without_at`; `es_slice_without_at` / `es_text_without_at`, the list written first), and `every ORDINAL item of|in L` (`at_every_nth`: `second`...`tenth` or a `TOK_ORDINAL`; step 0 is "There's no item at position 0."). The checker needs a list ("I can only take items from a list") and numbers ("The number of items has to be a number" for counts). Runtime: `es_slice_range` (both positions via `es_index`; backwards is "I can't take items %zu to %zu: the first position is after the last one."), `es_slice_end` (negative or fractional counts are errors; more than the length gives everything), `es_slice_without` (empty is "There's no first item"), `es_slice_every` (positions step, 2·step, ...), all through `es_list_pick` (text retained, inner lists copied).
- **Positions** (`parse_position`): a number, a name (never a call: `item n of L`), `it`, or a primary (`(n plus 1)`, text). `parser_at_item(p, after)` decides whether `item`/`first`/`last` start the form: `item` + number/text/`(`, or `item` + a name + one of `after` or an arithmetic word; `first`/`last` + `item` + one of `after`. Otherwise they're names (`add item to total`). Arithmetic after a position is "A position worked out with arithmetic needs parentheses."; `item of` is "Something is missing after "item"".
- **`every NAME in L REST`** (`EXPR_EVERY`): `parse_every` parses the name and a primary L, sets `Parser.pending_item` to an `EXPR_NAME` for the item, and parses REST with `parse_or`, whose first primary is the item (`parse_unary`/`parse_not` skip their prefixes while it's pending, so `- 1` subtracts). **`only L that are COMPARISON V`** (`EXPR_ONLY`): L is a primary; the condition is `BINARY(op, EXPR_IT, V)` from the `item_comparisons` table (`are` for `is`), or `are empty` / `are not empty` / `aren't empty`; `only` starts the form only before `NAME that` or `(`.
- **Kinds** (`parser_parse_kind` in parse_kind.c, shared with definitions): `number`, `text`, `yes or no`/`yes/no`, `nothing` (results only), `list of` + plural items `numbers`, `text`, `yes/no values`/`yes or no values`, `lists of ...`.
- **Sentences:** `add E to end of L` (`parser_finish_add_end` turns the STMT_CHANGE into STMT_LIST), `set item P of L to E`, `remove item P from L` (anything else after `remove` is "I expected "item" here"), `insert E at position P of L`, `sort L [by their length] [,] [smallest|biggest|shortest|longest first]` (length words need `by their length` and the other way round: two errors). `for each N in L:` is `LOOP_EACH` with `Stmt.loop.list` (parse_loop.c).
- **Checker** (`check_list.c`): `checker_require_list` unifies with "a list of" a fresh item variable ("<message>, but this is <kind>."); values put into a list unify with its items ("\"scores\" is a list of numbers, so it can't hold text." / "contain"); literal items unify with the first ("All the items of a list have to be the same kind: ..."). `sort`, `biggest of`, `smallest of` need numbers or text (by length: text or lists), `length of`/`is empty` text or a list (`DEFER_ONE_OF`). `added together` needs a list of numbers. `every`/`only` push a `Loop` whose `it` is the item; `every`'s name (and a for-each's) is made by `checker_make_item_name` ("You already made ...", note `each_NAME`), with `Symbol.loop_item` for the "is each item of the loop on line N" note. **`add E to X`** (STMT_CHANGE) where X is a list: if its items are numbers (or undecided) it's "\"scores\" is a list of numbers, so this could mean two things." with both phrasings; otherwise the checker sets `Stmt.change.append`. Fixed lists: see "Constants".
- **Codegen** (`codegen_list.c`): a list is `EsList *`; variables `es_vl<depth><n|t|b>_NAME`. Runtime functions with a per-item-kind suffix (`cg_item_suffix`: n/b/t/l): `es_list_from(ES_ITEMS_X, n, (CTYPE[]){...})`, `es_list_new`, `es_get_X(line, L, ES_AT|ES_FIRST|ES_LAST, P)`, `es_put_X`, `es_add_X`, `es_insert_X`, `es_remove`, `es_contains_X`, `es_extreme_n/t`, `es_list_sum`, `es_list_length`, `es_list_is_empty`, `es_text_is_empty`, `es_list_reversed`, `es_list_copy`, `es_list_same`, `es_list_text`, `es_sort(L, ES_SORT_*)`. Parts are worked out in source order (`cg_ordered`); reading list contents counts as an effect in `cg_has_effects` (a call could change the list). `for each` stores `es_list_snapshot(L)` in a hidden variable `0eachN` of the loop's scope (dropped like any variable) and assigns the item (retained) each round; `LoopCode.item` makes `it` the item. `every`/`only` become `static EsList *es_everyN/es_onlyN(EsList *es_list, captured...)` in `Codegen.helpers` (emitted after prototypes, before functions): the captured variables (`collect`: every variable name the body reads, minus constants, functions, and names bound by inner `every`s) are borrowed parameters (`Codegen.captured`); the helper snapshots the list only if the body can call a function.
- **Runtime** (`runtime/es_list.h`): `EsList {header, items, len, cap, at}` (in `es_memory.h`, which frees it and releases counted items), growing by doubling (`es_list_reserve`, counted against `ES_MEMORY_LIMIT` first; 1.5x was tried and dropped: on macOS realloc then moved the last big block with a deferred copy paid at the sort, +5 MB). Exact sizes when known (literals, slices, copies, `every`); `only` results are shrunk (`es_list_shrink`). A list with a count of 1 is reused: `es_list_keep` (slices) and `es_list_copy` work in place, with `es_list_own_deep` copying any inner list something else holds, so slices and copies still share no lists. Errors: "There's no item %s in the list: it has %zu item%s." / "it's empty." (hint "Positions start at 1: the first item is item 1." below 1), "The position of an item has to be a whole number, but it's %s.", "There's no %s item: the list is empty." (first/last/biggest/smallest), "I can't insert at position %s: the position has to be from 1 to %zu (the list has %zu item%s).". `es_list_snapshot` and `es_list_reversed` reuse a list nobody else holds. `es_list_copy` copies inner lists too. Sorting (`runtime/es_sort.h`): numbers are sorted in place by `ES_DEFINE_PDQSORT` (pdqsort: insertion sort below 24, median of 3 or of 9, partition-left for runs of equal items, a nearly-sorted check, heapsort after too many unbalanced partitions; comparisons `<`/`>`, exact, not `es_close`), with "not a number" moved to the end first because it breaks the order pdqsort needs. Text (`es_text_less`, bytes) and `(length, item)` pairs for `by their length` use `ES_DEFINE_SORT`, a stable bottom-up merge sort (insertion sort for runs of 32, an already-ordered check per merge). Both inline the comparison. `es_list_text` writes "72, 95 and 88", inner lists in parentheses, an empty list as empty text.
- **Joining:** `L followed by M` with two lists is `es_list_join(L, M)` (codegen picks it when the expression's type is a list): exactly `len(L) + len(M)` items, L reused when its count is 1 (`es_list_own_deep` first), text retained and inner lists copied (`es_list_append_copies`).
- **Sharing:** lists are references; `let b be a` shares, functions get the list itself, `a copy of` copies. A list can't contain a list of its own kind (the occurs check and kinds), so lists never form cycles.

### Maps (implemented in `src/front/parse_map.c`, `check_map.c`, `src/back/codegen_map.c`, `runtime/es_map.h`)

- **Values:** `map of K to V, K to V and K to V` (`EXPR_MAP`, `items` holding key, value, key, value...; keys and values are `parse_join` values; commas separate entries until the first `and`, as in a list; an unparenthesized `list of`/`map of` inside is "A list/map inside a map needs parentheses."), `empty map from KEYS to VALUES` (`EXPR_EMPTY_MAP`, `list_type`), `value for K in M [, or D]` (`EXPR_MAP_GET {key, map, fallback}`; `parser_at_lookup`: `value` + `for`, unless `value` is a function; the span (and column) starts at a dropped "the" (`Token.filler`); K is `parse_join`, except that a name straight before `in` is the key (`parse_key`), so `the value for item in prices` isn't an item form; M is a primary; D is a unary value, and arithmetic straight after an unparenthesized D is "... could mean two things." with both parenthesized forms), `keys of M` / `values of M` / `number of entries in M` (`EXPR_LIST_OP` with `LIST_KEYS`/`LIST_VALUES`/`LIST_ENTRIES`; M a primary), `M has K` / `does not have` / `doesn't have` (`BINARY_HAS`/`BINARY_NOT_HAS`, a comparison), and `is empty`, `a copy of`, `is` (equal maps: the same keys with equal values, in any order).
- **Sentences:** `set the value for K in M to E` and `add/subtract/increase/... the value for K in M` (targets through `parser_parse_target`; `, or` on a target is "A value that changes can't have ", or"."), `add E to the end of the value for K in M` (a list value), `M without K` (postfix `without` + a unary value after every other `without` form: `EXPR_MAP_WITHOUT`, reusing `as.lookup`; `es_map_without(site, M, K)` copies like `a copy of`, then takes K out, "I can't leave out ..."), `remove K from M` (`parse_remove_key`; `remove item from M` stays the list form's missing-position error; `remove from M` is "Something is missing after "remove"."), `for each K and V in M:` (`Stmt.loop.pair`, `value_name`; `it` is the key; the pre-scan records both names).
- **Kinds** (`parser_parse_map_kind`, from `parser_parse_kind` and `parser_parse_items_kind`): `map from KEYS to VALUES` (`maps from ...` in the plural), KEYS `text` or `numbers` ("I expected "text" or "numbers" here, but found ..."), VALUES in the plural like a list's items. `Type`: `TYPE_MAP` (1<<13) + the index of a `MapKind {key, value}` in `Records.maps` (`ast_map_type` adds a kind the first time it's used; `maps[0]` is "a map" with its kinds undecided, so `TYPE_MAP` alone is that), `type_is_map`, `ast_map_key`/`ast_map_value`, `ast_type_undecided` (looks inside maps); record kinds stay below `TYPE_MAP`. `Records` (a `Vec(RecordKind)`'s fields plus `maps`) is mutable in the parser and checker (`check_program` takes a `Program *`).
- **Checker** (`check_map.c`): a map's type variable is a `TypeSlot` of type `TYPE_MAP` with `key` and `item` (the values) variables (`types_new_map`, `types_key`; `types_of` interns the kind; the occurs check, `compatible` and `join` go through both). `checker_require_map(var, at, message, list_note, &key, &value)` ("I can only look up a value in a map, but this is a list of numbers." plus a note showing the list form); keys unify with the map's ("The keys of "ages" are text, but this is a number.") and then must be text or numbers (`DEFER_ONE_OF`, "A map's keys have to be text or numbers"); values put in unify ("\"ages\" is a map from text to numbers, so it can't hold text."); the fallback unifies with the values; literal keys and values unify with the first ("All the keys/values of a map have to be the same kind: ..."); a key written out twice is "The key "tea" is in this map twice." (numbers compared to 12 significant digits, `const_key_text`). `checker_check_each` (a map needs two names, a list one, each with its own message), `checker_check_remove_key`, `checker_check_map_set`/`checker_check_map_change` (a constant's map: `checker_reject_fixed`), `checker_check_has`, `checker_check_map_op`. `length of` a map and `contains` on one get notes pointing to `the number of entries in` and `has`. `add 5 to the value for K in M` with a list of numbers is "This value is a list of numbers, so this could mean two things.".
- **Constants:** `keep NAME as a map of ...` / `an empty map from ...` make `ConstValue {kind CONST_MAP, len, keys, items (the values), key_type, value_type}` in `consteval.c` (keys text or numbers, each once; values numbers, text or yes/no of one kind; "A fixed map can't hold lists or maps, because those could change."); `the number of entries in` a fixed map folds; anything else worked out from a map is "A constant can't work things out from a map." (`reject_map`: lookups, `has`, `contains`, `keys of`, operators). `const_eval` takes the `Records`. `checker_const_type` gives a constant's kind (adding the kind of map). Fields can start at a fixed map or an empty map (copied for each record). Codegen: `static EsMap *es_k_NAME;`, made at the start of `main()` (`Codegen.inits`) as `es_map_fix(es_map_from(...))`; reading the name gives `es_map_copy(es_k_NAME)`, except where it's only looked at (`cg_list_operand` gives `es_k_NAME`).
- **Codegen** (`codegen_map.c`): a map is `EsMap *`; variables `es_vh<kind>_NAME` (lists of maps `es_vl1h<kind>_`); keys are passed as `(EsValue){.t = K}` / `{.n = K}`; values go through one runtime function per kind (`cg_value_suffix`: n/b/t/l/r/m): `es_map_from(KEYS, VALUES, n, (EsValue[]){...})`, `es_map_new(KEYS, VALUES, 0)`, `es_map_get_X(site, M, K)`, `(es_map_lookup_X(M, K, &es_tN) ? es_tN : D)` (D worked out only when the key is missing), `es_map_put_X(M, K, V)`, `es_map_has`, `es_map_remove(site, M, K)`, `es_map_length`, `es_map_is_empty`, `es_map_list(M, keys?)`, `es_map_copy`, `es_map_same`, `es_map_text`. A change is one C block that works out its parts in written order, then `EsValue *es_p = es_map_at(site, es_m, es_k)` (after the amount, which could change the map) and changes `es_p->n` (or `es_add_X(es_list_retain(es_p->l), ...)`). Parts are worked out in written order (`cg_ordered`); a lookup counts as an effect. `for each K and V in M` keeps `es_map_snapshot(M)` in a hidden variable and goes over `entries[0..used)`, skipping removed ones (hash 0). Frames mark maps 'm' (left out of the call chain, like lists); record fields that hold maps are 'm'.
- **Runtime** (`runtime/es_map.h`, the eighth part): `EsMap {header, keys, values (EsItems), len, used, cap, entries (EsEntry {hash, key, value}), index (uint32_t places: 0 empty, ES_GONE removed, else 1 + the entry), slots (a power of two), filled}` (in `es_memory.h`, which frees it). Insertion order: entries stay in the order added; setting an existing key keeps its place; a removed entry keeps its place with hash 0 until the entries are packed (when they're full and a quarter are removed, or when the index is rebuilt). Maps of up to `ES_MAP_SMALL` (8) entries have no index (a scan comparing hashes); bigger ones rebuild the index (`es_map_reindex`: at least 16 places, more than twice the entries) when more than two thirds of it is filled, with linear probing. Hashes: `es_mix` (the splitmix64 finalizer, never 0) of the text's bytes 8 at a time, or of a number key's bits. Number keys are kept as `es_key_number(x)` (whole numbers up to 2^53 exactly, others rounded through `%.12g`, close to `is`'s 1e-12; -0 is 0; NaN is one key), so numbers that differ only by rounding errors are the same key (printing rounds further, to 10 digits). Errors: "There's no value for "Bob" in the map." (the key cut at 60 characters; a hint about `has` and `, or`; a change says "It has to be in the map before it can change. ..." instead), "I can't remove "Bob": the map has no value for it.". Lists of maps (`ES_ITEMS_MAP`) and maps of lists or maps copy their inner lists and maps with them (`es_items_copied`, `es_copy_inner`, `es_map_own_deep`), like lists of lists; records and text are shared. `es_map_fix` makes a map immortal and takes it out of the live counts (fixed maps). Printing: `"Paris" is 19 and "Junie" is 24` (text quoted; lists, maps and records in parentheses, `(an empty list)`/`(an empty map)`); an empty map prints as empty text. The record cycle check (`es_each_inner_value`) follows maps.

### Text (implemented in `src/front/parse_text.c`, `parse_list.c`, `check_text.c`, `src/back/codegen_text.c`, `runtime/es_text.h`)

- **A character is a Unicode code point stored as UTF-8** (every byte that isn't a UTF-8 continuation byte starts one), so `"café"` has 4. `EsText.count` caches the character count (0 = not worked out; codegen writes it into literals); text with `count == len` is ASCII and handled byte by byte. Single ASCII characters are 128 static immortal texts (`es_ascii_text`).
- **Characters and pieces reuse the list forms** in `parse_list.c` through a `Noun` (`item`/`items` or `character`/`characters`): `character P of|in T`, `first|last character of T`, `characters A to B|to the end of T`, `first|last N characters of T`, `every other|second|3rd character of T`, postfix `without the first|last character` (`without_phrases` with a `WITHOUT_CHARACTER` flag), plus `the number of characters in T` (`EXPR_LENGTH`). They're `EXPR_ITEM`/`EXPR_SLICE` with `characters` set; the checker (`checker_check_characters`) requires text, codegen calls `es_char_at`/`es_text_range`/`es_text_end`/`es_text_without`/`es_text_every`, and the runtime errors mirror the list ones with "character" (`es_char_index`). A list form on text (or a character form on a list) gets a note showing the other form.
- **`EXPR_TEXT_OP`** (`TextOp`, with `operand`, `arg`, `arg2`, `negated`): prefixes `the characters of T`, `the words of T`, `the lines of T`, `the code of T`, `the character with code N`, `the position of X in T` (single values, like `length of`); postfixes `T in uppercase|lowercase` (matched as whole phrases only, so `count ... to n in steps of 2` keeps its `in`), `T without extra spaces`, `T split by X`, `L joined with X`, `T with X replaced by Y` (`parser_at_replace`: `with` + a single value + `replaced`; after a name that isn't a known function this beats the call reading); `C is [not] a letter|digit|space` / `isn't a ...` only when the word carries a dropped `a` (`Token.filler`), so `x is letter` compares with a variable `letter`.
- **Searching:** `contains` works on text or lists and `the position of X in T|L` too: both are `DEFER_SEARCH` (`checker_settle_search`): text needs text ("I can only look for text in text"), a list unifies X with its items, an unknown container with a non-text X becomes a list of it, and an undecided one is suggested as `(text)`. `starts with` / `ends with` need text on both sides. Position is 1-based, **0 when not found**, 1 for empty text; lists use `es_position_n/b/t/l`.
- **Semantics:** words split at runs of space/tab/CR/LF/FF/VT; lines split at `\n` (a `\r` before it dropped; no extra line for a final `\n`; empty text has none); `split by` keeps empty pieces, empty text gives an empty list, an empty separator is a runtime error; `joined with` takes a list of numbers, text or yes/no; trim takes spaces off both ends; replace is left to right, non-overlapping (empty text to replace is an error); case and letters cover ASCII, Latin-1, Latin Extended-A, Greek and Cyrillic (`es_upper`/`es_lower`/`es_letter_code`); digits are 0-9; `is a ...` is yes only for exactly one character; codes are 1..1114111 without surrogates.
- **Constants:** any text tool (or character form, `contains` on text, `starts with`) in a `keep` is "A constant can't take text apart or look inside it." (consteval).
- **In-place building:** `set T to T followed by|and A ...` where only the leftmost part reads T (`reads` in codegen_text.c) becomes one `es_append(&T, A)` per part; `es_append` grows text whose count is 1 by doubling `EsText.cap` (realloc, counted against the memory limit) and otherwise joins as before.
- **`as a number`** errors: empty text is "I can't turn empty text into a number.", long text is cut at 60 characters with "...", and both have a hint; consteval matches.

### Records (implemented in `src/front/parse_record.c`, `check_record.c`, `src/back/codegen_record.c`, `runtime/es_record.h`)

- **Definitions:** `NAME is a kind of thing with:` at a line start, then one field per sentence, indented: `NAME, which is KIND [or nothing] [, starting at E].` (`parse_record`; errors for a missing comma, `which is`, kind, colon, fields on the header line, over-indented fields, extra words). The pre-scan (`find_records` in parse_names.c, run first) finds every kind (in order: its index makes `TYPE_RECORD + index`) and every field name (`NAME, which is` at a line start, in `Parser.fields`), and adds kind names as known names (a method's input). AST: `STMT_RECORD {name, index, fields}`, `Field {name, type, initial, pos, folded}`; `Program {body, records}` (`Records` = `Vec(RecordKind {name, display, plural, definition})`); `ast_type_name(arena, records, type)` names kinds ("a dog", "a dog or nothing", "a list of dogs"; plural: `s`, `es` after s/x/z/ch/sh, `ies` after consonant+y).
- **Kinds:** `parser_parse_kind` accepts a record kind (`dog` after the dropped `a`), plural in list kinds, and `or nothing` after a record kind only ("Only a record can be "or nothing", not a number."). `Type`: `TYPE_RECORD` (16) + index, `TYPE_MAYBE` (1<<14) added for "or nothing" (alone: a record or nothing, kind undecided), `TYPE_LIST` is 1<<15. Helpers `type_is_record`, `type_is_maybe` (a concrete one), `type_present`, `type_record`, `type_record_index`; `type_counted` includes records.
- **Values:** `new NAME [with FIELD V (and|,) ...]` (`parser_parse_new`; `new` + a known kind; values are `parse_join`; field names the longest known; a `new` with fields inside another needs parentheses; its span starts at a dropped "a"). `R's FIELD` (`EXPR_FIELD {record, name, index}`), `EXPR_NEW {type, values (FieldValue {field, value, index})}`. Targets: `parser_parse_target` (`set`, `add ... to`, `increase ... by` ...) takes a name, `it's`, or `(X)'s` plus fields (`Stmt.assign.field` / `change.field`). `let X's ...` is an error.
- **Methods:** `to NAME [,] for KIND [[,] with INPUTS] ...:`. "for" ends a function's name only before a known kind (`at_method_for`; pre-scan the same), so "print receipt for" can still be a name. The record is input 0, named like its kind (`Stmt.function.method`). Calls (`parser_parse_method_args`): `NAME [for] R [and ... | with/using/of/the definition's to/from/in ...]`, as sentences and values (`KnownName.method`; `Parser.method_record` stops `rex with` being read as a call).
- **Methods sharing a name:** methods for different kinds of record can share a name (`reject_duplicate` in check.c; same kind twice, or a plain function, is an error). A call of a shared name (`checker_shared_method`) picks the method by its first input's kind: at once when it's known, otherwise `DEFER_METHOD` (`Deferred.args` holds the inputs; settled in `checker_settle_method`, unsettled ones reported by `checker_report_unsettled_method` before undecided inputs). The checker sets `call.target` on every call (codegen calls it) and `function.overload` (1 + the kind's index) on shared methods, whose C names get `_0rN` (`cg_append_function`).
- **Checker:** `checker_collect_records` (defined twice), `checker_check_record` (pass 1, after constants: top level only, fields twice, starting values via `const_eval` with only constants or an empty list, a field that always holds its own kind (directly or through others) is an error). `checker_check_new` (unknown fields with a suggestion, given twice, kinds, missing fields listed). `checker_check_field`: a known record kind; an undecided base takes the only kind with that field, else waits (`DEFER_FIELD`). Records compare by identity (`is`), can be copied (`LIST_COPY` when known to be a record), and in lists use identity for `contains`/`position`.
- **Nothing:** `checker_check_value` gives `nothing` the kind `TYPE_NOTHING` where a value may be nothing (set, new, call inputs, give back), and `checker_fits` lets a record go where a record or nothing is kept (otherwise unify). `X is [not] nothing` (`checker_check_nothing_test`) needs a record or nothing (`TYPE_MAYBE` if undecided). **Narrowing:** `Checker.present` holds paths (`checker_path`: a name, or name's field...) checked not to be nothing (`checker_narrow_condition`: `is not nothing` when true, `is nothing` when false, `and`/`or`/`not`), added for if branches (and later branches), while/until bodies, the right side of `and`/`or`, and after a one-branch `if` whose body ends with give back/stop/break/skip. `checker_narrow` makes a checked name or field its record (`Expr.narrowed`; `DEFER_PRESENT` when the kind isn't decided). Setting a path kills it and everything under it; a loop body that sets a path kills it before the body (`checker_kill_set_in`). `Checker.unnarrowed` checks an expression as written (`x is nothing`, a field being set). Unchecked use: "\"node's next\" could be nothing, so check it first.".
- **Codegen** (`codegen_record.c`): per kind `typedef struct {EsRecord base; ... fN;} es_RN`, `es_rnN` (field names), `es_roN` (offsets), `EsRecordType es_rtN {"a dog", n, names, kinds "ntblr", offsets, size}`, `es_newN(fields...)`, and `es_k_0dN_F` for list starting values (copied per record). A variable is `EsRecord *` (`es_vrN_x`, `es_vmN_x` for or-nothing; lists `es_vl1rN_`), NULL for nothing. Field reads: `((es_RN *)var)->fF` (retained if counted) for a plain variable, else `es_field_X(R, offsetof(...))`. Field sentences are one C block (`cg_field_stmt`; the amount first when written first). A narrowed expression is wrapped in `es_present(site, ...)`. `nothing` is `NULL`; `es_is_nothing`, `es_record_same`, `es_record_copy`, `es_record_text`. A narrowed name reads its or-nothing variable. Inputs that are records are retained by the frame (`.r`) like text.
- **Runtime:** `EsRecord {header, type, prev, next, mark}` (in es_memory.h), NULL-safe `es_record_retain/release/set/drop`, `es_record_new`. Freeing is iterative: `es_free_object` frees text at once and lists/records through `es_dying`. Lists hold records as `ES_ITEMS_RECORD` (`at.r`, items may be NULL), shared by copies and slices. Printing: `a dog with name "Rex" and age 3`, text quoted, lists and records in parentheses (`ES_RECORD_DEPTH` 3 levels, then "a node with ..."; in lists records are parenthesized). Stack traces show record inputs (`es_record_short_text`, cut at 60 characters). With `ES_DEBUG_MEMORY`, live records are linked (`es_memory.records`) and `es_finish` calls `es_report_cycles` (trial deletion; lists counted only when held once) to explain records alive in a circle (exit 70).

### Types (implemented in `src/front/check_types.c`, `check_expr.c`, `check.c`)

- **Kinds:** `Type` in `ast.h` is an unsigned number: `TYPE_NUMBER`, `TYPE_TEXT`, `TYPE_YESNO`, `TYPE_NOTHING` (only a function's result), plus `TYPE_UNKNOWN` (undecided) and `TYPE_ERROR` (after a mistake; unifies with anything silently, so one mistake gives one message). A list type is its innermost kind plus `TYPE_LIST` (8) per level (`type_list_of`, `type_is_list`, `type_item`, `type_base`, `type_counted` for text and lists), so equal types are equal numbers. `ast_type_name(arena, type)` gives "a number", "text", "a yes/no value", "nothing", "a list of numbers", "a list of lists of text", "a list" (items undecided); `checker_kind(c, var)` is the same for a variable. The checker writes `Expr.type` for every checked expression and `param_types`/`result` for every function.
- **Inference engine** (`check_types.c`): `TypeVar` indexes into `Checker.types` (union-find with path halving; each root has a type and the line it was decided; a list root has type `TYPE_LIST` and an `item` variable). `types_new` (a list type gets an item variable), `types_new_list`, `types_item`, `types_of` (rebuilds the full `Type`), `types_unify` (checks `compatible` first, with an occurs check, then `join`s: the root that knows more wins, lists join their items; false if two different concrete kinds), `types_require` (unifies with a new variable of that kind), `types_line`. Every checked expression is recorded in `Checker.typed`. `types_defer` queues operators whose meaning depends on kinds (`DEFER_AND`: logical for yes/no, join with text, a number side forces the other to text, a list joins text and nothing else; `DEFER_ORDER`: numbers or text; `DEFER_TO_NUMBER`: number or text; `DEFER_JOIN`: `followed by` is a list when both sides are lists (unified; "I can't join a list of numbers with a list of text."), text as soon as either side is known not to be a list; `types_defer_one_of`/`DEFER_ONE_OF`: one of the `KIND_` bits, reported as "<message>, but this is <kind>."), trying to settle them at once. `types_finish(c, first_error)` settles the rest in a fixpoint loop, reports undecided inputs/results (innermost kind undecided: "I can't tell what kind of value "x" is." / "… gives back.", suggesting `(a number)` or, for a list, `(a list of numbers)`) **only if no other error was reported**, then writes kinds into the AST.
- **Rules** (`check_expr.c`; messages keep the old runtime wording, with carets): arithmetic needs numbers (`checker_arithmetic`, also used for change statements with the variable on the left); `or`/`not`/conditions need yes/no; equality unifies both sides ("I can't compare a number with text."); ordering unifies and defers; `followed by`/`as text` give text; `length of` and file names need text; `nothing` as a value is "\"nothing\" can't be used as a value."; constants have the kind of their value. `checker_require(c, var, type, at, message, hint)` reports "MESSAGE, but this is KIND.".
- **Variables** (`check.c`): `Symbol.var`; `let` shares the value's variable; `set`/`ask`/`read file` into an existing variable must match ("\"total\" is a number (made on line 1), but this is text."); loop numbers are numbers; a for-each item has the list's item kind. `Loop.it` is the kind of `it` (a number, or the item).
- **Functions:** `Function.params`/`result` are type variables, from the annotations or fresh; a function with no `give back E` anywhere in its body (`gives_value`) gives back nothing. Calls unify each argument with its input ("\"halve\" needs a number for \"x\", but this is text." with "\"x\" is a number because of line N…" or the definition when it was written down). A nothing-function used as a value is "… doesn't give back a value, so it can't be used here." `give back E` unifies with the result ("… gives back text (since line N), but this is a number."), a bare `return` in a value function and a value in a `giving back nothing` function are errors.
- **Order:** `check_program` checks top-level constants, then top-level function bodies, then the rest of the program, then `types_finish`, then `diag_sort(diag, first_error)` puts the checker's errors into source order. Because constants are checked before the main program, `lookup_constant` finds variables through `checker_find_later`, and a function's "only sees its own inputs" note uses `later` too.

### Runtime semantics (implemented in `runtime/es_memory.h`, `runtime/es_program.h` and `runtime/es_runtime.h`)

- **Eight files** (the seventh, `es_record.h`, is records, and the eighth, `es_map.h`, maps; see "Records" and "Maps"), embedded in this order: `es_memory.h` (text and list objects and reference counting, the memory checks), `es_program.h` (start/finish, output, sites, the call stack, errors), `es_runtime.h` (text, numbers, comparisons, functions, loops, files and input), `es_list.h` (lists; see "Lists"), `es_sort.h` (sorting) and `es_text.h` (text tools; see "Text"). Each later file includes the one before only when its guard isn't defined, so each also works on its own in an editor.
- **No tagged value:** the checker knows every kind, so generated code uses `double`, `bool`, `EsText *` and `EsList *`, and the runtime never checks kinds. Runtime errors are only what kinds can't catch: dividing or `mod` by zero, a count step that isn't more than zero, a times count that's negative/not whole/too big, `as a number` on text that isn't a number, file errors, `es_no_result`, recursion depth, and list positions (see "Lists").
- **Memory: reference counting for text and lists** (full description in `docs/memory.md`). Every heap object starts with `EsObject {kind, refs}`: text (`ES_OBJ_TEXT`, its characters right after the `EsText {header, len, chars}`) and lists (`ES_OBJ_LIST`, `EsList`, owning the text and lists in it). `es_object_release` is the generic release; `es_list_retain`/`es_list_release`/`es_list_set`/`es_list_drop` are the list versions of the text functions, and an empty list variable holds the immortal `es_no_list`. `refs == ES_IMMORTAL` means never counted or freed: text literals (codegen's `static EsText es_sN`), text constants, and the runtime's own words (`ES_STATIC_TEXT`, e.g. `es_lit_yes`, `es_empty_text`). `es_retain`/`es_release` take `EsText *` (never NULL: empty variables hold `&es_empty_text`); `es_free_object` frees by kind and is kept out of line (`noipa` on GCC, `noinline` on Clang), because otherwise GCC sees `free()` reachable from releases of static immortal text and warns `-Wfree-nonheap-object`. `es_set(&slot, t)` stores and then releases the old text; `es_drop(&slot)` releases and stores `&es_empty_text`.
- **Ownership convention (keep it consistent):** every text or list expression yields an owned value. Reading a variable retains it; literals and constants are used directly. Runtime functions that take `EsText *` or `EsList *` **consume** them (release, or return them: `es_join` returns the other side when one is empty), except `es_push_*` and the "only looks" helpers. Functions own their text and list arguments. Numbers and yes/no own nothing: no retain/release is ever generated for them. `es_text_new(len, &chars)` and `es_text_copy` make heap text with a count of 1.
- **Environment hooks** (`ES_SKIP_OUTPUT`, `ES_ANSWERS`, `ES_DEBUG_MEMORY`, `ES_MEMORY_LIMIT`) are read in `es_init` only under `#ifdef ES_HOOKS`. The compiler passes `-DES_HOOKS` only for `run` with `ES_HOOKS=1` in its own environment (exported by `tests/run.sh` and `tests/bless.sh`; the shell sets it for its child); `build` never does (`cli/no-env-hooks-in-built-programs`). Memory tests build from `emit` with `-DES_HOOKS` (`build_with_hooks` in run.sh). See `SECURITY.md`.
- **Memory checks:** live objects and bytes are always counted (`es_memory`). `ES_DEBUG_MEMORY=1` makes `es_finish(true)` fail with exit 70 ("Memory check: N value(s) was/were still alive at the end of the program (B bytes).") if anything is alive. `ES_MEMORY_LIMIT=N` fails with exit 70 ("... more than N bytes of text and lists alive at once.") as soon as live heap bytes would exceed N (`es_memory_take`, checked before `malloc` and before a list grows, so nothing is left unreferenced for LeakSanitizer). Runtime errors exit without the check.
- **Printing** (`es_number_text`, `es_yesno_text`, `es_list_text`): whole numbers with `|x| <= 2^53` (`ES_EXACT_WHOLE`; consteval's `EXACT_WHOLE`) print with `%.0f` (no decimals, never `-0`). Other numbers are rounded to 10 significant digits (`%.10g`, read back; a result that's whole prints with `%.0f`), so `0.1 plus 0.2` prints `0.3` and `0.99999999999` prints `1`; `const_number_text` matches. NaN prints `not a number`; infinities print `infinity` and `-infinity`. yes/no prints `yes`/`no`. Lists print as "72, 95 and 88".
- **Numbers:** `+ - *` and unary `-` are plain C. `es_div`/`es_mod` fail with "You divided by zero."; `es_mod` uses the integer remainder for whole numbers below 9e15 (same as `fmod`, whose −0 results aren't observable) and `fmod` otherwise.
- **Text:** `es_join(a, b)` (for `followed by` and text `and`), `es_say`, `es_length` (UTF-8 characters, via `es_text_chars`), `es_text_is_empty`, `es_text_number(line, t)` for `as a number` (optional surrounding spaces, an optional `-`, digits, optionally `.digits`; otherwise "I can't turn "…" into a number.").
- **Comparisons:** numbers are equal when `a == b` or `|a - b| <= 1e-12 * max(|a|, |b|)` (`es_close`), so `0.1 plus 0.2 is 0.3` is yes. `es_number_order` returns 0 for numbers that are `es_close`, so `<=`/`>=` agree with equality and `<`/`>` are false for them. Text: `es_text_same`, `es_text_order` (bytewise), both consuming. yes/no: C `==`/`!=`.
- **Files:** `es_write_file` writes the text plus `\n`. `es_read_file` strips one final `\n` (and a `\r` before it). I/O errors read like `I couldn't read the file "x": it doesn't exist.`
- **Input:** `es_ask` prints its prompt without a newline, reads one line (stripping `\n`/`\r\n`), and gives empty text at end of input.
- **Shell support:** all program output goes through `es_out`, which drops the first `ES_SKIP_OUTPUT` bytes. With `ES_ANSWERS` set, `es_read_answer` replays answers from that file before reading stdin, appends new ones, and stdin is unbuffered. Both are set only by the shell (which also sets `ES_HOOKS=1` for its `run`).
- **Ending:** `main()` ends by releasing its text variables and calling `es_finish(true)` (flush, then the memory check). `stop the program` in `main()` is `goto es_end` (that same ending); inside a function, the function releases its own text and calls `es_stop()`, which runs `es_finish(false)` (no check: the callers' values are out of reach) and exits 0. Runtime errors flush stdout, print `Line N: message`, the source line with carets (`es_show_source`, laid out like compile errors), an optional hint line, and the call chain (`es_show_calls`) to stderr, and exit 1 with no clean-up.
- **Sites and the call stack:** runtime functions that can fail take a site (an `int` index into the program's `es_sites` table of `EsSite {line, column, length}`; `es_init(es_sites, es_source, es_source_line_count)` hands over the tables) instead of a line. Every EasyScript call pushes an `EsFrame {fn, call, in}` onto `es_stack` (an array of `ES_MAX_DEPTH` frames; `es_depth` counts them) with `es_enter`/`es_enter_one`/`es_enter_many`: `fn` is a static `EsFunction {name, inputs, input_names, kinds}` (kinds `n b t l`), `call` the call's site, and `in` the input values (`in.one` inline for one input; for more, `es_enter_many` copies them onto the growing `es_inputs` array and `in.many` is where they start, so no frame points into a C stack: GCC's `-Wdangling-pointer` caught that); text inputs are retained by the frame and released by `emit_drop_all` through `es_input(i)`. `es_leave` is `es_depth--`; `es_leave_many(n)` also takes the inputs off `es_inputs` (codegen's `leave_code` picks). The depth check comes before the push, so "too deeply" is reported at the call, while working out the caller. The chain: "while working out "F" (x was 1, s was "text...")" (numbers, yes/no, and text cut at 30 characters; lists skipped), then "called from "G" on line N (its inputs)" per caller, collapsing a run of three or more calls from the same place into "...it called itself N more times..." (thousands with commas), and last "called from line N: <the source line>". Costs about 3% on `fib`, nothing measurable elsewhere.
- **Loops:** `es_count_start(site, from, to, step, has_step, down)` checks step > 0, picks the direction (`down` forces -1 and is empty when from < to), and works out `last` (the last round's index, adjusted ±1 for rounding; `LLONG_MAX` for an endless or NaN count) and `at_end` (the first round whose number is `es_close` to `to`; from there to `last` the number is `to`). `es_count_value(&c, i)` is `from + direction * i * step` (from scratch each round, no drift) or `to`. This matches the old round-by-round rule exactly (checked against it on 20,000 random counts). `es_times(line, n)` needs a whole number ≥ 0 (and ≤ 9e18).
- **The runtime is header-only** (all `static`) and silences `-Wunused-function` and (Clang, GCC 12+) `-Winfinite-recursion` (endless recursion is an EasyScript runtime error) with pragmas. Generated programs must compile cleanly under `-std=c11 -Wall -Wextra -Wpedantic` with both GCC and Clang; `make test` checks this (`strict-c/generated-programs`). Fix warnings in the runtime's structure, not with more pragmas.

## Parser rules

- **New syntax must follow `docs/design-principles.md`** (statements vs values, how inputs are introduced, `of`/`in`, optional and "not found" results, errors, equality, copying). A phrase that can't follow them is added to its "Known exceptions" with the reason, in the same commit; a doubt goes under "Open questions" instead of into the parser.
- The parser must be **deterministic**. Never guess what the user meant, and never use heuristics, "best match", or silent fallbacks.
- If a sentence is ambiguous or doesn't match any grammar rule, **report an error**. Include the line and column, what was expected, and concrete suggestions (for example, the closest valid sentence forms). Don't pick one reading.
- Because a period ends a statement, it can't also be part of an identifier. The current lexer accepts `.` in identifiers so that `myfile.txt` works. That conflicts with the new syntax, so filenames have to become string literals.

## Compiler implementation rules

- **Arena allocator for all compiler memory** (tokens, AST nodes, strings, symbol tables). No per-object `malloc`/`free` and no `strdup`. Free the whole arena once at the end. The compiler is leak-free: verified with macOS `leaks --atExit` on every command, including error paths and the shell. Keep it that way.
- **No fixed-size buffers.** No `char buf[256]`, `VarMap var_map[100]`, `char line[1024]`, and so on. Grow storage dynamically from the arena. The same goes for generated C: don't emit `char x[256]` for strings.
- Write portable C11 (`-std=c11 -Wall -Wextra`). Invoke the C compiler as `cc`, not `gcc`.
- Report compile errors with source positions rather than calling `exit(1)` deep inside the lexer or parser.

## Code organization (target)

The compiler follows this pipeline:

- **Front end:** lexer → parser → checker.
- **Middle end:** IR and optimizations (added later).
- **Back end:** C codegen.

Each stage talks to the next only through shared data structures: tokens, the AST, and the symbol table. **The parser never emits C. Codegen never looks at source text.** (The one exception is `src/back/source_table.c`, which only copies the source lines into a C table for runtime errors; the driver passes its output to codegen as opaque text.)

Target layout:

```
src/main.c            driver: runs the passes in order
src/front/            lexer.c, parse_expr.c, parse_stmt.c, check.c
src/back/             codegen_c.c
src/common/           arena.c, util.c, diag.c, ast.h
runtime/              runtime support linked into generated programs
```

Rules:

- **Group code by job**, not one file per function. Each module has a small public `.h` and keeps its private details in the `.c`.
- **Keep files under ~600 lines.** Split a file when it passes that, or when it covers two different concerns.
- **Helpers that aren't used elsewhere must be `static`.**
- **No global mutable state.** Pass context structs (`Compiler`, `Parser`, `Checker`, `Codegen`) explicitly.
- **Prefer opaque structs** when other modules don't need the fields.
- **Functions stay short and do one thing.**

Don't move code into this layout separately. Create it as later steps rewrite each stage, and update "Current state" as each piece moves.

## Testing

- **Every feature needs tests in `tests/`.** That includes parser error cases: ambiguous input must produce the expected error and suggestions.
- **Never commit while any test is failing.** Run `make test` and `make test-debug` (sanitizers) before every commit.
- `tests/ast/NAME.es` plus `NAME.out`, and an optional `NAME.err`: the same as `tests/tokens`, but run with `easyscript ast`.
- `tests/tokens/NAME.es` plus `NAME.out`, and an optional `NAME.err`: run with `easyscript tokens`. Stdout must match `NAME.out`. If `NAME.err` exists, the run must exit 1 with exactly that stderr. Otherwise it must exit 0 with empty stderr. Name error cases `err_*`.
- `tests/unit/*.c`: C unit tests for `src/common` and `src/front`. Don't use `a`, `an` or `the` as variable names in `.es` fixtures, because the lexer drops them, linked into `build/*/unit_tests`. Each test is `static void test_x(TestContext *t)`, registered with `unit_run` in that file's `*_tests(TestRunner *)` function. Declare that function in `unit.h` and call it from `main` in `unit.c`. Use `CHECK`, `CHECK_SIZE`, and `CHECK_STR`. `t->arena` is fresh for each test.
- `tests/run/NAME.es` plus `NAME.out`: the program is compiled and run with `easyscript run`, with stdin from `NAME.in` if it exists (otherwise `/dev/null`). Stdout must match `NAME.out`. If `NAME.err` exists, the program must exit 1 with exactly that stderr; these are the runtime-error tests, named `err_*`. Otherwise it must exit 0 with empty stderr.
- `tests/errors/NAME.es` plus `NAME.err`: compiled with `easyscript emit`. It must exit non-zero, and stderr must match `NAME.err` exactly. Mostly checker errors, plus one parse error showing that the checker is skipped.
- `tests/shell/NAME.in`: typed into the interactive shell (`easyscript` with no arguments) in an empty scratch directory. Stdout must match `NAME.out` and stderr `NAME.err` (empty if there's no `.err`); `make bless` writes both.
- **Audits** (end of `tests/run.sh`, need `python3`, skipped otherwise):
  - `tests/tools/error_coverage.py` checks that every error format string in `src/` and `runtime/` (`diag_error`, `parser_error`, `es_fail`, consteval `fail`, `usage_error`, `fprintf(stderr, "…")`, found by `tests/tools/messages.py`) matches some expected `.err` file or `expect_failure` line in `run.sh`. Messages that need the OS to fail are in its `EXEMPT` table with a reason.
  - `tests/tools/vocab_coverage.py` checks (allowing dropped `the`/`a`/`an` between words) that every phrase the parser accepts (statement table, phrase tables, `parser_at_word`/`parser_match_words`/`parser_expect_phrase` literals, NULL-terminated word lists, operator words) appears as whole words in a code span of `docs/vocabulary.md`.
  - `audit/no-underscore-suggestions` (shell, in `run.sh`): a quoted example with an underscore in a note line (`like`, `Try`, `mean`) of an expected `.err` must appear in its `.es`, so messages never invent underscore names.
  - **Adding an error message means adding a test that produces it; adding a phrase means documenting it.**
- **Message style** (audited at v0.1.0): every error, including CLI and system errors, is a plain first-person English sentence ("I couldn't open the file "x": it doesn't exist.", "I don't know the command "x"."). No "Error:" prefixes, codes or jargon. Notes give a concrete fix or example.
- **README sync checks:** the end of `tests/run.sh` checks that the README's "A first program" block equals `examples/programs/first_program.es`, and its "A bigger example" block equals `examples/programs/taste.es` (which runs and has a `.out`).
- CLI behavior (modes, usage errors, no files left in the cwd, temp-dir cleanup) is checked at the bottom of `tests/run.sh`. Add a check there when changing the CLI.
- `examples/programs/NAME.es` plus `NAME.out` and optional `.in`/`.err` (run like `tests/run`), `examples/lexer/NAME.es` plus `NAME.tokens`, and `examples/parser/NAME.es` plus `NAME.ast` (both with an optional `.err`) back the docs. `tests/run.sh` fails if any other folder or a loose `.es` appears under `examples/`.
- `tests/run.sh` compiles every generated program with `-Werror` (strict C, see Current state). It runs the unit binary, then the run/errors/tokens tests and the examples (each in an empty scratch directory, via the shared `check_run`/`check_errors`/`check_dump` functions), then the CLI checks. It prints PASS/FAIL per test plus one summary and exits 1 if anything fails. The `ES` and `UNIT` env vars choose which binaries are tested.
- Expected files record current behavior, including known quirks (for example, the blank line after `FILE READ` in `run/file_io.out`). When fixing a quirk, update the expected file in the same commit.
- **`make bless`** (`tests/bless.sh`) rewrites every golden file from the current output, then shows `git diff --stat` and any new expected files.
  - It covers `tests/run`, `tests/errors`, `tests/tokens`, `tests/ast`, `examples/programs`, `examples/lexer` and `examples/parser`. Run tests use `.in`; exit 1 writes `.err`.
  - In the tokens/ast folders, `.err` is written on failure and removed on success.
  - It exits 1 with "NOT BLESSED" when no golden file could make a test pass.
  - **Only bless after confirming the new output is intended.** First read every failing diff from `make test`. Bless only if each difference is a deliberate change. Then review `git diff` before committing, and say in the summary which expected files changed and why.
  - Never bless just to get a green suite, and never bless output you haven't read.

## Documentation rules

**Every commit that adds or changes a language feature must, in the same commit:**

1. Update the status in `README.md` (the Status table and "Coming soon" list, and the roadmap table if a phase changes).
2. Update `docs/vocabulary.md` with every new or changed word, sentence pattern and synonym, each with an example and its status.
3. Update the matching chapter of `docs/language-guide.md`, including its status label.
4. Add or update an example in `examples/` with its expected output (`examples/lexer/NAME.tokens`, `examples/parser/NAME.ast`, each with an optional `.err`, or `examples/programs/NAME.out` with optional `.in`/`.err` for anything that runs).
5. Add an entry to `CHANGELOG.md` under `[Unreleased]`.

## Build

```sh
make                                  # builds ./easyscript (plus build/tools/embed and build/release/unit_tests); no warnings expected
make test                             # builds, then runs tests/run.sh (unit, tokens, ast, run, errors, examples, strict C, docs, CLI)
make debug                            # ASan/UBSan build in build/debug/
make test-debug                       # full suite against the sanitizer build (programs sanitized too), then the leak check
make bless                            # rewrite golden files from current output, then show git diff --stat
./easyscript run FILE.es              # compile + run (generated C/binary go to a temp dir)
./easyscript build FILE.es -o OUT     # compile to an executable at OUT
./easyscript emit FILE.es             # print the generated C
./easyscript tokens FILE.es           # print the lexer's tokens
./easyscript ast FILE.es              # print the syntax tree
./easyscript                          # interactive shell (exit or quit to leave)
make clean
```
