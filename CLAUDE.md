# EasyScript

EasyScript is a programming language with English sentence syntax. The compiler is written in C11. It compiles `.es` source files to C, then builds the generated C with `cc -O2` and runs the result.

## Language syntax (target)

- Statements are lowercase conversational sentences. A **period or a newline** ends a statement.
- A **colon followed by an indented block** opens a block (loops, conditionals, functions). The block ends when indentation returns to the outer level.
- Keywords are **case-insensitive**.
- `the`, `a`, `an` are **filler words**: the lexer/parser ignores them everywhere outside string literals. So they can never be used as identifiers. The one place meaning depends on one is `is a letter|digit|space`, which needs the dropped `a` (`Token.filler`), so `x is letter` still compares with a variable `letter` (and an unknown `letter`/`digit`/`space` gets a note suggesting `is a letter`).
- The 2024 uppercase prototype syntax (`MAKE A VARIABLE x ASSIGN 10`, `PRINT # x`) and its pipeline have been **removed**. Only the sentence syntax exists. `old/*.code` are historical files that no longer compile.

### Lexical rules (implemented in `src/front/lexer.c` and `lexer_text.c`)

- **Names of several words** are a parser matter (see "Names"); the lexer only makes words.
- **Words:** an ASCII letter followed by letters, digits, or `_`. An apostrophe is part of a word only when a letter follows it (`isn't`, `rock'n'roll`). A word ending in `'s` (any case) is the word and then a `TOK_POSSESSIVE` (`rex's` is `rex`, `'s`), and so is `'s` straight after `)`. A trailing apostrophe (`guests'`) is an error. Words are lowercased. `the`/`a`/`an` are dropped, and the next token (including NEWLINE/EOF, but never INDENT/DEDENT) records the dropped word's span in `Token.filler`. A filler-only line passes nothing on to the next line. `tokens` shows it as `[after "the"]`. **There is no keyword table:** every word is a `WORD`, and the parser decides what it means, so `count` can be a variable.
- **Ordinals:** a whole number directly followed by `st`/`nd`/`rd`/`th` (any case, and no more word characters) is `TOK_ORDINAL` (text as written); a wrong ending ("2th") is an error suggesting the right one ("2nd"). Only `every 3rd item of L` uses it.
- **Numbers:** `digits` or `digits.digits`. A `.` is a decimal point only when a digit follows it, so `5.` is `5` and then a period, `.5` is a period and then `5`, and `1.2.3` is `1.2 . 3`. No sign; `-` is always its own token. Letters stuck to a number (`3times`) are an error suggesting `3 times`.
- **Strings:** double quotes only, on one line, with escapes `\n \t \r \" \\` and `\u{HEX}`/`\uXXXX` (1..10FFFF, no surrogates; otherwise "... isn't a character I know."). **Text blocks:** a line ending `text below:` (after the dropped `the`), or a line starting `put`/`write` that ends with `:` and has `text below` in it (`text_below_inside`: the STRING takes the place of `text below`, the words after it are kept, the colon dropped), becomes one STRING (`lexer_text_block`, called from `end_line`): the lines indented more than that line, exactly as written, without their shared indentation, joined by `\n`, up to the last non-blank one. An unknown escape is an error and is kept as written. An unterminated string is an error, and its value runs to the end of the line. `[VALUE]` inside a string splits it (`lex_text_value`): STRING, `TOK_LBRACKET`, the value's tokens, `TOK_RBRACKET`, STRING (each STRING possibly empty); `[[`/`]]` are literal brackets, a lone `]` is an error, text in quotes inside the brackets is its own STRING when its closing quote and then a `]` come on the line (`quote_in_value`: `"[the note, or "none"]"`), and otherwise a quote or line end before the `]` is an error that skips the rest of the line (the RBRACKET then has empty text, so the parser stays quiet). The parser (`parse_text` in parse_value.c) makes `BINARY_JOIN`s of the pieces, leaving out empty ones after the first; "There's no value between these brackets." is the parser's.
- **Symbols:** `. , : ( ) + - * / % = == < > <= >= !=`, and `'s` (possessive). A lone `!` is an error suggesting `!=`.
- **Comments:** `#` to the end of the line (outside strings), and any line whose first word is `note:` (any case, colon directly after it). `notes:` and `note :` are not comments.
- **Layout:**
  - `NEWLINE` ends each line that produced at least one token.
  - Blank lines, comment lines and filler-only lines produce nothing and don't affect indentation.
  - Indentation is measured with a tab as exactly 4 columns (not "next tab stop"). It's compared Python-style: an increase emits one `INDENT`, and a decrease emits a `DEDENT` per closed level.
  - A dedent to a width that matches no open level is an error that lists the valid widths. The line then stays at the nearest enclosing level.
  - An indented first line just emits `INDENT`; the parser rejects it.
  - Parentheses do **not** join lines, but a line whose last token is `,`, `then` or `and` carries its sentence on (`carries_on`, `Lexer.continued`): no NEWLINE, and the next line with tokens gets no indentation handling (blank and comment lines in between are skipped). The shell reads such lines on too.
  - At EOF the last line gets its `NEWLINE`, then a `DEDENT` for each open block, then `EOF`.
- **Positions:**
  - Tokens carry `line` and `column`, both 1-based. Columns count characters (UTF-8 aware), and a tab counts as 1.
  - Each token's `Span` covers exactly its source bytes: `NEWLINE` covers `\n` or `\r\n`, `INDENT` covers the indentation, and `DEDENT`/`EOF` are zero-length.
- **Other characters:** anything else is an error, and lexing continues. Curly quotes and curly apostrophes get a "use straight quotes" note. Non-ASCII letters get a note to use quotes. Invalid UTF-8 is reported as a byte, and control characters as `U+XXXX`.

### Expression grammar (implemented in `src/front/parse_expr.c`, operators; `parse_value.c`, values)

- **Precedence, loosest to tightest:**
  0. `every NAME in L REST` (only at the start of a value: `parse_expression`, which parentheses also use; elsewhere it's an error)
  1. `or`
  2. `and`, which stops before `and call`
  3. `not`
  4. comparison (no chaining), including `contains` / `does not contain` / `doesn't contain`, `has` / `does not have` / `doesn't have` (maps), `starts with` / `ends with` (and `does not` / `doesn't` forms), `is empty` / `is not empty` / `isn't empty` (but `is empty list of ...` compares with an empty list), and `is a letter` / `is a digit` / `is a space` (`parser_parse_char_test`)
  5. `followed by` (its own level, below arithmetic, so `"Sum: " followed by 2 plus 3` is `"Sum: " followed by (2 plus 3)`)
  6. `plus` / `minus` / `+` / `-`
  7. `times` / `multiplied by` / `divided by` / `mod` / `*` / `/` / `%`
  8. unary `-`
  9. postfix `as a number` / `as text`, `added together` / `reversed`, `without the first item|character`, and the text postfixes (`parser_parse_text_postfix`: `in uppercase`, `in lowercase`, `without extra spaces`, `split by X`, `joined with X`, `with X replaced by Y`)
  10. primary (including the list forms in `parse_list.c`, the map forms in `parse_map.c`, the text prefixes in `parse_text.c`, `only L that ...`, and `a new NAME with ...`), followed by any number of `'s FIELD` (`parse_primary` in parse_value.c; `parser_parse_field`), so `'s` binds tightest

  Binary levels are left-associative.
- **`and` is a single `BINARY_AND` node, always "both" (yes/no).** Text on either side is "\"and\" doesn't join text: ..." (`check_and`; consteval matches). `followed by` is `BINARY_JOIN`. **Pieces:** `say`/`show`/`print`/`display`/`complain` take `parser_parse_pieces`: values separated by top-level commas (not before `or`/`sorted`/`as`/`rounded`/`starting`) become left-nested `BINARY_PIECES` (text; codegen `es_join_spaced`, which adds a space unless a piece is empty, the left ends with space/newline/tab/`(`/`[`/`$`, or the right starts with space/newline/tab/`. , ! ? ; : ) ] %`).
- **Operator phrases** live in `Phrase` tables, both words and symbols. The longest full match wins.
  - **Missing last word:** if the next tokens spell a phrase minus its last word, and that prefix is longer than any full match, it's a "Something is missing after … / Did you mean …" error. This covers `is greater 5`, `is at 5`, `multiplied 3`, `as numbr`.
  - **No negated or mixed forms:** `is not greater than` and `is above or equal to` are errors that suggest `is at most` / `is at least` (or `<=`/`>=` after a symbol).
  - **Equality:** `is not equal to` and `isn't equal to` are accepted, and `==` is a lexer token.
- **`times` needs a value after it:** it's multiplication only when the next token can start a value, so `repeat 3 times:` keeps its `times`.
- **Reserved words:** these can't start a value or be names: `and or not is isn't equals reaches plus minus times multiplied divided mod followed as using`. The value words `yes no true false nothing it` are literals. Every other word is a name. `length`, `contents` and `file` are only special when followed by `of` / `of file`; the list words are only special in their forms (see "Lists"), so `item`, `first`, `last`, `only`, `every`, `list`, `copy` can still be names.
- **Prefix forms bind tightly:** `length of X` and `contents of file X` take a single *primary*, so `length of x plus 1` means `(length of x) plus 1`. Postfix conversions wrap the whole form.
- **Calls:** a call is a name (one word, or the longest known name of several) followed by `of`, `with` or `using` (or `to`/`for`/`from`/`in`, for a function defined with that word), then arguments (`parser_parse_call_args`). Each argument is a *unary* expression.
  - **Separators:** arguments are separated by `and` (but not `and call`), and also by commas after `using` only, so `if f of x, say y` keeps its comma. The `and`s are taken greedily, and the checker reports a wrong count. A definition can put `in`/`to`/`from`/`by`/`at` between two inputs (`Stmt.function.joiners`, `parser_input_joiner`; the pre-scan keeps them in `KnownName.joiners`), and a call can use that word there (`joiner_before` in parse_value.c).
  - **Call sentences** (`Parser.call_sentence`, set by `parse_call_statement`): each argument is a `parse_join` value, since the result isn't used.
  - **Arithmetic after the arguments** (+ - * / % plus minus times multiplied divided mod followed by) is an ambiguity error that suggests both parenthesized forms, unless the last argument is parenthesized (`fib of (n minus 1) plus 1` adds; `is_parenthesized` looks at the source).
  - **Comparisons and `or` end the call.**
  - **No inputs:** a bare `NAME` is `EXPR_NAME`, and the checker and codegen treat it as a call when it's a function with no parameters (functions and variables share one namespace).
- **Positions:** every node has a `SourcePos`, holding its span and the line and column of its first token. A parenthesized group's span includes its parentheses. Binary, unary and convert nodes also keep `op_span`.
- **Errors and recovery:** at most one error per sentence (`Parser.sentence_failed`). After an error, the parser skips to the sentence end (`.`, NEWLINE, DEDENT, INDENT or EOF) and continues.
- **`.5`** (a period directly followed by a number) is rejected wherever a value or a sentence is expected ("Write 0.5 instead of .5.").

### Statement grammar (implemented in `src/front/parse_stmt.c`)

- **A program is a list of statements** (`parse_statements(p, block, in_block)`, used for the program and for every block; in a block it stops after the closing DEDENT). A simple statement ends at `.`, NEWLINE, or EOF, and several can share a line when separated by periods; a block statement (`p->ended_with_block`) ends with its DEDENT instead. An INDENT nothing opened is rejected ("nothing above it starts a block") and its whole block is parsed and discarded, so its DEDENT can't close an enclosing block. A sentence-initial `.` is an error. Expressions can't stand alone as statements. `p->ends_with_name` (set from the form; a one-line if's inner statement overrides it) chooses the leftover message.
- **`and` between sentences** (`parser_at_next_action`, `parser_parse_actions`): `and then`, or `and` + a statement word that doesn't open a block or define (not `if unless check count go for do repeat while as forever to keep use privately`; library sentences count) + a token that starts a value (NUMBER, STRING, `(`, a non-operator word); `stop`/`skip`/`break`/`continue` need only no operator word after them, and `move` needs `on`. A name the program knows (functions, names of several words) after `and` is a value. Value parsing stops there (`parser_at_and` in `and`, call arguments, list and map items; `reject_reserved_inside` for names), and the statement list (and a one-line if's body) parses the next sentence.
- **Optional `please`:** a leading `please` is skipped. `please` on its own is an error.
- **Statement forms** (table `forms[]`, keyed by the first word; the AST normalizes synonyms but keeps `Stmt.verb` as written):

  | Form | AST |
  |---|---|
  | `let X be E`, `let X equal E` | `STMT_LET` |
  | `set X to E`, `change X to E` | `STMT_SET` |
  | `add E to X`, `subtract E from X` (amount first) | `STMT_CHANGE` with a `ChangeOp` |
  | `increase` / `decrease` / `multiply` / `divide X by E` (target first) | `STMT_CHANGE` with a `ChangeOp` |
  | `say` / `print` / `show` / `display E`, or plain `write E` | `STMT_SAY` |
  | `write E to file F` | `STMT_WRITE_FILE` |
  | `ask E and call the answer X` (or `and call it X`) | `STMT_ASK`. The lexer drops "the", so the phrase is `and call answer`, and the prompt expression stops before `and call`. Both `ask` and `read file` take both phrases (`expect_call_phrase`). |
  | `append E to file F` | `STMT_APPEND_FILE` |
  | `read file F and call it X` | `STMT_READ_FILE` |
  | `stop the program` | `STMT_STOP` (`stop` on its own, or `stop the loop`, is `STMT_BREAK`; see loops) |
  | `if …` | `STMT_IF` (parse_if.c) |
  | `count` / `go` / `for` / `do` / `repeat` / `while` / `as long as` / `keep doing this until` / `forever` | `STMT_LOOP` (parse_loop.c) |
  | `stop the loop`, `stop`, `break` / `skip this one`, `skip`, `continue`, `move on` | `STMT_BREAK` / `STMT_CONTINUE` (parse_loop.c) |
  | `to NAME …:` / `give back E`, `return [E]` / `call NAME …`, or a sentence starting with a pre-scanned function name | `STMT_FUNCTION` / `STMT_RETURN` / `STMT_CALL` (parse_func.c) |
  | `keep NAME as E` / `keep NAME at E` (`keep doing …` is the loop) | `STMT_CONSTANT` (parse_func.c) |
| `add E to the end of L`, `insert E at position P of L`, `remove item P from L` (or `the first item`/`the last item`), `set`/`change item P of L to E`, `sort L …` | `STMT_LIST` with a `ListChange` (parse_list.c; `add`/`set` hand over when `end of` / an item form follows) |
| `remove K from M` (a map; anything after `remove` but an item form) | `STMT_LIST` with `LIST_REMOVE_KEY` (`value` is K, `list` is M) |
| `set the value for K in M to E`, `add E to the value for K in M` (and the other change sentences) | `STMT_SET` / `STMT_CHANGE` whose `field` is the `EXPR_MAP_GET` (`parser_parse_target`) |

- **Statement words are contextual.** They're special only as the first word, so `let say be 2`, `add 1 to add` and `let file be …` are fine.
- **Names** (`parse_names.c`): a name is one or more WORDs. `Name {text, display, pos}`: `text` is matched (lowercased, one space between words), `display` is how it was written there. `parser_parse_name(p, name, next)` takes the words up to one of `next` (the words that follow the name in that form, e.g. `be`/`equal` after `let X`), the end of the sentence, or a non-word. The first word may be any word that's neither an operator word nor a value word; further words also can't be stop words (`be equal to from by of with in at then that giving`). A word that means something followed by more name words is "\"%s\" can't be part of a name, because it already means something in EasyScript." suggesting the other words (`price tax`; `pay rate` for `rate of pay`).
- **Known names (pre-scan):** `parser_find_names` (run before parsing) records every function name (any length; `intros` holds the `to`/`for`/`from`/`in` its definitions introduce inputs with) and every other name of several words made by `let X be`, `keep X as|at`, `as X:`, `call answer|it|each number X`, `for each X in|from`, `every X in`, and function inputs. `parser_match_name(p, ahead, functions_only)` gives the longest known name there. Values (`parse_name_or_call` in parse_value.c), positions, and statement starts use it; a known function name of several words starts a call sentence even if its first word is a statement word.
  - **Filler as name:** if the current token isn't a valid name, or *is* one of those `next` words, and it carries a `filler` span, the filler was meant as the name. That gives the "can't be used as a name… EasyScript ignores a/an/the" error. `let the total be 0` stays valid.
  - **Reserved words** give "already means something" with a note suggesting a name that says what it holds.
  - **A `next` word with no filler** (`let be 5`) is "Something is missing after "let"".
- **Missing connectors:** `expect_word`/`expect_phrase` report the missing or wrong connector with the form's example sentence. For a wrong phrase, they quote what was written, e.g. `found "and call it"`. If the connector appears straight after the verb (`add to x`, `write to file …`, `append to file …`), the error is "Something is missing after "add"", because `to` would otherwise parse as a name.
- **Unknown first word:** "I don't know a sentence that starts with …", plus one note:
  - the closest statement word (or `please`) by edit distance, if one is close enough
  - otherwise, if the second token is `is`/`=`/`equals`/`be`, a `let X be …` / `set X to …` hint
  - otherwise, the generic list of starting words

  A non-word start gives "A sentence can't start with …".
- **Leftovers:** forms ending in a name or keyword (`add`, `subtract`, `ask`, `read`, `stop`, `break`, `skip`, `continue`, `move`) report extra words as "I expected the sentence to end after …". Others use the expression leftover reporting. Statements with errors are left out of the returned `Block`.
- **Quoting in messages:** `parser_quoted` renders text spans as `the text "…"` to avoid nested quotes.

### Charts (implemented in `lib/charts.es`, `src/modules.c`, `parse_library_stmt.c`, `check_library.c`, `codegen_library.c`)

- **Sentences:** `save a bar|line|pie chart of X as F [, titled T]` and `make a bar|line|pie chart of X called F [, titled T]` are `STMT_LIBRARY` `DO_SAVE_CHART` (`scale` 0/1/2 for the kind, `parts[0]` the title or NULL, `name` a hidden `0chartN`). `X` ends at `as` (`as_ends_value`). In steps in a row, `it` afterwards is F (and `what's in it` reads it).
- **The module:** `lib/charts.es` (EasyScript; `numbers chart`, `text map chart`, `number map chart`, each `with values and kind and title`, giving back SVG text; sine and cosine by their series) is embedded (`es_charts_source`) and joined by `sources_load` when any file has `bar|line|pie chart of` (`at_chart` in `find_uses`): first in order, module `0charts`, display `charts.es`, used by every file. `Sources.shown` leaves out the program's own name in diagnostics and the runtime's file table when it's the only other file.
- **Checker** (`check_chart`): X checked once; the call (`module = "0charts"`, chosen by X's shape: a list, a map from text or from numbers) gets X as plain numbers in the hidden name (and the title in `0chartNt`) and the currency's name as its last input, an `EXPR_TEXT` filled in by `checker_finish_charts` (before `types_finish`, from `Checker.charts`) once X's items are known; it's checked and kept in `parts[1]`. Items not decided yet wait as a number or an amount (`KIND_NUMBER_FIRST`). Errors: "A chart needs a list of numbers or amounts, or a map to them, but this is ..." (`report_unchartable`: the note names the latest value made that a chart can show, or says what a chart needs), "A chart's title has to be text". Amounts are turned into units by `es_list_units`/`es_map_units` in `emit_chart`, and `lib/charts.es` writes them with `as money` (its `shown` helper).
- **Codegen** (`emit_chart`): stores X (and the title) in the hidden names, then emits `STMT_WRITE_FILE` of the call. Tests: `tests/run/charts` (the SVG text), `errors/chart_errors`, `ast/charts`, `ast/err_charts`, `examples/programs/best_months` (with its chart line).

### Inputs in the middle (implemented in `src/front/parse_pattern.c`)

- **Definitions:** `to WORDS a KIND ... another KIND ... some NAME [(KIND)] ...:` (`Pattern`/`PatternPart` in parse_internal.h, found by the pre-scan `parser_find_patterns`, called from `parser_find_names` before the other names, which then skips these lines). A line is a pattern only when an input (`a`/`an` + a kind, by `Token.filler`; `another KIND`; `some NAME`) comes before any of `parser_input_intros`, it has no comma, and it doesn't start with an input. A `STMT_FUNCTION` with `function.pattern` set, named by its words (`give a customer a discount of some percent`), inputs `customer`, `other person`, `percent` (kinds declared for `a KIND`). Errors: a fixed word that's a kind, two inputs in a row (`Pattern.broken`: never matched by calls), two inputs with one name.
- **Calls** (`parser_at_pattern_call`, tried in `parse_statement` before the statement table): the sentence's end (also `, then`, `and then`, `and` + a sentence), then for each pattern starting with the first word, each fixed word is the first one after the input before it at depth 0. Each input is parsed with `Parser.limit` (`parser_peek` returns `limit_token`, a NEWLINE, from there). A `some NAME` value may end with NAME (`10 percent`). `every ITEM` in one input sets `group_list` (`parser_finish_group` makes the for-each). Two fits (or a fit and a known function) is an error; a near miss (first word, and the second fixed word present) says what's missing.
- **Percent changes:** `increase|decrease|reduce X by N percent` is `STMT_CHANGE` `CHANGE_MULTIPLY` by `(100 ± N) / 100` (`by_percent` in parse_stmt.c); `reduce` is a synonym of `decrease`.

### Describing fields and one-line choices (implemented in `src/front/parse_describe.c`)

- **Yes/no fields:** `..., and can be WORD` in a `has` sentence, or `KIND can be WORD [and can be WORD].` after the kind's definition (`parser_at_can_be`, added to its `STMT_RECORD`), make a `TYPE_YESNO` field starting at `no`. The pre-scan (`find_has_fields`) records them, and fields written `(yes ...)`, in `Parser.yes_fields`; `parser_is_describing` (an adjective or such a field) is what `X is WORD`, `the WORD Ls`, `are WORD`, `every WORD ITEM` and `remove the WORD Ls` check, and `parser_adjective_call` gives an `EXPR_FIELD` for a field. `it's WORD` (`parser_parse_field` after `it`) is the adjective when WORD is one and not a field. `a new WORD... KIND` puts `WORD yes` first in the values (`yes_words` in parse_record.c). `mark X as [not] WORD` is a `STMT_SET` of the field (statement word `mark`).
- **Indenting:** `say|show|print|display ..., indented [by N]` (parse_say; `indented` stops the pieces) is `EXPR_TEXT_OP` `TEXT_INDENTED` of the pieces `as text`, `arg` N or NULL (2); `es_text_indent(site, text, n)` puts the spaces before every line (a whole number from 0 to 1000). The checker turns it back into pieces when the program makes a name `indented` and there's no `by`.
- **Choices:** `A if C, otherwise B` (`parser_at_choice`: `if` and then `, otherwise` at depth 0 in the sentence; checked at the end of `parse_expression`) is an `EXPR_TABLE` with no subject (values A, B; conditions C, NULL), shown as `choice`; `X, plus|minus N if C` (`parser_parse_add_if` from `parse_comma_postfixes`; read back when neither `if` nor `percent` follows N) is `X ± (N if C, otherwise 0)` with that 0's `number.zero` set; `X, plus|minus N percent` (`percent_change`) is `X times (100 ± N) divided by 100`. The checker and `cg_emit_table` skip the subject when it's NULL.

### The best group (implemented in `src/front/parse_best_group.c`, `check_aggregate.c`)

Benchmark `benchmarks/forms/best_group`.

### Exact money (implemented in `src/front/lexer_money.c`, `check_money.c`, `runtime/es_runtime.h`)

- **Writing it:** `$`, `€` or `£` followed by a digit is `TOK_MONEY` (text: the currency's word and the cents, `dollars 120000`; commas between groups of three digits, at most two decimals, below 2^53 cents); a number followed by `dollars|euros|pounds` (or the singular) is money too (`money_after_number` in parse_value.c). Both are `EXPR_NUMBER` with `number.money` (the kind) and `text` the cents. Kinds `TYPE_DOLLARS`/`TYPE_EUROS`/`TYPE_POUNDS` (`type_is_money`; "an amount in dollars"), written `(dollars)` or `an amount in dollars`, `a list of dollars`/`amounts in euros` (`money_kind` in parse_kind.c). `ask for an amount [in euros|pounds]` (`es_ask_money`).
- **Checker:** `checker_arithmetic` hands money to `checker_money_arithmetic` (check_money.c): amount ± amount of one currency (an undecided side becomes that money), amount ×/÷ number, number × amount, amount ÷ amount (a number; an undecided left side becomes money), errors otherwise; it returns the result's kind, and `check_change` checks the result fits the target (`Stmt.change.type`). In a program that writes money (`Records.money`, set by the parser for a money literal, a money kind or `ask for an amount`), arithmetic whose side isn't decided yet and could be money (`arith_waits`: both sides of `+`/`-`, a side of `times`, the left of `divided by`; also `percent of`, `half of`, `twice`) is `DEFER_ARITH` (`Deferred.span`, `.line`): settled by `checker_settle_arith` once the sides are known (a definition's input from its calls), and made numbers by `types_default_numbers` otherwise; a result already used as something else is "This gives an amount in dollars, but it's used as a number." A call giving a number where money was given before (or the other way) gets a note saying how to write it. Unary minus keeps money. `as money`/`with commas` take money; `as a number` gives units. `KIND_MONEY` is allowed wherever dates are (sorting, top N, best, joined with, csv). `the total|average|median of` gives the kind of what it adds up, with `KIND_NUMBER_FIRST`: `types_default_numbers` (before table columns default to text, and in `types_finish`) makes what nothing decided a number. `half of`, `twice`, `N percent of` keep money.
- **Codegen and runtime:** C type `long long` (cents), kind letters `u`/`e`/`p` (`cg_kind_letter`: C names, record field kinds, inputs in frames, cells `es_cell_u`), `ES_ITEMS_DOLLARS/EUROS/POUNDS` (kept in `at.n` as numbers of cents, exact; `es_items_numeric`, `es_items_money`) for lists and maps, record fields `long long` (`es_field_u`, `es_vfield_u`). Arithmetic is `es_money_add/subtract/times/divide/ratio/percent/round` (overflow checked by `es_money_fits`; `round()` is half away from zero), comparisons plain C, text `es_cents_text(cents, currency)`; `cg_plan` notes each rounding. csv: money columns read with `es_parse_money`, saved as `$1200.00`; tables right-align money.

### Kinds of text (implemented in `parse_define.c`, `check_record.c`, `check_types.c`)

- `NAME is text that must ... .` at a line start (`parser_text_kind_words`; the pre-scan adds `Records.texts`) is a `STMT_RULE` with `rule.text` the kind, `TYPE_TEXTKIND` (16) + index (`type_is_textkind`; record kinds start at 64 now). `parser_match_kind_name` finds kinds of text first, so they're written `(an email)`, `a list of emails`; a `has` field named like one gets that kind. `X as an email` is `EXPR_CONVERT` `CONVERT_TO_TEXT_KIND` (`convert.kind`).
- **Checker:** `check_text_kind` checks the rule with `it` text, gives it an id, sets the kind's `definition`, and adds it to the `rules` of every field of the kind. A kind of text is text wherever text is needed (`types_require` accepts it for `TYPE_TEXT`, `kind_bit` gives `KIND_TEXT`, comparisons through `text_and_kind`, searches in `checker_settle_search`); text where the kind is needed is an error in `checker_fits` ("This has to be an email, but this is text."), except while `Checker.storing_field` (new, set field), where the field's rules check it. `types_finish` erases every kind of text to `TYPE_TEXT` (`erase_text_kinds`) in the syntax tree, inputs, results and fields, so codegen only sees text; `as an email` is `es_ruleN(site, text)` (`cg_emit_rule` gives a kind of text's rule a text input).

### Constants (implemented in `parse_func.c`, `consteval.c`, `check.c`, `codegen_c.c`)

- **Syntax:** `keep NAME (as | at) E`. `parse_keep_form` sends `keep` + `doing` to the loop and everything else to `parse_constant`. AST: `STMT_CONSTANT {name, value, folded}`, where `folded` (a `ConstValue`: number/text/yes-no) is filled in by the checker.
- **Evaluation** (`front/consteval.c`, `const_eval(arena, diag, records, expr, lookup, ctx, out)`): literals (not `nothing`), unary minus and `not`, arithmetic, `followed by`, `and`/`or` (with the runtime's short-circuit and join rules), comparisons (with the 1e-12 tolerance), `as text`/`as a number`, and `length of`. Calls, `it`, `contents of file` and `nothing` are errors with a "fixed before the program starts … use let instead of keep" note. **It mirrors the checker's kind rules and `runtime/es_runtime.h`'s values exactly**, including `const_number_text` (= `es_number_text`) and the error wording (a kind mistake in a constant is reported by consteval, not by inference). `tests/run/constant_matches_runtime.es` prints each of 30 constants next to the same runtime expression, so change both together.
- **Checker:**
  - **Collection:** `checker_collect_constants` runs after `collect_functions`, so constants can be used anywhere. Duplicates are errors, and so is a constant named like a function (reported at the constant).
  - **Values:** `checker_check_constant` rejects constants inside blocks or functions. Otherwise it evaluates the value via `lookup_constant`: only constants with a lower `index` are allowed, and a failed earlier constant adds no extra error. Self, later constants, functions, variables and unknown names get specific errors.
  - **Use:** names resolve to constants everywhere (`check_name_expr` ignores `floor`). `check_target` rejects changing a constant ("… is a constant, so it can't change", with a `let` suggestion). `checker_clashes` also rejects variables, inputs and loop numbers named like a constant. Unknown names can get "Did you mean "rate"? It's a constant, kept on line N.".
- **Fixed lists:** `keep NAME as a list of ...` (or `an empty list of ...`) makes `ConstValue {kind CONST_LIST, len, list_type, items}`: items must be fixed numbers, text or yes/no of one kind ("All the items of a list have to be the same kind: ..."), never lists ("A fixed list can't hold lists or maps, because those could change."). `length of` a fixed list folds; any other list form or operator on a list in a constant is "A constant can't work things out from a list." `checker_check_list_stmt` rejects add/insert/remove/set item/sort on a constant's name with the constant message, and `check_target` already rejects `add X to`/`set`. Codegen emits a static immortal list (`static EsText *es_ki_NAME[]` plus `static EsList es_k_NAME = {{ES_OBJ_LIST, ES_IMMORTAL}, ...}`); reading the name gives `es_list_copy(&es_k_NAME)` (so a variable, function or list that keeps it gets its own copy), except where it's only looked at: `cg_list_operand` passes `&es_k_NAME` to items, `contains`, `length of`, list operations, slices, `every`/`only` and `for each`.
- **Kind:** the kind of `folded` (an unworked-out constant is `TYPE_ERROR`).
- **Codegen:** each constant becomes `static const double es_k_NAME = …;` (NAN/HUGE_VAL for special numbers), `static const bool …`, or `static EsText *const es_k_NAME = &es_sN;` (a static immortal text object). `EXPR_NAME` resolves constants first (`es_k_`), and `main` adds a `(void)es_k_NAME;` per constant so unused ones don't warn.

### Functions (implemented in `src/front/parse_func.c`, `check.c`, `codegen_c.c`)

- **Definition:** `to NAME [with | of | using | to | for | from | in] P [(KIND)] [and | ,] Q [(KIND)] … [[,] giving back KIND]:` plus an indented block. NAME is every word before the intro word (or `(`, `,`, `giving back`, `:`; `for` always ends it: a method when a kind of record follows or a comma precedes it, otherwise the intro word), so `to make tea:` has no inputs and `to greet someone:` is the function "greet someone"; `Stmt.function.intro` keeps the intro word (headers in messages reuse it). A `(` straight after the name is "A kind in parentheses goes after an input, and inputs come after "with"." (suggesting `to greet with who (text):`). KIND (`parse_kind`) is `number` (after the dropped `a`), `text`, `yes or no` or `yes/no`, and `nothing` only after `giving back`; errors: "I don't know the kind of value …", "I expected ")" after the kind of value…", "Something is missing after "giving back"". The param loop stops at `giving back`; with no inputs, `to roll, giving back a number:` skips the comma. AST: `STMT_FUNCTION {name, params, declared (per input, TYPE_UNKNOWN if none), declared_result, param_types, result (filled by the checker), body}`; `easyscript ast` shows `define area (width: a number) giving back a number`. The name can't be a statement word (`parser_is_statement_word`, which includes `please`): "… starts sentences in EasyScript, so it can't be the name of a function". `to greet a:` (filler before the colon) and `to greet with:` are errors.
- **Return:** `give back E`, `return E`, or bare `return` give `STMT_RETURN` (`returned` is NULL for bare; the parser also makes `give back nothing` bare).
- **Call sentences:** `NAME [with | of | using | to | for | from | in] A and B` (`to`/`for`/`from`/`in` only for a function defined with that word: `parser_at_call_intro`, `KnownName.intros` bits from `parser_intro_bit`; another of them is "\"pause\" takes its inputs after ... not ..."), where NAME was found by the pre-scan (the longest known function name), or `call NAME …`. A sentence starting with the first word of a longer function name gets a note explaining the name and the `with` fix. Zero arguments is allowed (`greet.`), but `greet with` with nothing after it is an error. AST: `STMT_CALL {call: EXPR_CALL}`. Unknown first words also get the pre-scanned function names as suggestions.
- **Checker:**
  - **Function table:** all top-level functions are collected first; a duplicate is "You already defined …".
  - **Where they can go:** a definition inside an if, a loop or another function (`Checker.blocks` / `function`) is "Functions can only be defined at the top level…", and its body isn't checked.
  - **Displays:** `Symbol`, `Function` and `Constant` keep `display` (as first written); messages show it, and names nothing made show as written at the use (`Expr.display`). An unknown name that ends the current function's name gets a note on making it an input with `with`.
  - **Function bodies:** a body sees only its parameters and the names it makes. `Checker.floor` hides `made[0..floor)`, and the loop stack is cleared. An unknown name that exists outside gives "A function only sees its own inputs and the names it makes. … pass it in as an input." Duplicate parameters are errors.
  - **Calls:** an unknown function gets "Did you mean "area"? It's defined on line N." or a "Define it first" note; a variable called like a function gets "… is a variable, not a function". A wrong count is "needs N value(s), but this gives it M" (or "doesn't take any values"), with a note quoting `to area with width and height` and the definition line. A bare name that's a function with parameters counts as 0 arguments.
  - **`give back` outside a function** is an error. Kinds of inputs, results and give-backs: see "Types".
  - **Names:** making a variable, parameter or loop number with a function's name is an error (`checker_clashes`).
- **Codegen:**
  - **Signature and order:** each function becomes `static RESULT es_f_NAME(int es_call, TYPE es_vX_P…)` (`es_call` is the call's site) with C types from `param_types`/`result` (`void` for nothing), with prototypes before all function bodies and main.
  - **Each body:** `emit_function` uses a fresh `Codegen` (its own body, temps, vars, loops, depth). It declares typed temporaries, then every variable made in the function (`cg_declare_name` hoists into `vars`, skipping parameters; numbers `= 0`, yes/no `= false`, text `= &es_empty_text`), `(void)` casts for non-text variables and all inputs, then the frame push (`es_enter`, `es_enter_one` or `es_enter_many`; see "Sites and the call stack").
  - **Returns:** `es_tN = E;` (worked out first), drop text inputs and variables (`emit_drop_all`), `es_leave(); return es_tN;` (or `return;`). Falling off the end: a nothing function drops and calls `es_leave()`; a value function calls `es_no_result(def line, "NAME")` (runtime error "The function "NAME" ended without giving anything back." with a hint).
  - **Calls:** `es_f_NAME(line, A, B)`; when two or more arguments have effects (`cg_has_effects`), all go into typed temporaries first, left to right. A zero-parameter function used as a name is `es_f_NAME(line)`. A call sentence: `es_release(CALL);` for text, `(void)CALL;` for numbers/yes-no, `CALL;` for nothing.
- **Runtime:** the frame push (`es_enter`/`es_enter_one`/`es_enter_many`) fails at `ES_MAX_DEPTH` (10000) frames with "Functions are calling each other too deeply (more than 10000 calls inside each other)." and a hint. `es_leave()` pops. See "Sites and the call stack".

### Loops (implemented in `src/front/parse_loop.c`)

- **`for each N:`** (no `in`): `Stmt.loop.implied`, and the list is an `EXPR_NAME` of N's plural (`parser_plural_of`, the record-kind rule); the checker reports "There's no list called "things" for this to go through." when that name isn't made.
- **Forms** (all need `:` plus an indented block via `parser_parse_block`; no one-line loops): `count [down] from A to B [by S | in steps of S] [and call each number N | as N]`, `go from …` (same as `count from`), `for each N from A to B [by S | in steps of S]`, `for each N in L` (`LOOP_EACH`, `list`; see "Lists"), `do this N times` / `repeat N times`, `while C` / `as long as C` / `repeat while C`, `keep doing this until C` / `repeat until C`, `forever`. AST: `STMT_LOOP` with `LoopKind`, `from`/`to`/`step` (NULL = 1)/`down`/`var` (default `"number"` at the verb's position, `var_named`)/`times`/`condition`/`list`/`body`.
- **`as` in count headers:** while parsing A, B and S, `Parser.as_ends_value` makes `parse_postfix` stop at `as`, so `as N` names the loop variable (even `as number`). Parentheses reset the flag (`parse_group`), so `(limit as a number)` converts. B and S stop before `and call` (the `and` rule), `by` and `in` (plain words).
- **Counting goes up only** unless it says `count down`; a count whose start and end are written numbers with the start above the end is a warning (`warn_never_counts` in check.c) suggesting `count down`.
- **`count` followed by `is`/`=`/`equals`/`be`** is "A sentence that starts with "count" is a counting loop…" with a `let count be` hint.
- **`stop`** (`parse_loop_control`): `stop program` (filler "the" dropped) is `STMT_STOP`; `stop loop` or bare `stop` is `STMT_BREAK`; `break` too. `skip [this one]`, `continue`, and `move on` are `STMT_CONTINUE`. Whether they're inside a loop is checked by the checker.
- `parse_loop` sets `ended_with_block` last, like `parse_if`.

### if / otherwise (implemented in `src/front/parse_if.c`)

- **Forms:** `if C:` NEWLINE INDENT block DEDENT, then any number of `otherwise if C:` blocks and at most one final `otherwise:` block. `else` is a synonym (`else if`, `else:`). One-line forms `if C, S` and `if C then S` take exactly one simple statement (not `if`/`otherwise`) and never have an `otherwise`. AST: `STMT_IF` with `Vec(IfBranch) branches` (`condition` NULL for the final `otherwise`, `body`, `pos` spanning the header up to its colon) and `one_line`.
- **Lining up:** after the if's DEDENT, an `otherwise` at the start of the next statement continues it (the lexer guarantees it's in the same column). Anything else starting with `otherwise`/`else` goes to `parse_orphan_otherwise`, which explains, in order: after a one-line if ("can't have an otherwise"), inside an open if's block (`p->open_ifs`, "doesn't line up with its if… The if on line N starts in column C"), or no if at all. A second plain `otherwise` is "already has an otherwise, on line N".
- **Header errors** (missing condition, missing colon/comma/then, text after the colon, nothing indented, broken condition) report once, then `parser_skip_line_and_block` skips the line and parses-and-discards an indented block; the rest of the chain is still consumed so it causes no extra errors. `parse_if` sets `ended_with_block` last, because statements inside its blocks reset it.
- **`unless`** (statement word, `parse_if` with `IfBranch.unless`): the same forms as `if` (block and one-line), its branch runs when C is no (`if (!(C))`; the checker narrows with the condition's opposite); an `otherwise` after it is "An "unless" can't have an "otherwise"." (`reject_unless_otherwise`, which still consumes the chain).
- **A condition after the sentence** (`parser_finish_condition_after`): `give back E if|unless C`, `return if C`, and `stop here [if|unless C]` (a `STMT_RETURN` with `Stmt.stop_here`, from `parse_loop_control`) become a one-line `STMT_IF` with `trailing` set holding the sentence; `stop here` outside a function is a checker error.
- **`:` or `,` right after an operator** (`if x plus:`) is "Something is missing after "plus"" (in `expected_value`).

### Lists (implemented in `src/front/parse_list.c`, `parse_expr.c`, `check_list.c`, `src/back/codegen_list.c`, `runtime/es_list.h`)

- **Values:** `list of A, B and C` (`EXPR_LIST`; items are `parse_join` values; commas separate items until the first `and`, after which only `and` does, so a one-line if's comma survives; an unparenthesized `list of` inside is "A list inside a list needs parentheses."), `empty list of KINDS` (`EXPR_EMPTY_LIST`, `list_type`), `item P of|in L`, `first item of|in L`, `last item of|in L` (`EXPR_ITEM` with `ItemWhere`; the list is a primary), `number of items in L` (`EXPR_LENGTH`), `copy of L`, `biggest of L`, `smallest of L`, postfix `L added together`, `L reversed` (inner lists copied, via `es_list_copy`), `L sorted [biggest|smallest first]` / `L sorted by their length [longest|shortest first]` (`LIST_SORTED*`, `es_list_sorted`: `es_list_copy` then `es_sort`; mismatched order words are the sort sentence's errors), and `L is empty` / `is not empty` / `isn't empty` (`EXPR_LIST_OP` with `ListOp`), `L contains X` / `does not contain` / `doesn't contain` (`BINARY_CONTAINS` / `BINARY_NOT_CONTAINS`).
- **Slices** (`EXPR_SLICE` with `SliceKind`, all new lists; `every other item of L` is `SLICE_EVERY` with step 2 and start 1, positions 1, 3, 5, while `every second item` starts at 2; `parser_at_every_nth` keeps `every other item in L` from being read as the map `every NAME in L`): `items A to B of|in L` and `items A to end of|in L` (`at_range`: `items` + a position + `to`, or arithmetic to report), `first N items of|in L` / `last N items ...` (`at_first_last`), postfix `L without first item` / `without last item` (`without_phrases` in parse_expr.c), postfix `L without item P` / `T without character P` (`SLICE_WITHOUT_AT`, `parser_parse_without_at`; `es_slice_without_at` / `es_text_without_at`, the list written first), and `every ORDINAL item of|in L` (`at_every_nth`: `second`...`tenth` or a `TOK_ORDINAL`; step 0 is "There's no item at position 0."). The checker needs a list ("I can only take items from a list") and numbers ("The number of items has to be a number" for counts). Runtime: `es_slice_range` (both positions via `es_index`; backwards is "I can't take items %zu to %zu: the first position is after the last one."), `es_slice_end` (negative or fractional counts are errors; more than the length gives everything), `es_slice_without` (empty is "There's no first item"), `es_slice_every` (positions step, 2·step, ...), all through `es_list_pick` (text retained, inner lists copied).
- **Positions** (`parse_position`): a number, a name (never a call: `item n of L`), `it`, or a primary (`(n plus 1)`, text). `parser_at_item(p, after)` decides whether `item`/`first`/`last` start the form: `item` + number/text/`(`, or `item` + a name + one of `after` or an arithmetic word; `first`/`last` + `item` + one of `after`. Otherwise they're names (`add item to total`). Arithmetic after a position is "A position worked out with arithmetic needs parentheses."; `item of` is "Something is missing after "item"".
- **`every NAME in L REST`** (`EXPR_EVERY`): `parse_every` parses the name and a primary L, sets `Parser.pending_item` to an `EXPR_NAME` for the item, and parses REST with `parse_or`, whose first primary is the item (`parse_unary`/`parse_not` skip their prefixes while it's pending, so `- 1` subtracts). **Filters** (`parse_filter` in parse_apply.c, the first postfix tried in `parser_parse_apply_postfix`): `L where C` and `L whose FIELD REST` (an `EXPR_ONLY`; for `whose`, REST is parsed by `parser_parse_condition_after` with `it's FIELD` pending, like `every`), `L that are ...` (`parser_parse_item_test`, shared with `only`), `L that pass F` (`APPLY_FILTER`); "\"whose\" needs a field after it, ..." when no kind has the field. `each NAME in L REST` is `every`. **`only L that are COMPARISON V`** (`EXPR_ONLY`): L is a primary; the condition is `BINARY(op, EXPR_IT, V)` from the `item_comparisons` table (`are` for `is`), or `are empty` / `are not empty` / `aren't empty`; `only` starts the form only before `NAME that` or `(`.
- **Kinds** (`parser_parse_kind` in parse_kind.c, shared with definitions): `number`, `text`, `yes or no`/`yes/no`, `nothing` (results only), `list of` + plural items `numbers`, `text`, `yes/no values`/`yes or no values`, `lists of ...`.
- **`for each K and its V in M:`** (`its_is_dropped` in parse_loop.c): `its` is skipped, and the value's name is V, when the program's tokens have `its V` only there; otherwise the name stays `its V`.
- **Sentences:** `add E to end of L` (`parser_finish_add_end` turns the STMT_CHANGE into STMT_LIST), `set item P of L to E`, `remove item P from L` (anything else after `remove` is "I expected "item" here"), `insert E at position P of L`, `sort L [by their length] [,] [smallest|biggest|shortest|longest first]` (length words need `by their length` and the other way round: two errors). `for each N in L:` is `LOOP_EACH` with `Stmt.loop.list` (parse_loop.c).
- **Checker** (`check_list.c`): `checker_require_list` unifies with "a list of" a fresh item variable ("<message>, but this is <kind>."); values put into a list unify with its items ("\"scores\" is a list of numbers, so it can't hold text." / "contain"); literal items unify with the first ("All the items of a list have to be the same kind: ..."). `sort`, `biggest of`, `smallest of` need numbers or text (by length: text or lists), `length of`/`is empty` text or a list (`DEFER_ONE_OF`). `added together` needs a list of numbers. `every`/`only` push a `Loop` whose `it` is the item; `every`'s name (and a for-each's) is made by `checker_make_item_name` ("You already made ...", note `each_NAME`), with `Symbol.loop_item` for the "is each item of the loop on line N" note. **`add E to X`** (STMT_CHANGE) where X is a list: if its items are numbers (or undecided) it's "\"scores\" is a list of numbers, so this could mean two things." with both phrasings; otherwise the checker sets `Stmt.change.append`. Fixed lists: see "Constants".
- **Codegen** (`codegen_list.c`): a list is `EsList *`; variables `es_vl<depth><n|t|b>_NAME`. Runtime functions with a per-item-kind suffix (`cg_item_suffix`: n/b/t/l): `es_list_from(ES_ITEMS_X, n, (CTYPE[]){...})`, `es_list_new`, `es_get_X(line, L, ES_AT|ES_FIRST|ES_LAST, P)`, `es_put_X`, `es_add_X`, `es_insert_X`, `es_remove`, `es_contains_X`, `es_extreme_n/t`, `es_list_sum`, `es_list_length`, `es_list_is_empty`, `es_text_is_empty`, `es_list_reversed`, `es_list_copy`, `es_list_same`, `es_list_text`, `es_sort(L, ES_SORT_*)`. Parts are worked out in source order (`cg_ordered`); reading list contents counts as an effect in `cg_has_effects` (a call could change the list). `for each` stores `es_list_snapshot(L)` in a hidden variable `0eachN` of the loop's scope (dropped like any variable) and assigns the item (retained) each round; `LoopCode.item` makes `it` the item. `every`/`only` become `static EsList *es_everyN/es_onlyN(EsList *es_list, captured...)` in `Codegen.helpers` (emitted after prototypes, before functions): the captured variables (`collect`: every variable name the body reads, minus constants, functions, and names bound by inner `every`s) are borrowed parameters (`Codegen.captured`); the helper snapshots the list only if the body can call a function.
- **Runtime** (`runtime/es_list.h`): `EsList {header, items, len, cap, at}` (in `es_memory.h`, which frees it and releases counted items), growing by doubling (`es_list_reserve`, counted against `ES_MEMORY_LIMIT` first; 1.5x was tried and dropped: on macOS realloc then moved the last big block with a deferred copy paid at the sort, +5 MB). Exact sizes when known (literals, slices, copies, `every`); `only` results are shrunk (`es_list_shrink`). A list with a count of 1 is reused: `es_list_keep` (slices) and `es_list_copy` work in place, with `es_list_own_deep` copying any inner list something else holds, so slices and copies still share no lists. Errors: "There's no item %s in the list: it has %zu item%s." / "it's empty." (hint "Positions start at 1: the first item is item 1." below 1), "The position of an item has to be a whole number, but it's %s.", "There's no %s item: the list is empty." (first/last/biggest/smallest), "I can't insert at position %s: the position has to be from 1 to %zu (the list has %zu item%s).". `es_list_snapshot` and `es_list_reversed` reuse a list nobody else holds. `es_list_copy` copies inner lists too. Sorting (`runtime/es_sort.h`): numbers are sorted in place by `ES_DEFINE_PDQSORT` (pdqsort: insertion sort below 24, median of 3 or of 9, partition-left for runs of equal items, a nearly-sorted check, heapsort after too many unbalanced partitions; comparisons `<`/`>`, exact, not `es_close`), with "not a number" moved to the end first because it breaks the order pdqsort needs. Text (`es_text_less`, bytes) and `(length, item)` pairs for `by their length` use `ES_DEFINE_SORT`, a stable bottom-up merge sort (insertion sort for runs of 32, an already-ordered check per merge). Both inline the comparison. `es_list_text` writes "72, 95 and 88", inner lists in parentheses, an empty list as empty text.
- **Joining:** `L followed by M` with two lists is `es_list_join(L, M)` (codegen picks it when the expression's type is a list): exactly `len(L) + len(M)` items, L reused when its count is 1 (`es_list_own_deep` first), text retained and inner lists copied (`es_list_append_copies`).
- **Sharing:** lists are references; `let b be a` shares, functions get the list itself, `a copy of` copies. A list can't contain a list of its own kind (the occurs check and kinds), so lists never form cycles.

### Maps (implemented in `src/front/parse_map.c`, `check_map.c`, `src/back/codegen_map.c`, `runtime/es_map.h`)

- **Values:** `map of K to V, K to V and K to V` (`EXPR_MAP`, `items` holding key, value, key, value...; keys and values are `parse_join` values; commas separate entries until the first `and`, as in a list; an unparenthesized `list of`/`map of` inside is "A list/map inside a map needs parentheses."), `empty map from KEYS to VALUES` (`EXPR_EMPTY_MAP`, `list_type`), `value for K in M [, or D]` (`EXPR_MAP_GET {key, map, fallback}`; `parser_at_lookup`: `value` + `for`, unless `value` is a function; the span (and column) starts at a dropped "the" (`Token.filler`); K is `parse_join`, except that a name straight before `in` is the key (`parse_key`), so `the value for item in prices` isn't an item form; M is a primary; D is a unary value, and arithmetic straight after an unparenthesized D is "... could mean two things." with both parenthesized forms), `keys of M` / `values of M` / `number of entries in M` (`EXPR_LIST_OP` with `LIST_KEYS`/`LIST_VALUES`/`LIST_ENTRIES`; M a primary), `M has K` / `does not have` / `doesn't have` (`BINARY_HAS`/`BINARY_NOT_HAS`, a comparison), and `is empty`, `a copy of`, `is` (equal maps: the same keys with equal values, in any order).
- **Sentences:** `set the value for K in M to E` and `add/subtract/increase/... the value for K in M` (targets through `parser_parse_target`; `, or` on a target is "A value that changes can't have ", or"."), `add E to the end of the value for K in M` (a list value), `M without K` (postfix `without` + a unary value after every other `without` form: `EXPR_MAP_WITHOUT`, reusing `as.lookup`; `es_map_without(site, M, K)` copies like `a copy of`, then takes K out, "I can't leave out ..."), `remove K from M` (`parse_remove_key`; `remove item from M` stays the list form's missing-position error; `remove from M` is "Something is missing after "remove"."), `for each K and V in M:` (`Stmt.loop.pair`, `value_name`; `it` is the key; the pre-scan records both names).
- **Kinds** (`parser_parse_map_kind`, from `parser_parse_kind` and `parser_parse_items_kind`): `map from KEYS to VALUES` (`maps from ...` in the plural), KEYS `text` or `numbers` ("I expected "text" or "numbers" here, but found ..."), VALUES in the plural like a list's items. `Type`: `TYPE_MAP` (1<<13) + the index of a `MapKind {key, value}` in `Records.maps` (`ast_map_type` adds a kind the first time it's used; `maps[0]` is "a map" with its kinds undecided, so `TYPE_MAP` alone is that), `type_is_map`, `ast_map_key`/`ast_map_value`, `ast_type_undecided` (looks inside maps); record kinds stay below `TYPE_MAP`. `Records` (a `Vec(RecordKind)`'s fields plus `maps`) is mutable in the parser and checker (`check_program` takes a `Program *`).
- **Checker** (`check_map.c`): a map's type variable is a `TypeSlot` of type `TYPE_MAP` with `key` and `item` (the values) variables (`types_new_map`, `types_key`; `types_of` interns the kind; the occurs check, `compatible` and `join` go through both). `checker_require_map(var, at, message, list_note, &key, &value)` ("I can only look up a value in a map, but this is a list of numbers." plus a note showing the list form); keys unify with the map's ("The keys of "ages" are text, but this is a number.") and then must be text or numbers (`DEFER_ONE_OF`, "A map's keys have to be text or numbers"); values put in unify ("\"ages\" is a map from text to numbers, so it can't hold text."); the fallback unifies with the values; literal keys and values unify with the first ("All the keys/values of a map have to be the same kind: ..."); a key written out twice is "The key "tea" is in this map twice." (numbers compared to 12 significant digits, `const_key_text`). `checker_check_each` (a map needs two names, a list one, each with its own message), `checker_check_remove_key`, `checker_check_map_set`/`checker_check_map_change` (a constant's map: `checker_reject_fixed`), `checker_check_has`, `checker_check_map_op`. `length of` a map and `contains` on one get notes pointing to `the number of entries in` and `has`. `add 5 to the value for K in M` with a list of numbers is "This value is a list of numbers, so this could mean two things.".
- **Constants:** `keep NAME as a map of ...` / `an empty map from ...` make `ConstValue {kind CONST_MAP, len, keys, items (the values), key_type, value_type}` in `consteval.c` (keys text or numbers, each once; values numbers, text or yes/no of one kind; "A fixed map can't hold lists or maps, because those could change."); `the number of entries in` a fixed map folds; anything else worked out from a map is "A constant can't work things out from a map." (`reject_map`: lookups, `has`, `contains`, `keys of`, operators). `const_eval` takes the `Records`. `checker_const_type` gives a constant's kind (adding the kind of map). Fields can start at a fixed map or an empty map (copied for each record). Codegen: `static EsMap *es_k_NAME;`, made at the start of `main()` (`Codegen.inits`) as `es_map_fix(es_map_from(...))`; reading the name gives `es_map_copy(es_k_NAME)`, except where it's only looked at (`cg_list_operand` gives `es_k_NAME`).
- **Codegen** (`codegen_map.c`): a map is `EsMap *`; variables `es_vh<kind>_NAME` (lists of maps `es_vl1h<kind>_`); keys are passed as `(EsValue){.t = K}` / `{.n = K}`; values go through one runtime function per kind (`cg_value_suffix`: n/b/t/l/r/m): `es_map_from(KEYS, VALUES, n, (EsValue[]){...})`, `es_map_new(KEYS, VALUES, 0)`, `es_map_get_X(site, M, K)`, `(es_map_lookup_X(M, K, &es_tN) ? es_tN : D)` (D worked out only when the key is missing), `es_map_put_X(M, K, V)`, `es_map_has`, `es_map_remove(site, M, K)`, `es_map_length`, `es_map_is_empty`, `es_map_list(M, keys?)`, `es_map_copy`, `es_map_same`, `es_map_text`. A change is one C block that works out its parts in written order, then `EsValue *es_p = es_map_at(site, es_m, es_k)` (after the amount, which could change the map) and changes `es_p->n` (or `es_add_X(es_list_retain(es_p->l), ...)`). Parts are worked out in written order (`cg_ordered`); a lookup counts as an effect. `for each K and V in M` keeps `es_map_snapshot(M)` in a hidden variable and goes over `entries[0..used)`, skipping removed ones (hash 0). Frames mark maps 'm' (left out of the call chain, like lists); record fields that hold maps are 'm'.
- **Runtime** (`runtime/es_map.h`, the eighth part): `EsMap {header, keys, values (EsItems), len, used, cap, entries (EsEntry {hash, key, value}), index (uint32_t places: 0 empty, ES_GONE removed, else 1 + the entry), slots (a power of two), filled}` (in `es_memory.h`, which frees it). Insertion order: entries stay in the order added; setting an existing key keeps its place; a removed entry keeps its place with hash 0 until the entries are packed (when they're full and a quarter are removed, or when the index is rebuilt). Maps of up to `ES_MAP_SMALL` (8) entries have no index (a scan comparing hashes); bigger ones rebuild the index (`es_map_reindex`: at least 16 places, more than twice the entries) when more than two thirds of it is filled, with linear probing. Hashes: `es_mix` (the splitmix64 finalizer, never 0) of the text's bytes 8 at a time, or of a number key's bits. Number keys are kept as `es_key_number(x)` (whole numbers up to 2^53 exactly, others rounded through `%.12g`, close to `is`'s 1e-12; -0 is 0; NaN is one key), so numbers that differ only by rounding errors are the same key (printing rounds further, to 10 digits). Errors: "There's no value for "Bob" in the map." (the key cut at 60 characters; a hint about `has` and `, or`; a change says "It has to be in the map before it can change. ..." instead), "I can't remove "Bob": the map has no value for it.". Lists of maps (`ES_ITEMS_MAP`) and maps of lists or maps copy their inner lists and maps with them (`es_items_copied`, `es_copy_inner`, `es_map_own_deep`), like lists of lists; records and text are shared. `es_map_fix` makes a map immortal and takes it out of the live counts (fixed maps). Printing: `"Paris" is 19 and "Junie" is 24` (text quoted; lists, maps and records in parentheses, `(an empty list)`/`(an empty map)`); an empty map prints as empty text. The record cycle check (`es_each_inner_value`) follows maps.

### Text (implemented in `src/front/parse_text.c`, `parse_list.c`, `check_text.c`, `src/back/codegen_text.c`, `runtime/es_text.h`)

- **A character is a Unicode code point stored as UTF-8** (every byte that isn't a UTF-8 continuation byte starts one), so `"café"` has 4. `EsText.count` caches the character count (0 = not worked out; codegen writes it into literals); text with `count == len` is ASCII and handled byte by byte. Single ASCII characters are 128 static immortal texts (`es_ascii_text`).
- **Characters and pieces reuse the list forms** in `parse_list.c` through a `Noun` (`item`/`items` or `character`/`characters`): `character P of|in T`, `first|last character of T`, `characters A to B|to the end of T`, `first|last N characters of T`, `every other|second|3rd character of T`, postfix `without the first|last character` (`without_phrases` with a `WITHOUT_CHARACTER` flag), plus `the number of characters in T` (`EXPR_LENGTH`). They're `EXPR_ITEM`/`EXPR_SLICE` with `characters` set; the checker (`checker_check_characters`) requires text, codegen calls `es_char_at`/`es_text_range`/`es_text_end`/`es_text_without`/`es_text_every`, and the runtime errors mirror the list ones with "character" (`es_char_index`). A list form on text (or a character form on a list) gets a note showing the other form.
- **`EXPR_TEXT_OP`** (`TextOp`, with `operand`, `arg`, `arg2`, `negated`): prefixes `the characters of T`, `the words of T`, `the lines of T`, `the code of T`, `the character with code N`, `the position of X in T` (single values, like `length of`); postfixes `T in uppercase|lowercase` (matched as whole phrases only, so `count ... to n in steps of 2` keeps its `in`), `T without extra spaces`, `T split by X`, `L joined with X`, `T with X replaced by Y` (`parser_at_replace`: `with` + a single value + `replaced`; after a name that isn't a known function this beats the call reading); `C is [not] a letter|digit|space` / `isn't a ...` only when the word carries a dropped `a` (`Token.filler`), so `x is letter` compares with a variable `letter`.
- **Searching:** `contains` works on text or lists and `the position of X in T|L` too: both are `DEFER_SEARCH` (`checker_settle_search`): text needs text ("I can only look for text in text"), a list unifies X with its items, an unknown container with a non-text X becomes a list of it, and an undecided one is suggested as `(text)`. `starts with` / `ends with` need text on both sides. Position is 1-based, 1 for empty text, and **`a number or nothing`** (`TYPE_MAYBE + TYPE_NUMBER`): the runtime's `es_text_position`/`es_position_n/b/t/l/r/m` give 0 when not found, and codegen wraps them in `es_found` (NULL for 0, else a box).
- **Semantics:** words split at runs of space/tab/CR/LF/FF/VT; lines split at `\n` (a `\r` before it dropped; no extra line for a final `\n`; empty text has none); `split by` keeps empty pieces, empty text gives an empty list, an empty separator is a runtime error; `joined with` takes a list of numbers, text or yes/no; trim takes spaces off both ends; replace is left to right, non-overlapping (empty text to replace is an error); case and letters cover ASCII, Latin-1, Latin Extended-A, Greek and Cyrillic (`es_upper`/`es_lower`/`es_letter_code`); digits are 0-9; `is a ...` is yes only for exactly one character; codes are 1..1114111 without surrogates.
- **Constants:** any text tool (or character form, `contains` on text, `starts with`) in a `keep` is "A constant can't take text apart or look inside it." (consteval).
- **In-place building:** `set T to T followed by|and A ...` where only the leftmost part reads T (`reads` in codegen_text.c) becomes one `es_append(&T, A)` per part; `es_append` grows text whose count is 1 by doubling `EsText.cap` (realloc, counted against the memory limit) and otherwise joins as before.
- **`as a number`** errors: empty text is "I can't turn empty text into a number.", long text is cut at 60 characters with "...", and both have a hint; consteval matches.

### Records (implemented in `src/front/parse_record.c`, `check_record.c`, `src/back/codegen_record.c`, `runtime/es_record.h`)

- **`has` definitions:** `NAME has FIELD [(KIND | KIND, starting at E | starting at E)] [, | and] ...` at a line start (`parser_has_definition_words` in parse_names.c: the first word can't start sentences or be `otherwise`/`else`/`when`; the pre-scan adds the kind and its field names, `find_has_fields`; `parser_parse_has` in parse_record.c; a leading `some` is dropped from a field's name). `Stmt.record.has` is set. A field without a kind has `TYPE_UNKNOWN`: its kind comes from a starting value (`check_default`) or from use (`checker_field_kind`: one variable per field in `Checker.field_kinds`, written back through `slots`; `checker_report_undecided_fields` in `types_finish`, only without other errors).
- **Definitions:** `NAME is a kind of thing with:` at a line start, then one field per sentence, indented: `NAME, which is KIND [or nothing] [, starting at E].` (`parse_record`; errors for a missing comma, `which is`, kind, colon, fields on the header line, over-indented fields, extra words). The pre-scan (`find_records` in parse_names.c, run first) finds every kind (in order: its index makes `TYPE_RECORD + index`) and every field name (`NAME, which is` at a line start, in `Parser.fields`), and adds kind names as known names (a method's input). AST: `STMT_RECORD {name, index, fields}`, `Field {name, type, initial, pos, folded}`; `Program {body, records}` (`Records` = `Vec(RecordKind {name, display, plural, definition})`); `ast_type_name(arena, records, type)` names kinds ("a dog", "a dog or nothing", "a list of dogs"; plural: `s`, `es` after s/x/z/ch/sh, `ies` after consonant+y).
- **Kinds:** `parser_parse_kind` accepts a record kind (`dog` after the dropped `a`), plural in list kinds, and `or nothing` after any kind but a list or map (`type_can_be_nothing`; "A list can't be "or nothing"." / "A map ..." with a note about empty ones). `Type`: `TYPE_RECORD` (64) + index, `TYPE_MAYBE` (1<<14) added for "or nothing" (alone: a record or nothing, kind undecided), `TYPE_LIST` is 1<<15. Helpers `type_is_record`, `type_is_maybe` (a concrete one), `type_present`, `type_record`, `type_record_index`; `type_counted` includes records.
- **Values:** `new NAME [with FIELD V (and|,) ...]` (`parser_parse_new`; `new` + a known kind; values are `parse_join`; field names the longest known; a `new` with fields inside another needs parentheses; its span starts at a dropped "a"). `R's FIELD` (`EXPR_FIELD {record, name, index}`), `EXPR_NEW {type, values (FieldValue {field, value, index})}`. `the FIELD of R` (`parse_field_of` in parse_value.c, tried last in `parse_word`, so built-in phrases win; R is a primary; also a target) is the same `EXPR_FIELD`; a function with the field's name makes it "\"size of rex\" could mean two things.". Targets: `parser_parse_target` (`set`, `add ... to`, `increase ... by` ...) takes a name, `it's`, or `(X)'s` plus fields (`Stmt.assign.field` / `change.field`). `let X's ...` is an error.
- **Methods:** `KIND can NAME [with INPUTS] [, giving back K]:` at a line start (`parser_at_can_method`/`parser_parse_can` in parse_func.c, `Stmt.function.can`; the pre-scan calls `find_function(p, i, true)` at `can`; `parse_record_input` makes the record input for both forms; messages show the header as written), or `to NAME [,] for KIND [[,] with INPUTS] ...:`. "for" ends a function's name only before a known kind (`at_method_for`; pre-scan the same), so "print receipt for" can still be a name. The record is input 0, named like its kind (`Stmt.function.method`). Calls (`parser_parse_method_args`): `NAME [for] R [and ... | with/using/of/the definition's to/from/in ...]`, as sentences and values (`KnownName.method`; `Parser.method_record` stops `rex with` being read as a call).
- **Methods sharing a name:** methods for different kinds of record can share a name (`reject_duplicate` in check.c; same kind twice, or a plain function, is an error). A call of a shared name (`checker_shared_method`) picks the method by its first input's kind: at once when it's known, otherwise `DEFER_METHOD` (`Deferred.args` holds the inputs; settled in `checker_settle_method`, unsettled ones reported by `checker_report_unsettled_method` before undecided inputs). The checker sets `call.target` on every call (codegen calls it) and `function.overload` (1 + the kind's index) on shared methods, whose C names get `_0rN` (`cg_append_function`).
- **Checker:** `checker_collect_records` (defined twice), `checker_check_record` (pass 1, after constants: top level only, fields twice, starting values via `const_eval` with only constants or an empty list, a field that always holds its own kind (directly or through others) is an error). `checker_check_new` (unknown fields with a suggestion, given twice, kinds, missing fields listed). `checker_check_field`: a known record kind; an undecided base takes the only kind with that field, else waits (`DEFER_FIELD`). Records compare by identity (`is`), can be copied (`LIST_COPY` when known to be a record), and in lists use identity for `contains`/`position`.
- **Nothing:** `checker_check_value` gives `nothing` the kind `TYPE_NOTHING` where a value may be nothing (set, new, call inputs, give back), and `checker_fits` lets a record go where a record or nothing is kept (otherwise unify). `X is [not] nothing` (`checker_check_nothing_test`) needs a record or nothing (`TYPE_MAYBE` if undecided). **Narrowing:** `Checker.present` holds paths (`checker_path`: a name, or name's field...) checked not to be nothing (`checker_narrow_condition`: `is not nothing` when true, `is nothing` when false, `and`/`or`/`not`), added for if branches (and later branches), while/until bodies, the right side of `and`/`or`, and after a one-branch `if` whose body ends with give back/stop/break/skip. `checker_narrow` makes a checked name or field its record (`Expr.narrowed`; `DEFER_PRESENT` when the kind isn't decided). Setting a path kills it and everything under it; a loop body that sets a path kills it before the body (`checker_kill_set_in`). `Checker.unnarrowed` checks an expression as written (`x is nothing`, a field being set). Unchecked use: "\"node's next\" could be nothing, so check it first.".
- **Codegen** (`codegen_record.c`): per kind `typedef struct {EsRecord base; ... fN;} es_RN`, `es_rnN` (field names), `es_roN` (offsets), `EsRecordType es_rtN {"a dog", n, names, kinds "ntblr", offsets, size}`, `es_newN(fields...)`, and `es_k_0dN_F` for list starting values (copied per record). A variable is `EsRecord *` (`es_vrN_x`, `es_vmN_x` for or-nothing; lists `es_vl1rN_`), NULL for nothing. Field reads: `((es_RN *)var)->fF` (retained if counted) for a plain variable, else `es_field_X(R, offsetof(...))`. Field sentences are one C block (`cg_field_stmt`; the amount first when written first). A narrowed expression is wrapped in `es_present(site, ...)`. `nothing` is `NULL`; `es_is_nothing`, `es_record_same`, `es_record_copy`, `es_record_text`. A narrowed name reads its or-nothing variable. Inputs that are records are retained by the frame (`.r`) like text.
- **Runtime:** `EsRecord {header, type, prev, next, mark}` (in es_memory.h), NULL-safe `es_record_retain/release/set/drop`, `es_record_new`. Freeing is iterative: `es_free_object` frees text at once and lists/records through `es_dying`. Lists hold records as `ES_ITEMS_RECORD` (`at.r`, items may be NULL), shared by copies and slices. Printing: `a dog with name "Rex" and age 3`, text quoted, lists and records in parentheses (`ES_RECORD_DEPTH` 3 levels, then "a node with ..."; in lists records are parenthesized). Stack traces show record inputs (`es_record_short_text`, cut at 60 characters). With `ES_DEBUG_MEMORY`, live records are linked (`es_memory.records`) and `es_finish` calls `es_report_cycles` (trial deletion; lists counted only when held once) to explain records alive in a circle (exit 70).

### Kinds with variants (implemented in `src/front/parse_kind.c`, `parse_match.c`, `check_kind.c`, `check_narrow.c`, `src/back/codegen_kind.c`, `runtime/es_kind.h`)

- **Definitions:** `NAME is one of:` at a line start, variants indented one per sentence: `VARIANT [with FIELD (KIND) [and | ,] FIELD (KIND) ...]` (`parse_sum`; errors for a missing kind in parentheses, a missing `)`, extra words, variants on the header line, over-indented lines). The pre-scan (`find_records` in parse_names.c) adds kinds to `Records.sums` (a `RecordKind` whose definition is a `STMT_SUM`), variants to `Records.variants` (`VariantKind {name, display, sum, index}`, numbered across the program, so a variant's name says its kind), and field names to `Parser.fields`. AST: `STMT_SUM {name, index, variants (VariantDef {name, id, fields, pos})}`. `Type`: `TYPE_SUM` (1<<12) + index (`type_is_sum`, `type_sum`, `type_sum_index`; record kinds stay below it); `TYPE_MAYBE` can be added (`a shape or nothing`). `parser_match_kind_name` (records and sums, longest) is used for kinds, methods (`to describe, for a shape:`) and the pre-scan.
- **`NAME is made of FIELD (KIND) [and | ,] ...`** (`parser_made_of_words` in parse_names.c adds the kind and a variant of the same name; `parser_parse_made_of` in parse_kind.c makes a `STMT_SUM` with `made_of` and one `VariantDef`): `check_variant_names` lets the variant share its kind's name, and `checker_sum_field` takes the only variant without a check (unless the value could be nothing).
- **Values:** `a new VARIANT [with ...]` (`parser_parse_new`: `EXPR_NEW` with `type` the sum and `variant` the id); `make a circle ...` is a parse error pointing to `new`. `S is [not] VARIANT` / `isn't` (`EXPR_KIND_TEST`, `parser_parse_kind_test`, only with a dropped `a`/`an`); `its FIELD` (only before a known field name) is `it's FIELD`. Values never change (`set s's radius` is "The fields of a shape can't change.", via `Checker.setting_field`), are equal by value, and `a copy of` copies their lists and maps.
- **`check which kind S is:`** (`parse_match`, statement word `check`; `STMT_MATCH {subject, branches (MatchBranch {variants, nothing, otherwise, body, pos})}`): `when it's [a] V [or [a] V ...] [or nothing]:` (or `when it is`) blocks, then at most one final `otherwise:`/`else:`. The subject is a `parse_join` value up to `is`.
- **Checker** (`check_kind.c`): `checker_collect_sums` (kinds and variants named twice or like a record kind), `checker_check_sum` (top level only, fields twice, `ever_made`: a fixpoint that every kind has a variant whose fields don't all need unmakeable kinds), `checker_check_new_variant`, `checker_sum_field` (a field needs the record expression checked to be a variant that has it: `checker_narrowed_variant`, from `Narrowing.variant` for paths or the innermost `Loop` with `subject` for `it`; errors suggest `if s is a circle:` and `check which kind`), `checker_check_kind_test` (an undecided operand becomes the variant's kind), `checker_check_match` (the subject is checked unnarrowed; its kind comes from the first variant named if undecided; every variant needs a `when` unless there's an `otherwise`, "This doesn't say what to do when s is a rectangle or a point."; an `otherwise` that can never run is a **warning**). Each branch pushes a `Loop {has_it, it, subject, variant}` (`it` is the subject, its present kind where it can't be nothing) and narrows the subject's path; `stop the loop` looks past these. Narrowing (`check_narrow.c`): `checker_add_narrowing(path, variant)`; `if s is a circle` (and `and`, `not`, `otherwise`, early exits) and `let`/`set s to a new circle ...` narrow to the variant.
- **Codegen** (`codegen_kind.c`): a value is an `EsRecord *` (`type_is_object`: records, sums and maybes share all record plumbing: C type, retain/release, `ES_ITEMS_RECORD`, map values `r`, field kind `r`, frames). Per variant id: `typedef struct {EsRecord base; ...} es_WN`, `es_wnN`/`es_woN`, `EsRecordType es_wtN {..., ES_VARIANT}`, `es_makeN(fields)` (missing maybe fields are `NULL`). Fields: `es_vfield_X(site, R, &es_wtN, offsetof(es_WN, fF))` (checks the variant again). `S is a circle`: `es_is_variant(S, &es_wtN)`. `check which kind`: a block with the subject in a hidden variable `0matchN` (declared in its scope, so `stop the loop`/`give back` drop it), then an `if`/`else if` chain on `->type` (not a C `switch`, so `break` leaves the loop around it); `LoopCode` with `stmt` the match makes `it` that variable; `cg_innermost_loop` skips them. Variables: `es_vkN_` (kind N), `es_vqN_` (kind N or nothing).
- **Runtime** (`runtime/es_kind.h`, the ninth part): `es_vfield_X`, `es_wrong_variant` ("This was checked to be a circle, but something has set it to a point since then."), `es_is_variant`, `es_record_equal` (identity for records, fields for `ES_VARIANT`; declared in es_list.h and used by list and map equality, `contains`, `the position of`, `es_record_same`), `es_kind_copy`. `EsRecordType.style` is `ES_RECORD` or `ES_VARIANT`. The cycle check says "values" and suggests taking one out of its list or map when variants are in the circle.
- **"Or nothing" for numbers, text and yes/no** (`check_narrow.c`, `es_kind.h`): `TYPE_MAYBE` + a number, text or yes/no (`type_boxed`) is kept in a box, an `EsRecord` of style `ES_BOX` (`EsBoxN/T/B`, `es_box_type_n/t/b`; NULL is nothing), so it uses the record plumbing (C type `EsRecord *`, variables `es_von_`/`es_vot_`/`es_vob_`). `checker_fits(c, target, value, expr, line)` lets a present value go where its "or nothing" is kept and marks the expression `lifted`; `cg_emit_expr` wraps lifted boxed values in `es_box_X(...)` (`cg_value_type` gives the C kind, for temporaries) and narrowed ones in `es_unbox_X(site, ...)` (records and kind values in `es_present`); `it` in a `when` unboxes too, and a narrowed field read uses the kind as kept. `checker_note_maybe` adds "It could be nothing. Check it first, like "if at is not nothing:"." after kind mistakes (`checker_require`, comparisons, arithmetic). Boxes print as their value (text quoted inside records and maps), compare by value, and aren't copied. `check which kind X is:` on one needs `otherwise:` for the value ("This doesn't say what to do when at isn't nothing."). Lists of maybes come only from inference; `ask`/`read file` can't store into one.
- **Warnings** (`diag_warning`, kept apart from errors; `diag_count` counts errors only): printed by the driver as "Line N (a warning): ..." before the program runs when there are no errors; the shell sets `ES_WARN_FROM_LINE` so lines already shown don't warn again. `tests/warnings/NAME.es` + `.out` + `.err` (run, exit 0, stderr is the warnings).

### Functions as values (implemented in `src/front/parse_func_value.c`, `check_func_value.c`, `src/back/codegen_closure.c`, `runtime/es_closure.h`)

- **Values:** `the function NAME` (`EXPR_FUNCTION_REF {name, target}`; `function` + a known function name), `a function [taking P [(KIND)] [and Q ...]] that gives back E` and the block form `a function [taking ...] [[,] giving back KIND]:` + indented block (`EXPR_LAMBDA`, `as.lambda` a `STMT_FUNCTION` with `lambda` set, name `0lN` (`Parser.lambdas`), display "the function made on line N"; the one-line body is a `STMT_RETURN`). A value ending in a block ends its sentence: the lambda sets `ended_with_block` and `Parser.block_end` (`parser_at_sentence_end` is true there; reset by `parse_statement`). A broken sentence ending in a colon skips its block (`end_statement`).
- **Calls:** `call F [with|of|using A and B]` for any primary F (`parser_parse_called`, parsing F with `Parser.no_call` so `handler with 3` isn't read as a call of handler; `EXPR_CALL.callee`, or `name` when F is a name), as a sentence or a value (`parser_at_call_value`); `f with 3` in a value is an ordinary call whose name the checker finds is a variable (it then sets `callee` to an `EXPR_NAME`).
- **Kinds:** `function [taking K [and K ...]] [[and | ,] giving back K]` (`parse_function_kind` in parse_kind.c; inputs that are functions in parentheses), `functions ...` in list and map kinds; `TYPE_FUNC + n` (`Records.funcs`, `FuncKind {params, count, result}`, interned by `ast_func_type`; `funcs[0]` undecided), `type_is_func`; names "a function taking a number and giving back text". A function can't be "or nothing". Inference: a `TypeSlot` of type `TYPE_FUNC` with `params`/`count` and `item` the result (`types_new_func`, `types_func`; unify pairwise).
- **Checker** (`check_func_value.c`): `checker_check_function_ref` (shared methods are an error), `checker_check_lambda` (a `Function` in `Checker.lambdas`; body checked with the names around it visible, loops and narrowings hidden, inside a `LambdaScope {definition, scope, outer, in_loop}`; inputs can't reuse names around it; not inside `every`/`only` (`Loop.helper`)), `checker_check_value_call` (an undecided callee becomes a function of that many inputs; wrong count/kind with the function's kind as a note; a value use of an undecided result is `DEFER_ONE_OF` with `KIND_OTHER`). **Captures:** `checker_use(c, symbol, setting)` (from names, set targets, ask/read into an existing name) adds the name to each enclosing lambda made after it (`Capture {name, type, var}` in `function.captures`) and to its owner's `cells` (`Symbol.owner`: the function or lambda that made it; `Program.cells` for main); setting it from a lambda records `Symbol.set_inside`, and a later narrowing of it is an error (`checker_reject_set_inside`). Undecided lambda inputs are reported (inputs first, then results), and kinds written back (`checker_write_lambdas`) at the end of `types_finish`.
- **Codegen** (`codegen_closure.c`): a name in `Codegen.cells` (owned: declared `EsRecord *es_cvn_x = NULL`, dropped like a variable) or `Codegen.borrowed` (a lambda's captures, read from `((es_L0l1 *)es_self)->cK` at entry) is read and written through `ES_CELL(es_cvn_x, double)` (`cg_append_var` is cell-aware, `cg_append_raw_var` isn't); `let`, a count's number and a for-each item make a new cell each time (`cg_append_assign(..., make)`); captured inputs are put in cells at entry. A lambda is `static RESULT es_f_0lN(int es_call, EsRecord *es_self, ...)` (emitted by `cg_emit_function` into `ClosurePool.code`, with its struct `es_L0lN`, `EsRecordType es_lt0lN` and maker `es_mk0lN` in `ClosurePool.head`); one with no captures is a static immortal `es_lv0lN`. `the function NAME` is a static immortal closure `es_fv_NAME` around a wrapper `es_w_NAME`. A call through a value is `ES_CODE(F, RESULT (*)(int, EsRecord *, ...))(site, F, args)`, holding F in a temporary (released after) unless F is a variable that isn't a cell. Text in a cell is never built in place.
- **Built-ins that take a function** (`parse_apply.c`, `check_apply.c`, `codegen_apply.c`): values `F applied to every X in|of L` (postfix, `APPLY_MAP`), `the Xs in L where C` (`EXPR_ONLY` with any condition on `it`), `the Xs in L that pass|passes F` (`APPLY_FILTER`), `L combined using F [, starting from S]` (postfix, or after `the Xs in L`; `APPLY_COMBINE`), `L sorted by F [biggest|smallest first]` (postfix, not before `their`; `APPLY_SORT`): `EXPR_APPLY {kind, function, list, start, descending}`. `parser_at_selection` (name words, `in`, then `where`/`that pass`/`combined using` at depth 0 before the sentence end) is checked first in `parse_word`. Sentences `apply F to every X in L`, `keep only the Xs in L where C | that pass F` (`keep` + `only`, unless `only as|at`), `sort L by F [, biggest first]` are `STMT_LIST` (`LIST_APPLY`/`LIST_KEEP`/`LIST_SORT_BY`) whose `value` is the value form read through `list.hidden` (an `EXPR_NAME` "0listN", `Parser.hidden_lists`); the checker makes that name for the value (`checker_check_replace`), the new items must be the list's kind, and codegen does `es_list_set(&hidden, L), es_list_replace(es_list_retain(hidden), VALUE)`. The item words are decorative (`it` is the item). F is parsed with `no_call`; a function's name there becomes `EXPR_FUNCTION_REF` in the checker. Kinds: F takes the item (and, combining, what's combined so far: the start's kind, or the item's) and gives back a new kind (map, not nothing), yes/no (filter), the so-far kind (combine), or numbers/text (sort): "This has to be a function taking a number, but it's ...". Codegen: one helper per use in the helper pool (`es_mapN`, `es_filterN`, `es_combineN`, `es_sortbyN`), calling a `to` function directly and a value through `ES_CODE`; a closure with captures gets `es_list_snapshot` first; sorting sorts a copy by keys (`es_sort_by_keys`, stable, "not a number" last). Combining an empty list with no start is "There's nothing to combine: the list is empty.".
- **Runtime** (`runtime/es_closure.h`, the tenth part): `EsClosure {EsRecord base; EsCode code}` (style `ES_CLOSURE`, fields the cells), cells (style `ES_CELL`, `es_cell_n/b/t/l/r/m`, `ES_CELL`), `es_report_function_cycle`, and for the built-ins `es_list_replace` and `es_sort_by_keys`. Closures print as their type's name ("the function double"), without parentheses in lists, records and maps, compare by identity, and `es_record_retain` skips immortal ones.

### Talking to it (implemented in `src/front/parse_question.c`, `parse_chain.c`, `parse_table_file.c`, `runtime/es_csv.h`)

- **Questions:** the lexer reads `?` as a `TOK_PERIOD` whose text is "?". `parser_question_ahead` (the sentence ends with it) and no sentence form at the start send it to `parser_parse_question`: `what is|are|'s X` / `X` (a `STMT_SAY` of pieces), `is|are X REST` (`parser_parse_is_rest`, which also takes describing words), `which ITEM has|with the highest ...`, `which Ls TEST`; `who`/`where`/`when`/`why` are an error. Requests: `show|tell me X`, `list X` (forms), `give me X` (in `parse_return`). `parser_skip_polite` (`I want to`, `I'd like to`, `I would like to`, `can|could|would you`, `please`, `let's`) and `parser_skip_step_words` (`first`, `next`, `after that`, `finally`, `then`, not before a known name of several words) run at every sentence start. `me` and `undo` are operator words.
- **Steps** (`parser_parse_actions`, parse_chain.c): sentences joined by `link_words` (`parser_at_next_action`, or `,` + `then`/`and then`/`after that`/`next`/`finally`; `parser_at_step_link` ends pieces, lists and maps). After each step `step_result` (a let's name, a sentence's list, file or table) is kept in a hidden `let 0stepN` inserted before the next step only if it says `it` (`Parser.chain_used`); `it` there is an `EXPR_IT` whose `display` is the hidden name (`parser_chain_it`; "" when the step before gives nothing), resolved by `check_step_it` in check_expr.c (an error when any loop's `it` is around).
- **Actions:** `total|average|median FIELD [of L] [per G]` and `count L` (`parser_at_action`: not a function, not a known name of several words, `count` not before `from`/`to`/...) are a `STMT_LET` of an aggregate (L defaults to the step's `it`), named by `and call it|called|named NAME` or hidden.
- **Tables** (parse_table_file.c): `read [the] table in F [and call it NAME | , called NAME]` is `STMT_LIBRARY DO_READ_TABLE`; the pre-scan (`parser_find_table_files`) makes a record kind per sentence (`RecordKind.table`, name `0rowN`, display "row of sales.csv") with hidden fields `0header` and `0cells` (lists of text); `parser_field_words` lets any name word be a field in a program that reads a table; the checker adds a field the first time one is read (`checker_add_column`, which moves `field_kinds` and `slots` if the fields move), defaults undecided columns to text before `types_finish`, and `per month` uses or adds the `date` column. Runtime `es_read_table` (columns matched without caring about capitals, `_` for a space; "sales.csv has no column called "amout"." with a closest-column hint; cells read as numbers, yes/no or dates `2026-10-31 [14:05]`), `es_table_render` (every column, used ones with their values), `es_save_records` (every column for tables) and `es_save_map` (`key`,`value`); `save X as F` is `save X as csv file F`.

### Interfaces (implemented in `src/front/parse_iface.c`, `check_iface.c`, `src/back/codegen_iface.c`)

- **Definitions:** `NAME is anything with:` at a line start (NAME is every word before it, stop words too: `parser_interface_words`), ways indented: `way to NAME [with|of|... INPUT (KIND) [and|,] ...] [[,] giving back KIND].` (`Way {name, intro, params, declared, result, pos}`; input kinds required). The pre-scan (`find_interface` in parse_names.c) adds `Records.interfaces` (a `RecordKind` whose definition is a `STMT_INTERFACE`; plural `things ...` for names starting `something`/`anything`) and each way's name as a known method (so `speak pet` parses as a method call). `parser_match_kind_name` matches interfaces too. `TYPE_IFACE + n` (record kinds are 16..1023, `TYPE_SUM` 2048, `TYPE_FUNC` 4096); `type_is_object` and `type_can_be_nothing` include them.
- **Checker** (`check_iface.c`): `checker_collect_interfaces` (twice, or named like a record kind), `checker_check_interface` (top level only, ways twice). Fitting: `checker_satisfies(kind, iface)`: a method for each way (`method_for`) with unified inputs and result; a way giving back an interface accepts a fitting kind (pairs being matched are assumed, `Checker.assumed`). `checker_iface_fits` is called by `checker_fits`, list `require_item` (not for `contains`) and map `require_value`; when the kind doesn't fit it reports "A fish can't be used as something that can speak: it has no way to speak." (or "its way to greet doesn't match.") and counts as handled. `checker_dispatch` (from `checker_check_call` once the inputs are checked, and `checker_settle_method`): a call whose first input is an interface's value and whose name is a way (or isn't a function) is checked against the way and marked `call.dispatch`. Fields of an interface's value are an error; a mixed list literal notes an interface both fit (`checker_shared_interface`).
- **Codegen** (`codegen_iface.c`): a dispatched call is `es_way<I>_<NAME>(site, value, inputs...)`, a helper (once per way, `ClosurePool.dispatchers`) testing `es_r->type` against each kind with a matching method (`es_rtN`, or a kind's variants' `es_wtN`), the last without a test.

### Modules (implemented in `src/modules.c`, `src/front/parse_module.c`, `check_module.c`)

- **Loading** (`sources_load`, driver side, before lexing): `use NAME.` / `use the NAME file.` at a sentence start reads `NAME.es` from the folder of the file that says it (`ES_MODULE_DIR` overrides it for the first file; the shell sets it to `.`). Files are found depth-first by real path (each read once), joined in post-order (used files first, the file that's run last), each ending with a newline, and `diag_set_files` makes errors say `Line N of helpers.es:` when there are several files. Errors (reported at the `use` sentence): "I couldn't find the file ... in the same folder as ...", "These files use each other in a circle: a.es uses b.es and b.es uses a.es.", "main.es can't use itself.". `lex_files` restarts lines per file and closes each file's blocks; `Token.file`/`SourcePos.file` say which file. `Program.files` (`SourceFile {name, display, uses}`, empty for one file).
- **Parsing:** `STMT_USE` (`as.module`; one-word names only), `privately to ...` / `privately keep ...` (`function.private`, `constant.private`; the pre-scan accepts `to` after `privately`), and `FILE's NAME` (`parser_find_modules` collects every `use`d name; `Expr.module` on `EXPR_NAME`/`EXPR_CALL`, values and call sentences).
- **Checking:** `Function`/`Constant` keep `file` and `private`; `c->file` is the current statement's file; `checker_find_function`/`checker_find_constant` prefer this file's definition, then one from a used file (`checker_visible`), or only one file while `FILE's` is being looked up (`only_file`, `checker_enter_names`). An unqualified name two used files define is "\"double\" is defined in both helpers.es and math.es."; hidden ones get `checker_report_hidden` ("... is private to helpers.es, ..." / "... is defined in tools.es, which this file doesn't use."). A used file's top-level non-definition is "... is used by another file, so it can only define things." Methods and kinds are global (methods for the same kind in two files are duplicates). Messages pointing at another file's definition use `checker_where` ("line 2 of helpers.es"). After a clean check, `checker_rename_modules` renames other files' functions (not methods) and constants to `NAME 0mN` and every recorded use (`checker_resolved`), so codegen needs no change.
- **Runtime:** `EsSite.file`, `es_source_files` (from `source_table_c`), `es_print_line`: runtime errors and call chains say `line 4 of calc.es`.
- **Tests:** `tests/modules/NAME/main.es` plus its files, `main.out` and optional `main.err` (compile or runtime errors, exit 1), run by `check_run` (also `examples/programs/NAME/main.es`).

### The standard library (implemented in `src/front/parse_library.c`, `parse_library_stmt.c`, `check_library.c`, `src/back/codegen_library.c`, `src/common/library.c`, `runtime/es_math.h`, `es_time.h`, `es_files.h`, `es_csv.h`)

- **No `use`:** every phrase starts with its own words. Full list with exact meanings in `docs/stdlib.md`. Values are `EXPR_LIBRARY {op (LibraryOp), op_span, a, b, part}`, sentences `STMT_LIBRARY {op (LibraryAction), a, b, scale, everything, folder, name, type}`.
- **Parsing:** prefixes in `parser_parse_library_word` (after known names of several words and only when the first word isn't a function the program defines): `the square root of`, `the absolute value of`, `pick one of` / `a random item of|in`, `the lines of file`, `the files in [the folder]`, `the folders in`, `the size of file`, `the last change of file` (a primary, or `-` and a unary), `the bigger/smaller of A and B`, `a random number from A to B`, `a random decimal between A and B`, `the number of days between A and B` (unaries), `roll a die`, `the time now`, `file|folder F exists` (`file`/`folder` + a value that isn't `of`), `the year|month|day|weekday|hour|minute of D` (unless a function has that name). Postfixes (`parser_parse_library_postfix`, in `parse_postfix` before the apply postfixes): `rounded [up|down|to N decimal place(s)]`, `shuffled`, `N day(s) ago`, `N day(s) from now`, `to the power of` + a primary (or `-` unary; a second one is "\"to the power of\" twice could mean two things."). Tests at the comparison level (`parser_parse_library_test`): `is before`, `is after`, `is in this|last|next month|year`. Sentences: `wait`, `shuffle`, `save ... as csv file`, `put ... in file` are in the statement table; `make [a new] file|folder called`, `rename|copy|move the file|folder ...`, `delete the file|folder ... [and everything in it]`, `clear the screen`, `read csv file ... and call it`, `use the same random numbers every time` are found by `parser_at_library_sentence` before the table (so `rename` etc. stay usable as function names). `write X in file F`, `add X to the end of file F` (in `parser_finish_add_end`) reuse STMT_WRITE_FILE / STMT_APPEND_FILE.
- **Names:** `pi`, `today`, `tomorrow`, `yesterday` are turned into EXPR_LIBRARY by the checker only when the name isn't a variable, function or constant (`checker_library_name`); `pi` also works in constants (`lookup_constant`). `D's year` is an EXPR_FIELD the checker turns into LIB_DATE_PART when D is (or must be) a date.
- **Dates:** `TYPE_DATE` (6), a `double` of seconds since 1970-01-01 on the local calendar (days are exact 86400 s steps); C variables `es_vd_`; frames mark them 'd'; printed by `es_date_text` ("Sunday, October 11, 2026", plus ", 2:05 PM" with a time of day). Dates can be kept in lists, maps (as values, not keys: `KIND_DATE` isn't allowed there) and records: `parser_parse_items_kind` reads `dates`; the runtime's `ES_ITEMS_DATE` is kept like numbers (`at.n`, codegen's `n` suffix functions) but printed with `es_date_text` in parentheses (`es_buf_add_date`) inside lists, maps and records, and joined with `es_date_text`; record and variant fields of kind `'d'` (`es_field_d`, `es_vfield_d`). `KIND_DATE` is allowed by `sort`, `sorted`, `biggest`/`smallest`, `sorted by`, `joined with` and function results. `a date or nothing` is a parse error ("A date can't be "or nothing" yet.").
- **Runtime:** `es_math.h` (part 11: math, xoshiro256** random numbers, shuffle), `es_time.h` (12: the civil calendar, `es_now`, `es_wait`), `es_files.h` (13: files and folders, `es_clear_screen`, only on a terminal), `es_csv.h` (14). Under `ES_HOOKS`, `ES_NOW` fixes the clock (`wait` moves it on instead of sleeping) and `ES_RANDOM_SEED` the random numbers; `tests/run.sh` and `bless.sh` export both. Making, renaming, copying and moving never replace anything; `delete the folder ... and everything in it` refuses `""`, `/`, `.`, `..`, `~` and doesn't follow links.
- **Tests:** `tests/run/library_*.es`, one `tests/run/err_lib_*.es` per runtime error, `tests/run/library_dates_kept.es` (dates in lists, maps, records and variants), `tests/memory/dates_loop.es` and `err_date_record_cycle.es`, `tests/errors/library_errors.es`, `tests/ast/library.es` and `err_library.es`.

### System tools and the keyboard (implemented in `src/front/parse_system.c`, `check_system.c`, `src/back/codegen_system.c`, `runtime/es_keys.h`, `es_system.h`)

- **Values** (`parser_parse_system_word`, called first by `parser_parse_library_word`; all `EXPR_LIBRARY` with ops from `LIB_PROGRAM_WORDS` on, routed by `op >= LIB_PROGRAM_WORDS` to `checker_check_system` / `cg_emit_system`): `the words given to the program` (a list of text), `the number of words given to the program`, `word N given to the program` (`at_program_word`: `word` + a number, word, text or parenthesized position + `given to program`; `word given to the program` alone is "Something is missing after "word"."), `the text sent to the program` / `the lines sent to the program` (stdin, read once into `es_sent` (es_program.h, released by `es_finish`), without its last new line; `ask` reads from the same `stdin`), `the setting called X` and `the key being pressed` (both `TYPE_MAYBE + TYPE_TEXT`, boxed), and the test `R worked` / `R didn't work` / `R did not work` (`parser_parse_system_test` from `parser_parse_library_test`; `part` 1 when negated; `es_worked(code field, yes)`).
- **Sentences** (`STMT_LIBRARY`, actions from `DO_COMPLAIN` on, routed to `checker_check_system_stmt` / `cg_emit_system_stmt`): `run P [with A, B and C] [and call the result NAME | and call it NAME]` (`parser_at_system_sentence`: `run`/`complain` unless the program defines a function with that name; P is parsed with `no_call`; parts in `Stmt.library.parts`, each text, a number (`cg_emit_text`) or a list of text (`es_command_add_list`); codegen builds `EsList *es_words` in a C block, then `es_run(site, es_command(P, words))` (fails when the code isn't 0) or `es_spawn(site, command, &es_out, &es_err)` + `es_newN(out, err, code)`), `complain X` (`es_complain`: flush stdout, X to stderr), `wait for a key and call it NAME` (`parser_parse_wait` hands `for key` to `parser_parse_wait_key`; `es_wait_key(site)`), and `stop the program, saying it failed` / `with code N` (`parser_finish_stop` sets `Stmt.as.stop_code`, a synthesized `1` for "saying it failed"; `checker_check_stop`; `cg_emit_stop_code` emits `es_set_status(site, N)` (whole, 0..255) before the stop; `main` returns `es_status` and `es_stop` exits with it). Statements with a `library.name` make it (`check.c`'s `collect_names`).
- **`program result`** (`parser_find_program_result`, run by `parser_find_names` after the record pre-scan): when any token is `run`, `worked`, `work` or `program result`, a record kind "program result" with fields `output` (text), `error output` (text) and `exit code` (number) is added through `parser_add_builtin_kind` (unless the program defines that name) with a synthesized `STMT_RECORD` definition that isn't in the program's body, and `Records.program_result` is 1 + its index. Field names go in `Parser.fields` (`parser_add_field_name`). Without it (the program's own kind), `run ... and call` and `worked` are "This program defines its own kind called "program result", ...".
- **Running** (`es_spawn` in es_system.h): the command is a list of text (first the program); `execvp` (PATH lookup, never a shell) in a `fork`ed child, outputs into two pipes read together with `poll` when the result is kept; a close-on-exec pipe reports `execvp`'s `errno` ("I couldn't find a program called "x"." for ENOENT, "it isn't a program I'm allowed to run" for EACCES); the code is the exit status or 128 + the signal; outputs lose one final new line. The terminal is put back first (`es_terminal_normal`), and stdout/stderr are flushed.
- **Keyboard** (es_keys.h, part 15, before es_system.h): all reads through `getc(stdin)` (so they share `ask`'s buffer); on a terminal `es_terminal_keys(least, tenths)` sets non-canonical, no-echo, no ICRNL/IXON mode with VMIN/VTIME for each read (blocking, non-blocking, or a tenth of a second after Escape for a sequence), saving the original settings once and installing `atexit(es_terminal_normal)` and handlers for SIGINT/SIGTERM/SIGHUP/SIGQUIT that restore and re-raise (signals that were ignored stay ignored). ISIG stays on, so Ctrl+C is a signal. `es_ask` (es_runtime.h) and `es_spawn` call `es_terminal_normal()` first. Escape sequences: `[A`..`[D` arrows, `[H`/`[F`, `[N~` (home, insert, delete, end, page up/down); unnamed ones are skipped, `\r`/`\n` are "enter", 127/8 "backspace", other control characters skipped, UTF-8 read whole. Not a terminal: bytes read the same way, `the key being pressed` is simply the next key (nothing at the end), and `wait for a key` at the end is "There's no key to wait for: the keys sent to the program have run out.".
- **CLI:** `easyscript run FILE WORDS...` passes everything after the file to the program (`cmd_run`); `main(int argc, char **argv)` calls `es_args`.
- **Tests:** `tests/run/system_*`, `keys_scripted` (+ `.in` with escape sequences), `err_sys_*`, `err_keys_ran_out`; `NAME.args` in `tests/run` (run.sh, bless.sh, leaks.sh) holds the words given to the program; `errors/system_errors`, `errors/system_own_program_result`, `ast/system`, `ast/err_system`; CLI checks `cli/run-gives-words`, `system/*` (exit codes, `complain`); `keys/terminal-restored` (`tests/tools/keys_terminal.py`: a pseudo-terminal, `sh` as session leader printing `stty -g` before and after, macOS's PENDIN state bit ignored; normal end, arrow key, runtime error, Ctrl+C (130), `ask` after keys (echo back on), `the key being pressed`); `examples/snake-play-compiles` (only `examples/programs/snake/play.es` is compiled, not run; `main.es` there tests the rules).

### Types (implemented in `src/front/check_types.c`, `check_expr.c`, `check.c`)

- **Kinds:** `Type` in `ast.h` is an unsigned number: `TYPE_NUMBER`, `TYPE_TEXT`, `TYPE_YESNO`, `TYPE_NOTHING` (only a function's result), plus `TYPE_UNKNOWN` (undecided) and `TYPE_ERROR` (after a mistake; unifies with anything silently, so one mistake gives one message). A list type is its innermost kind plus `TYPE_LIST` (8) per level (`type_list_of`, `type_is_list`, `type_item`, `type_base`, `type_counted` for text and lists), so equal types are equal numbers. `ast_type_name(arena, type)` gives "a number", "text", "a yes/no value", "nothing", "a list of numbers", "a list of lists of text", "a list" (items undecided); `checker_kind(c, var)` is the same for a variable. The checker writes `Expr.type` for every checked expression and `param_types`/`result` for every function.
- **Inference engine** (`check_types.c`): `TypeVar` indexes into `Checker.types` (union-find with path halving; each root has a type and the line it was decided; a list root has type `TYPE_LIST` and an `item` variable). `types_new` (a list type gets an item variable), `types_new_list`, `types_item`, `types_of` (rebuilds the full `Type`), `types_unify` (checks `compatible` first, with an occurs check, then `join`s: the root that knows more wins, lists join their items; false if two different concrete kinds), `types_require` (unifies with a new variable of that kind), `types_line`. Every checked expression is recorded in `Checker.typed`. `types_defer` queues operators whose meaning depends on kinds (`DEFER_ORDER`: numbers or text; `DEFER_TO_NUMBER`: number or text; `DEFER_JOIN`: `followed by` is a list when both sides are lists (unified; "I can't join a list of numbers with a list of text."), text as soon as either side is known not to be a list; `types_defer_one_of`/`DEFER_ONE_OF`: one of the `KIND_` bits, reported as "<message>, but this is <kind>."), trying to settle them at once. `types_finish(c, first_error)` settles the rest in a fixpoint loop, reports undecided inputs/results (innermost kind undecided: "I can't tell what kind of value "x" is." / "… gives back.", suggesting `(a number)` or, for a list, `(a list of numbers)`) **only if no other error was reported**, then writes kinds into the AST.
- **Rules** (`check_expr.c`; messages keep the old runtime wording, with carets): arithmetic needs numbers (`checker_arithmetic`, also used for change statements with the variable on the left); `or`/`not`/conditions need yes/no; equality unifies both sides ("I can't compare a number with text."); ordering unifies and defers; `followed by`/`as text` give text; `length of` and file names need text; `nothing` as a value is "\"nothing\" can't be used as a value."; constants have the kind of their value. `checker_require(c, var, type, at, message, hint)` reports "MESSAGE, but this is KIND.".
- **Variables** (`check.c`): `Symbol.var`; `let` shares the value's variable; `set`/`ask`/`read file` into an existing variable must match ("\"total\" is a number (made on line 1), but this is text."); loop numbers are numbers; a for-each item has the list's item kind. `Loop.it` is the kind of `it` (a number, or the item).
- **Functions:** `Function.params`/`result` are type variables, from the annotations or fresh; a function with no `give back E` anywhere in its body (`gives_value`) gives back nothing. Calls unify each argument with its input ("\"halve\" needs a number for \"x\", but this is text." with "\"x\" is a number because of line N…" or the definition when it was written down). A nothing-function used as a value is "… doesn't give back a value, so it can't be used here." `give back E` unifies with the result ("… gives back text (since line N), but this is a number."), a bare `return` in a value function and a value in a `giving back nothing` function are errors.
- **Order:** `check_program` checks top-level constants, then top-level function bodies, then the rest of the program, then `types_finish`, then `diag_sort(diag, first_error)` puts the checker's errors into source order. Because constants are checked before the main program, `lookup_constant` finds variables through `checker_find_later`, and a function's "only sees its own inputs" note uses `later` too.

### Runtime semantics (implemented in `runtime/es_memory.h`, `runtime/es_program.h` and `runtime/es_runtime.h`)

- **Eighteen files** (the eighteenth, `es_events.h`, runs events; the seventeenth, `es_totals.h`, is questions about lists, maps sorted by value and the rules' errors; see "Questions and totals" and "Choices without if"; the fifteenth and sixteenth, `es_keys.h` and `es_system.h`, are the keyboard and system tools; see "System tools and the keyboard"; the seventh, `es_record.h`, is records, the eighth, `es_map.h`, maps, the ninth, `es_kind.h`, kinds with variants, the tenth, `es_closure.h`, functions as values, and the eleventh to fourteenth, `es_math.h`, `es_time.h`, `es_files.h` and `es_csv.h`, the standard library; see "Records", "Maps", "Kinds with variants", "Functions as values" and "The standard library"), embedded in this order: `es_memory.h` (text and list objects and reference counting, the memory checks), `es_program.h` (start/finish, output, sites, the call stack, errors), `es_runtime.h` (text, numbers, comparisons, functions, loops, files and input), `es_list.h` (lists; see "Lists"), `es_sort.h` (sorting) and `es_text.h` (text tools; see "Text"). Each later file includes the one before only when its guard isn't defined, so each also works on its own in an editor.
- **No tagged value:** the checker knows every kind, so generated code uses `double`, `bool`, `EsText *` and `EsList *`, and the runtime never checks kinds. Runtime errors are only what kinds can't catch: dividing or `mod` by zero, a count step that isn't more than zero, a times count that's negative/not whole/too big, `as a number` on text that isn't a number, file errors, `es_no_result`, recursion depth, and list positions (see "Lists").
- **Memory: reference counting for text and lists** (full description in `docs/memory.md`). Every heap object starts with `EsObject {kind, refs}`: text (`ES_OBJ_TEXT`, its characters right after the `EsText {header, len, chars}`) and lists (`ES_OBJ_LIST`, `EsList`, owning the text and lists in it). `es_object_release` is the generic release; `es_list_retain`/`es_list_release`/`es_list_set`/`es_list_drop` are the list versions of the text functions, and an empty list variable holds the immortal `es_no_list`. `refs == ES_IMMORTAL` means never counted or freed: text literals (codegen's `static EsText es_sN`), text constants, and the runtime's own words (`ES_STATIC_TEXT`, e.g. `es_lit_yes`, `es_empty_text`). `es_retain`/`es_release` take `EsText *` (never NULL: empty variables hold `&es_empty_text`); `es_free_object` frees by kind and is kept out of line (`noipa` on GCC, `noinline` on Clang), because otherwise GCC sees `free()` reachable from releases of static immortal text and warns `-Wfree-nonheap-object`. `es_set(&slot, t)` stores and then releases the old text; `es_drop(&slot)` releases and stores `&es_empty_text`.
- **Ownership convention (keep it consistent):** every text or list expression yields an owned value. Reading a variable retains it; literals and constants are used directly. Runtime functions that take `EsText *` or `EsList *` **consume** them (release, or return them: `es_join` returns the other side when one is empty), except `es_push_*` and the "only looks" helpers. Functions own their text and list arguments. Numbers and yes/no own nothing: no retain/release is ever generated for them. `es_text_new(len, &chars)` and `es_text_copy` make heap text with a count of 1.
- **Environment hooks** (`ES_SKIP_OUTPUT`, `ES_ANSWERS`, `ES_NEW_FROM_LINE`, `ES_DEBUG_MEMORY`, `ES_MEMORY_LIMIT`) are read in `es_init` only under `#ifdef ES_HOOKS`. The compiler passes `-DES_HOOKS` only for `run` with `ES_HOOKS=1` in its own environment (exported by `tests/run.sh` and `tests/bless.sh`; the shell sets it for its child); `build` never does (`cli/no-env-hooks-in-built-programs`). Memory tests build from `emit` with `-DES_HOOKS` (`build_with_hooks` in run.sh). See `SECURITY.md`.
- **Memory checks:** live objects and bytes are always counted (`es_memory`). `ES_DEBUG_MEMORY=1` makes `es_finish(true)` fail with exit 70 ("Memory check: N value(s) was/were still alive at the end of the program (B bytes).") if anything is alive. `ES_MEMORY_LIMIT=N` fails with exit 70 ("... more than N bytes of text and lists alive at once.") as soon as live heap bytes would exceed N (`es_memory_take`, checked before `malloc` and before a list grows, so nothing is left unreferenced for LeakSanitizer). Runtime errors exit without the check.
- **Runtime errors must leave nothing unreachable:** every error goes through `es_fail` (exit 1, no clean-up), like the existing ones, and nothing `malloc`'d may be lost before it: free scratch memory first (`es_spawn` frees `argv`), and keep anything a message needs in a static (`es_shown` keeps every number it shows; `es_program_word`'s hint; `es_table_read` keeps what `read the table in` is building). Linux CI's LeakSanitizer checks error programs too (macOS's `leaks.sh` skips them), so check new error paths with Linux in mind.
- **Printing** (`es_number_text`, `es_yesno_text`, `es_list_text`): whole numbers with `|x| <= 2^53` (`ES_EXACT_WHOLE`; consteval's `EXACT_WHOLE`) print with `%.0f` (no decimals, never `-0`). Other numbers are rounded to 10 significant digits (`%.10g`, read back; a result that's whole prints with `%.0f`), so `0.1 plus 0.2` prints `0.3` and `0.99999999999` prints `1`; `const_number_text` matches. NaN prints `not a number`; infinities print `infinity` and `-infinity`. yes/no prints `yes`/`no`. Lists print as "72, 95 and 88".
- **Numbers:** `+ - *` and unary `-` are plain C. `es_div`/`es_mod` fail with "You divided by zero."; `es_mod` uses the integer remainder for whole numbers below 9e15 (same as `fmod`, whose −0 results aren't observable) and `fmod` otherwise.
- **Text:** `es_join(a, b)` (for `followed by` and brackets in text), `es_join_spaced` (the pieces of `say A, B`), `es_say`, `es_length` (UTF-8 characters, via `es_text_chars`), `es_text_is_empty`, `es_text_number(line, t)` for `as a number` (optional surrounding spaces, an optional `-`, digits, optionally `.digits`; otherwise "I can't turn "…" into a number.").
- **Comparisons:** numbers are equal when `a == b` or `|a - b| <= 1e-12 * max(|a|, |b|)` (`es_close`), so `0.1 plus 0.2 is 0.3` is yes. `es_number_order` returns 0 for numbers that are `es_close`, so `<=`/`>=` agree with equality and `<`/`>` are false for them. Text: `es_text_same`, `es_text_order` (bytewise), both consuming. yes/no: C `==`/`!=`.
- **Files:** `es_write_file` writes the text plus `\n`. `es_read_file` strips one final `\n` (and a `\r` before it). I/O errors read like `I couldn't read the file "x": it doesn't exist.`
- **Input:** `es_ask` prints its prompt without a newline, reads one line (stripping `\n`/`\r\n`), and gives empty text at end of input.
- **Shell support:** all program output goes through `es_out`, which drops the first `ES_SKIP_OUTPUT` bytes. With `ES_ANSWERS` set, `es_read_answer` replays answers from that file before reading stdin, appends new ones, and stdin is unbuffered. Both are set only by the shell (which also sets `ES_HOOKS=1` for its `run`).
- **Ending:** `main()` ends by releasing its text variables and calling `es_finish(true)` (flush, then the memory check). `stop the program` in `main()` is `goto es_end` (that same ending); inside a function, the function releases its own text and calls `es_stop()`, which runs `es_finish(false)` (no check: the callers' values are out of reach) and exits 0. Runtime errors flush stdout, print `Line N: message`, the source line with carets (`es_show_source`, laid out like compile errors), an optional hint line, and the call chain (`es_show_calls`) to stderr, and exit 1 with no clean-up.
- **Sites and the call stack:** runtime functions that can fail take a site (an `int` index into the program's `es_sites` table of `EsSite {line, column, length}`; `es_init(es_sites, es_source, es_source_line_count)` hands over the tables) instead of a line. Every EasyScript call pushes an `EsFrame {fn, call, in}` onto `es_stack` (an array of `ES_MAX_DEPTH` frames; `es_depth` counts them) with `es_enter`/`es_enter_one`/`es_enter_many`: `fn` is a static `EsFunction {name, inputs, input_names, kinds}` (kinds `n b t l`), `call` the call's site, and `in` the input values (`in.one` inline for one input; for more, `es_enter_many` copies them onto the growing `es_inputs` array and `in.many` is where they start, so no frame points into a C stack: GCC's `-Wdangling-pointer` caught that); text inputs are retained by the frame and released by `emit_drop_all` through `es_input(i)`. `es_leave` is `es_depth--`; `es_leave_many(n)` also takes the inputs off `es_inputs` (codegen's `leave_code` picks). The depth check comes before the push, so "too deeply" is reported at the call, while working out the caller. The chain: "while working out "F" (x was 1, s was "text...")" (numbers, yes/no, and text cut at 30 characters; lists skipped), then "called from "G" on line N (its inputs)" per caller, collapsing a run of three or more calls from the same place into "...it called itself N more times..." (thousands with commas), and last "called from line N: <the source line>". Costs about 3% on `fib`, nothing measurable elsewhere.
- **Loops:** `es_count_start(site, from, to, step, has_step, down)` checks step > 0 and counts up (empty when from > to) or, with `down`, down (empty when from < to), and works out `last` (the last round's index, adjusted ±1 for rounding; `LLONG_MAX` for an endless or NaN count) and `at_end` (the first round whose number is `es_close` to `to`; from there to `last` the number is `to`). `es_count_value(&c, i)` is `from + direction * i * step` (from scratch each round, no drift) or `to`. This matches the old round-by-round rule exactly (checked against it on 20,000 random counts). `es_times(line, n)` needs a whole number ≥ 0 (and ≤ 9e18).
- **The runtime is header-only** (all `static`) and silences `-Wunused-function` and (Clang, GCC 12+) `-Winfinite-recursion` (endless recursion is an EasyScript runtime error) with pragmas. Generated programs must compile cleanly under `-std=c11 -Wall -Wextra -Wpedantic` with both GCC and Clang; `make test` checks this (`strict-c/generated-programs`). Fix warnings in the runtime's structure, not with more pragmas.

## Parser rules

- **New syntax must follow `docs/design-principles.md`** (statements vs values, how inputs are introduced, `of`/`in`, optional and "not found" results, errors, equality, copying). A phrase that can't follow them is added to its "Known exceptions" with the reason, in the same commit; a doubt goes under "Open questions" instead of into the parser.
- **New phrases also follow "Rules for new phrases"** in `docs/design-principles.md`: one meaning per word, everyday English (idioms only with a plain form too), beginner messages at a grade 6-8 level without programmer words (variable, function, type, ...), an exact meaning in core-language terms for every high-level phrase, high-level operations kept as their own AST nodes (never rewritten into loops by the parser), and patterns that start with their own trigger words.
- **English pass:** before adding any phrase, read `docs/english-pass.md`; follow its Decided section and design rules; record any change of plan in its update log in the same commit.
- **New phrases go through `docs/proposals/`** (its README and `TEMPLATE.md`): one file per phrase, checked against the design rules and the Cognitive Dimensions, accepted before it's built.
- The parser must be **deterministic**. Never guess what the user meant, and never use heuristics, "best match", or silent fallbacks.
- If a sentence is ambiguous or doesn't match any grammar rule, **report an error**. Include the line and column, what was expected, and concrete suggestions (for example, the closest valid sentence forms). Don't pick one reading.
- Because a period ends a statement, it can't also be part of an identifier. The current lexer accepts `.` in identifiers so that `myfile.txt` works. That conflicts with the new syntax, so filenames have to become string literals.

## Compiler implementation rules

- **Arena allocator for all compiler memory** (tokens, AST nodes, strings, symbol tables). No per-object `malloc`/`free` and no `strdup`. Free the whole arena once at the end. The compiler is leak-free: verified with macOS `leaks --atExit` on every command, including error paths and the shell. Keep it that way.
- **No fixed-size buffers.** No `char buf[256]`, `VarMap var_map[100]`, `char line[1024]`, and so on. Grow storage dynamically from the arena. The same goes for generated C: don't emit `char x[256]` for strings.
- Write portable C11 (`-std=c11 -Wall -Wextra`). Invoke the C compiler as `cc`, not `gcc`.
- Report compile errors with source positions rather than calling `exit(1)` deep inside the lexer or parser.
- **Never rely on the order C works out a call's arguments in.** C leaves it open, and GCC on Linux x86-64 goes right to left. When two or more arguments generate code, add sites or static text, write plan notes, add kinds or report errors (`cg_operand`, `cg_site`, `cg_emit_*`, `checker_check_*`, ...), work each one out into a local first, in written order, then make the call. Plain formatting helpers (`checker_kind`, `parser_text`) are fine as arguments.

## Code organization (target)

The compiler follows this pipeline:

- **Front end:** lexer → parser → checker.
- **Middle end:** IR and optimizations (added later).
- **Back end:** C codegen.

Each stage talks to the next only through shared data structures: tokens, the AST, and the symbol table. **The parser never emits C. Codegen never looks at source text.** (The one exception is `src/back/source_table.c`, which only copies the source lines into a C table for runtime errors; the driver passes its output to codegen as opaque text.)

Target layout:

```
src/main.c            driver: runs the passes in order
src/front/            lexer.c, parse_expr.c, parse_stmt.c, check.c
src/back/             codegen_c.c
src/common/           arena.c, util.c, diag.c, ast.h
runtime/              runtime support linked into generated programs
```

Rules:

- **Group code by job**, not one file per function. Each module has a small public `.h` and keeps its private details in the `.c`.
- **Keep files under ~600 lines.** Split a file when it passes that, or when it covers two different concerns.
- **Helpers that aren't used elsewhere must be `static`.**
- **No global mutable state.** Pass context structs (`Compiler`, `Parser`, `Checker`, `Codegen`) explicitly.
- **Prefer opaque structs** when other modules don't need the fields.
- **Functions stay short and do one thing.**

Don't move code into this layout separately. Create it as later steps rewrite each stage, and update "Current state" as each piece moves.

Each test is `static void test_x(TestContext *t)`, registered with `unit_run` in that file's `*_tests(TestRunner *)` function. Declare that function in `unit.h` and call it from `main` in `unit.c`. Messages that need the OS to fail are in its `EXEMPT` table with a reason.

It prints the beginner docs' reading level without failing.

## Working efficiently

- **Run the test suite locally on macOS only.** Don't run the Docker Linux tests unless you're debugging a Linux-specific failure; GitHub Actions CI covers Linux after each push.
- **When the Linux check is run in Docker, it must include `make test-debug`** (LeakSanitizer and UBSan), not only `make CC=gcc test`: macOS doesn't catch a leak left behind by a runtime error (`leaks.sh` skips error programs) or UBSan's null-pointer `memcpy` checks, so both only show up on Linux. In the runtime, a `memcpy`/`memmove` whose source can be an empty list's items (which may be NULL) needs a `len > 0` guard.
- **Run `make test-gcc` before every push.** It builds the compiler with Homebrew's GCC (`brew install gcc`) and `-Werror`, then runs the full suite with the strict-C check also using GCC, so GCC-only warnings show up locally. Homebrew's GCC uses Apple's headers, so a header macOS includes indirectly (`SIZE_MAX` without `<stdint.h>`) is caught by `audit/includes` instead.
- **Show only summaries and failures** when running tests, benchmarks or builds (pipe through `tail`/`grep`). Never read full passing output.
- **Time-box investigations.** If a problem isn't solved after a few attempts, stop and report what you found and the options, instead of continuing to experiment.
- **Read only the files a task needs.** Use `grep` to find code rather than reading whole directories.

- **Pipeline** (`generate_c` in `src/main.c`, shared by `run`/`build`/`emit`):
  1. Lex and parse.
  2. If there were no errors, run `check_program`.
  3. If there are any diagnostics, print them all and exit 1.
  4. Otherwise run `codegen_c` and write `program.c` to the temp dir.

  `cc -O2 program.c -o OUT -lm` (plus `-DES_HOOKS` for `run` with `ES_HOOKS=1`) is run via `fork`/`execvp`, and `run` returns the program's exit status. With `ES_SANITIZE=1` (set by `make test-debug`) the program is built instead with `-O1 -fno-omit-frame-pointer -fsanitize=address,undefined -fno-sanitize-recover=all` (no `-g`: on macOS it leaves `.dSYM` folders behind).
- **Stage boundaries:** these now follow the target design. Codegen trusts the checker and reports nothing; it asserts if it ever sees `EXPR_ERROR` or an `it` with no counting loop around it. `src/main.c` still has file-scope `arena` and `temp_*` pointers for its `atexit` cleanup (the only global state in the compiler).
- `src/main.c`: the CLI (the shell is in `src/shell.c`). `run FILE [WORDS...]` (the words go to the program) / `test FILE [WORDS...]` (`run` built with `-DES_TESTING`: `es_examples_report` at `es_finish` says how many `for example, ...` sentences (`STMT_EXAMPLE`, `es_example`) were right, exit 1 if any weren't) / `build FILE -o OUT` / `emit FILE` / `tokens FILE` / `ast FILE` / `errors FILE` / `plan FILE` (also `build --plan FILE`), and `help`. Unknown commands and bad arguments print usage and exit 2.
  - Each invocation creates one `mkdtemp` directory under `$TMPDIR` (or `/tmp`), holding `program.c`, `program` and `session.es`. `atexit` removes it.
  - **The shell** (no arguments) is `src/shell.{c,h}` (`shell_run`). It keeps the accepted source in a `StrBuf`. Per entry (a line, or a `:`-ending line plus following lines until a blank one) it writes `session.es` and runs `argv[0] run session.es` with stdout piped through it, setting `ES_SKIP_OUTPUT` (bytes already shown) and `ES_ANSWERS` (`answers.txt` in the temp dir). It keeps the entry only on exit 0 (and adds the bytes printed to `shown`); otherwise it truncates the answers file back and prints "(That line/block wasn't kept.)". It also sets `ES_NEW_FROM_LINE` (the entry's first line): a runtime error at an earlier line of the main file (a kept line the new one changed, like a misspelled column making the read stop) ends with "This line worked before. The new line changes how it works." (`es_fail`). It reads stdin one byte at a time so it never reads lines meant for the program. `exit`, `quit` or `stop the program` leaves.

- `src/front/check.{c,h}` (statements, scopes, the program) plus `check_names.c` (finding and making names, the unknown-name message), `check_expr.c` (expressions, calls, kind rules), `check_types.c` (the inference engine; see "Types"), `check_const.c` (constants), `check_list.c` (list values and sentences; see "Lists") and `check_text.c` (text tools, `contains`, `the position of`; see "Text"), sharing `check_internal.h` (the `Checker`, `Symbol`, `Loop`, `Function`, `Constant`, `TypeSlot`, `Deferred`, `TypedExpr` structs and the `checker_`/`types_` helpers: `checker_find_made`, `checker_find_later`, `checker_find_function`, `checker_find_constant`, `checker_report_unknown`, `checker_clashes`, `checker_function_header`, `checker_check_expr`, `checker_check_call`, `checker_require`, `checker_arithmetic`, `checker_kind`, `checker_make_item_name`, `checker_require_list`, `checker_check_list_expr`, `checker_check_contains`, `checker_check_list_stmt`, `checker_add_to_list`, `checker_collect_constants`, `checker_check_constant`, `checker_closest_constant`, `types_*`): `check_program(arena, diag, program)`. A `Checker` context holds `made` (names made so far, with lines) and `later` (all names the program makes, for "You make "x" later, on line N").
  - **Making names:** `let` makes a name; making it twice is "You already made …" with a "set" hint. `ask` and `read file … and call it` make the name if it's new and silently reuse it otherwise. `set`/`change`/arithmetic statements and `EXPR_NAME` need an existing name.
  - **Unknown names:** "I don't know anything called "x"." plus one note:
    - "Did you mean "total"? You made it on line 1." for the single closest name (OSA distance, limit 1 for names of 3 or fewer characters, otherwise 2)
    - a list when several are equally close
    - "You make "x" later, on line N."
    - otherwise "Make it first, like "let x be 0"."
  - **Loops:** a `Loop` stack (`has_it` for count and times loops). `EXPR_IT` needs some enclosing loop with `has_it`; otherwise "it doesn't refer to anything here", with a note that's different inside a non-counting loop and outside any loop. `STMT_BREAK`/`STMT_CONTINUE` outside any loop are errors. Loop values (from/to/step/times/condition) are checked in the outer scope. The count variable is made in the loop's scope; if the name exists, it's an error ("This loop calls each number "number", but you already made…" when defaulted). The loop body ends the scope as "the loop"; a loop variable used afterwards gets "is the number of the loop on line N, so it only exists inside that loop" (`Symbol.loop_number`).
  - **Scopes:** each if branch body is a scope (`check_block`): names made inside are dropped from `made` at its end and recorded in `ended` with the if's line, so a later use says "You made "x" inside the "if" on line N, so it only exists inside that block." A name that exists outside can't be made again inside ("You already made …"); different blocks can make the same name.
- `src/back/codegen_c.{c,h}` (statements, loops) and `codegen_program.c` (functions, constants, the program) plus `codegen_expr.c` (names, literals, expressions), `codegen_list.c` (lists, `for each`, `every`/`only` helpers; see "Lists") and `codegen_text.c` (text tools and `es_append`; see "Text") sharing `codegen_internal.h` (the `Codegen`/`LoopCode`/`VarCode`/`NameScope`/`TextPool`/`HelperPool` structs and the `cg_` helpers: `cg_emit_expr`, `cg_emit_text` (any value as owned text), `cg_has_effects`, `cg_ctype`, `cg_retain`/`cg_release`/`cg_set`/`cg_drop`/`cg_empty` (per counted type), `cg_operand`, `cg_ordered`, `cg_is_constant`, `cg_emit_var`, `cg_append_prefixed`, `cg_append_var`, `cg_append_c_string`, `cg_static_text`, `cg_declare_name`, `cg_new_temp`, `cg_find_function`, `cg_emit_declarations`, `cg_item_suffix`, `cg_emit_list_expr`, `cg_emit_contains`, `cg_emit_each_head`, `cg_list_stmt`): `codegen_c(arena, program, out)` writes the embedded runtime (the `es_runtime_source` byte array), the static text objects `es_sN`, constants, prototypes, the `every`/`only` helpers, functions, and `int main(void)`. **No tagged value:** every expression is C of its kind's type (`cg_ctype`: `double`, `bool`, `EsText *`, `EsList *`, `void`), using `Expr.type` from the checker; codegen asserts on an undecided kind.
  - **Names:** variables are C locals of `main()` or of their function (spaces in a name become `_`, while `_` is doubled), mangled by kind and name: `es_vn_` (number), `es_vt_` (text), `es_vb_` (yes/no), `es_vl<depth><n|t|b>_` (lists) plus the name, with `_` written as `__` and `'` as `_q`, so blocks side by side can make the same name with different kinds (`Codegen.vars` holds name+kind pairs). Locals keep their addresses from escaping, so the C compiler keeps numbers in registers.
  - **Ownership** (text and lists, `type_counted`; see "Runtime semantics" and `docs/memory.md`): reads are `es_retain(es_vt_x)` / `es_list_retain(...)`; stores are `es_set` / `es_list_set`, other stores plain `=` (change statements: `es_vn_x = es_vn_x + AMOUNT;`, or `es_div`). `Codegen.scopes` is a stack of `NameScope`s of text and list variables, one per block (`[0]` the top level); `cg_declare_name` records such a variable in the innermost scope unless it's a parameter (or a helper's captured variable) or already in some scope. A block ends with `es_drop`/`es_list_drop` for its variables. `stop the loop`/`skip this one` drop every scope from the innermost through the loop's body (`LoopCode.scope`). `stop the program` in `main()` is `goto es_end;` (the label is emitted only if used, `Codegen.stops`), and the end of `main()` drops every text and list variable and calls `es_finish(true)`; in a function it drops the function's text and lists and calls `es_stop()`.
  - **Operators:** `+ - *` and unary `-` are C; `/` and `mod` are `es_div`/`es_mod(line, a, b)`; `and`/`or` between yes/no are `&&`/`||` (short-circuit, left to right); `followed by` is `es_join(text(L), text(R))` and the pieces of `say` `es_join_spaced`; equality is `es_close` (numbers), `es_text_same` (text) or `==` (yes/no); ordering is `es_number_order`/`es_text_order` compared with 0; `as text`/`say`/`ask` prompts/written text go through `cg_emit_text` (`es_number_text`, `es_yesno_text`); `as exact text` is `es_number_exact_text`; `as a number` on text is `es_text_number(line, t)`. Number literals always print with a `.` or exponent (`%.17g`, `HUGE_VAL` if infinite), so C never does integer arithmetic.
  - **Temporaries:** typed `es_tN` (`Codegen.temps` holds each one's kind) declared at the top of `main`/the function, always initialized (`0.0`, `false`, `NULL`) so GCC never warns "may be used uninitialized" (a map lookup's temporary is only set when the key is there). Only when both operands of an operation have effects (`cg_has_effects`: calls, file reads, `/`, `mod`, `as a number` on text, a zero-input function name) does the left one go into a temporary: `(es_tN = L, OP(es_tN, R))`, keeping left-to-right order. Counts store from/to/step in temporaries once; `give back` stores its value before the drops.
  - **Literals:** text becomes a static immortal object (`static EsText es_sN = {{ES_OBJ_TEXT, ES_IMMORTAL}, LEN, "...", CHARS, 0};`, collected in a `TextPool` shared with the functions) used as `&es_sN`; its string uses octal escapes and `\?`.
  - **Lines and sites:** each statement gets a `/* line N */` comment, and runtime calls that can fail receive the node's site (`cg_site`, a shared `SitePool` emitted as `es_sites`): division/`mod` the whole operation, calls the call, conversions the conversion, files the file name, counts the step, times the count, list operations the item/slice or the position, `es_no_result` the function's name. `codegen_c(arena, program, source_table, out)` puts `source_table` (from `source_table_c`, called by the driver) right after the runtime. Each function gets an `es_fn_NAME` description (and `es_in_NAME` input names) and starts by pushing its frame (`emit_frame`); its first parameter is `int es_call`, the call's site.
  - **if:** `if (C) { … } else if (C2) { … } else { … }`, with `Codegen.depth` indenting nested blocks.
  - **Loops:** each loop is wrapped in `{ }`. A count is `EsCount es_cN = es_count_start(site, from, to, step, has_step, down)` and `for (long long es_iN = 0; es_iN <= es_cN.last; es_iN++) { es_vn_var = es_count_value(&es_cN, es_iN); … }`. Times is `long long es_nN = es_times(…); for (es_iN = 1; es_iN <= es_nN; es_iN++)`. While/until use `while ([!]C)`, and forever is `for (;;)`. Break and continue are C `break;`/`continue;` (after the drops). `Codegen.loops` resolves `it` to the innermost count's variable or `((double)es_iN)` for times. Names made in blocks are hoisted like the rest; the checker guarantees they're only used in their block, and the block's end drops text.

## Build

```sh
make                                  # builds ./easyscript (plus build/tools/embed and build/release/unit_tests); no warnings expected
make test                             # builds, then runs tests/run.sh (unit, tokens, ast, run, errors, examples, strict C, docs, CLI)
make debug                            # ASan/UBSan build in build/debug/
make test-debug                       # full suite against the sanitizer build (programs sanitized too), then the leak check
make test-gcc                         # compiler built with GCC -Werror (build/gcc/), full suite, strict C with GCC; before every push
make bless                            # rewrite golden files from current output, then show git diff --stat
./easyscript run FILE.es [WORDS...]   # compile + run, giving it the words (generated C/binary go to a temp dir)
./easyscript build FILE.es -o OUT     # compile to an executable at OUT
./easyscript emit FILE.es             # print the generated C
./easyscript tokens FILE.es           # print the lexer's tokens
./easyscript ast FILE.es              # print the syntax tree
./easyscript errors FILE.es           # check, and print the errors as data (JSON lines)
./easyscript plan FILE.es             # what each list question, filter and sort became
./easyscript                          # interactive shell (exit or quit to leave)
make clean
```
